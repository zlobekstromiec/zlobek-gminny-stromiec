# Phase 6: UI Design Contract (Dostępność, zgodność prawna, wydajność)

> Visual and interaction contract for the accessibility widget, the high-contrast theme,
> the three text-size steps, both statutory legal pages, the EU-funding marking strip and
> the two editorial-panel screens that feed the legal pages. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This document is UI-SPEC Amendment v1.8.** The Phase 1 contract and Amendments v1.1,
> v1.2, v1.3, v1.4, v1.5, v1.6 and v1.7 stay in force in full except where §"Amendment
> v1.8: exactly what this document supersedes" names an override. The exact text to append
> to `01-UI-SPEC.md` is written out verbatim in §"Amendment v1.8 block (append verbatim)".
> **The executor appends that block; this agent does not edit `01-UI-SPEC.md`.**
>
> **This is a delta spec.** Where it is silent, Phase 1 (tokens, focus ring, motion, copy
> rules) governs the public surfaces, Amendment v1.4 governs form fields, Amendment v1.5
> (`04.1-UI-SPEC.md`) governs everything under `/admin`, and Amendment v1.7
> (`05-UI-SPEC.md`) governs the gallery, the lightbox and `/cennik`.

**Scope:** SITE-05, A11Y-01, A11Y-02, A11Y-03 (authored, not ticked), LEGAL-01 (verified),
LEGAL-02 (authored, not ticked), the EU-funding marking (designed, no requirement ID, D-17).
ROADMAP Phase 6 success criteria 1, 2, 3, 4.

**Explicitly out of scope:** everything in Phase 7. This phase does **not** flip the noindex
guard, does **not** replace a single placeholder value, and does **not** tick A11Y-03 or
LEGAL-02. Success criterion 5 (the launch gate) is a build-and-test deliverable with no UI
surface and is therefore named here only where it constrains a visual decision.

**Stack context:** SvelteKit 2 + Svelte 5 runes + Tailwind v4 CSS-first `@theme` in
`src/app.css`. There is no `tailwind.config.js` and there never will be. shadcn/ui is
React-only and does not apply. Public content routes prerender at build time.

**Language:** Polish only, every surface, no exceptions (SITE-06, CMS-03).

**Copy rules (v1.2 §8, non-negotiable, apply to shipped copy, code comments, test names and
commit messages):** no emoji, no em dashes anywhere (use commas, colons, parentheses), en
dash only inside numeric ranges (`6:30–16:30`), plain hyphen in day abbreviations
(`pon.-pt.`). **This phase adds exactly one byte-exempt string** (Contract 9): the statutory
EU klauzula „Dofinansowane przez Unię Europejską – NextGenerationEU", whose en dash is part
of the mandated wording. Same precedent as the verbatim client core message in v1.2 §8.

### The high-contrast tier's own split

The default split above describes the default theme only. The high-contrast tier deliberately
collapses to three values, so it has its own ratio and it is stated here rather than left implied
by the flip tables:

| Role | Value | Share | Carries |
|------|-------|-------|---------|
| Dominant | `#000000` | ~85% | Every surface without exception: page, header, footer, cards, the widget panel, both legal pages, the EU strip plate, panel screens |
| Secondary | `#FFFF00` | ~10% | All body text, all headings, all icon strokes, every border that replaces a shadow, the focus ring |
| Accent | `#FFFFFF` | ~5% | Interactive-state differentiation only: the hovered or checked control, the active nav marker, and the photo border. Never a large fill |
| Semantic | `--hc-uwaga` | rare | Validation errors only, on the two panel screens. `#B91C1C` on black computes to 3.25:1 and FAILS body text, which is precisely why this fourth value exists |

**The ratio inverts on purpose.** In the default theme the dominant value is a near-white surface
and colour is the scarce resource; in the high-contrast tier the dominant value is black and
*legibility* is the scarce resource, so yellow is spent freely on every glyph and stroke while
white is rationed to the few places a state change must be visible. Reading the default theme's
60/30/10 into this tier would produce a mode that is merely dark, not high-contrast.

| Foreground | Surface | Ratio | Meets | Where |

| `ink` `#1E293B` | `#FBFAF7` | ~13.9:1 | AAA | Legal-page warm sections |

| `brand-blue` `#0369A1` | `#FFFFFF` | 5.93:1 | AA | Legal-page links, the panel-screen back links |
| `white` `#FFFFFF` | `brand-blue` `#0369A1` | 5.93:1 | AA | **The widget trigger in the `TopBar`**, including its 1px border as a UI boundary (≥3:1) |
| `focus-ring` `#0C4A6E` | `#FFFFFF` adjacent | 9.46:1 | AA | The global 3px ring, on every new control |
| `border-strong` `#64748B` | `#FFFFFF` | 4.76:1 | AA (UI ≥3:1) | Widget control borders, EU placeholder chip borders |
| `danger` `#B91C1C` | `#FFFFFF` | 6.47:1 | AA | Panel field errors on both new screens |
| `danger` `#B91C1C` | `danger-surface` `#FEF2F2` | 5.92:1 | AA | Panel validation-summary heading |

**Hard rules added by this amendment:**
1. **The high-contrast theme is a separate, explicitly-entered tier.** It is never applied
   automatically, never derived from `prefers-contrast`, and never mixed with the default
   tier. Contract 3 declares every value.
2. **The default theme is unchanged, and that is a testable property, not an intention.**
   Both mechanisms this phase adds (the theme flip and the text scale) are no-ops unless an
   attribute is present on `<html>`. Contract 3 and Contract 5 are written so that a
   screenshot of any page with no attribute set is byte-identical to today's.
3. **No state is signalled by colour alone, in either theme.** In high contrast this is not
   merely honoured but structurally guaranteed: the palette has three values and every state
   also carries an icon, a border, a word, or an ARIA state.
4. **Placeholder attributes remain banned on every control** (v1.4 hard rule 3). The widget
   has no text input, so this is restated only for the two panel screens.

## Component Contracts

### 1. Accessibility widget: the trigger (closed state) (A11Y-02, D-01, D-02, D-04, D-06, D-07)

Component: `src/lib/components/UlatwieniaDostepu.svelte`. Mounted **once**, as the third
item of `TopBar.svelte`'s existing `space-between` flex row (D-02). It is not a floating
button, it is not in the `Header`, and it is not repeated anywhere.

**Markup contract:**

```
<div class="miejsce-widgetu">          <!-- ALWAYS rendered, including in prerendered HTML -->
  {#if zamontowany}
    <button type="button" class="wyzwalacz"
            aria-expanded={otwarte} aria-controls="panel-ulatwien">
      <IconAccessibility aria-hidden="true" focusable="false" size={18} />
      <span class="etykieta">Ułatwienia dostępu</span>
    </button>
  {/if}
</div>
```

- **With JavaScript disabled the widget renders nothing at all (D-04).** `zamontowany` is
  set inside an `$effect`, which never runs during prerendering, so the static HTML contains
  the wrapper and nothing else. This is the one place the project's standing „must degrade
  without JavaScript" rule (04.1 D-17, D-22) genuinely cannot be honoured: public routes are
  prerendered static HTML with no server, so a no-JS path is structurally impossible rather
  than merely expensive, and the site already meets AA unaided. **The component's header
  comment must state this in Polish rather than leave it to be inferred.**
- **The wrapper is always rendered and always sized, and that is a performance contract, not
  cosmetics.** Inserting a third flex item at hydration would shift `.hours` and register as
  CLS on every route, in the very phase that owns SITE-05. `.miejsce-widgetu` therefore
  carries the sizing rules and the button fills it: `min-height: 44px`, `width: 44px` below
  640px, `min-width: 168px` at 640px and above. The button is `width: 100%; height: 100%`.
  One class carries both, so the reserved box and the real button cannot drift apart.
  **An empty sized box is not a dead control**, which is what D-04 forbids; it is invisible
  and unfocusable.
- **Below 640px the trigger is icon-only** (44×44, accessible name from a
  `<span class="visually-hidden">Ułatwienia dostępu</span>`, never `aria-label` alone, so
  the name is real text a translation tool can reach). At 640px and above the visible label
  renders beside the icon.

**Treatment (default theme):** transparent fill on `brand-blue`, `#FFFFFF` label and icon
stroke (5.93:1), `1px solid #FFFFFF` border (≥3:1 as a UI boundary), `--radius-sm`, padding
`8px 12px`, Nunito 700 14px, `gap: 4px`. The border is what distinguishes it from the two
text items beside it: a button on a coloured bar with no border and no underline would be
signalled by nothing.

**States:** hover fills `--color-band` with a `brand-blue` label (the inverse of rest, 5.17:1);
focus-visible takes the global 3px `focus-ring` at 2px offset; while open, `aria-expanded="true"`
and the fill stays at the hover treatment so the open state is visible without colour alone
(the `aria-expanded` attribute carries it for assistive tech, the fill carries it visually,
and the panel itself is on screen).

### 2. Accessibility widget: the open panel (D-03, D-06, D-11)

**Markup contract:**

```
<div class="tlo" onclick={zamknij}></div>            <!-- scrim, mouse-dismiss only -->
<div id="panel-ulatwien" class="panel"
     role="dialog" aria-modal="true" aria-labelledby="panel-ulatwien-tytul"
     tabindex="-1" onkeydown={klawisz}>
  <div class="naglowek">
    <h2 id="panel-ulatwien-tytul">Ułatwienia dostępu</h2>
    <button type="button" class="zamknij" aria-label="Zamknij ułatwienia dostępu">
      <IconX aria-hidden="true" focusable="false" size={20} />
    </button>
  </div>

  <fieldset class="grupa">
    <legend>Wielkość tekstu</legend>
    <div class="segmenty">
      <input type="radio" id="skala-100" name="skala" value="100" checked={...} />
      <label for="skala-100">A<span class="visually-hidden">, tekst standardowy</span></label>
      <input type="radio" id="skala-115" name="skala" value="115" ... />
      <label for="skala-115">A+<span class="visually-hidden">, tekst większy, 115 procent</span></label>
      <input type="radio" id="skala-130" name="skala" value="130" ... />
      <label for="skala-130">A++<span class="visually-hidden">, tekst największy, 130 procent</span></label>
    </div>
  </fieldset>

  <div class="grupa">
    <input type="checkbox" id="kontrast" checked={...} />
    <label for="kontrast">Wysoki kontrast (żółty na czarnym)</label>
  </div>

  <button type="button" class="reset">Przywróć ustawienia domyślne</button>
  <p class="notatka">Ustawienia działają do zamknięcia karty przeglądarki.</p>
</div>
```

**Why native controls.** Three `<input type="radio">` in a `<fieldset>` give arrow-key
navigation, a single tab stop and correct group semantics for free; a hand-rolled
`role="radiogroup"` would owe all three. The checkbox is native for the same reason. This is
the same ruling 04.1 Contract 8 made for the file input: native is keyboard operable and
screen-reader labelled for free, and every replacement is worse.

**Geometry and placement:** anchored below the `TopBar`, right-aligned to the container
gutter, `position: absolute` inside a `position: relative` `TopBar`. Width `min(320px, calc(100vw - 32px))`.
Surface `--color-surface`, `--radius-md`, `2px solid var(--color-border-strong)`, `shadow-md`
(`0 4px 12px rgb(15 23 42 / 0.08)`), padding 16px, 24px between the two groups. `z-index: 80`
(above the `Header`'s 50 and the `MobileNav` drawer's 70, because the widget can be opened
while the drawer is shut and must never be occluded by the sticky header).

**Segmented control:** three `<label>` chips in a row, each `min-height: 44px`,
`min-width: 44px`, `--radius-sm`, `2px solid var(--color-border-strong)`, Baloo 2 700 at
14/17/20px so the three sample glyphs themselves show the difference the control makes. The
checked chip fills `--color-brand-blue` with a `#FFFFFF` label (5.93:1) **and** carries
`aria-checked` through the native input, so the state is never colour alone. The native
radios are visually hidden with the global `.visually-hidden` (never `display: none`, which
removes them from the tab order) and the focus ring is drawn on the chip via
`input:focus-visible + label`.

**Checkbox:** reuses the `ConsentBlock` checkbox visual verbatim (24×24px, `2px solid var(--color-border-strong)`,
checked fills `--color-brand-blue` with a white glyph) but **never its consent semantics or
copy**. This is the same reuse ruling 04.1 Contract 5 made for the „Treść zastępcza" checkbox.

**Reset button:** inherited `Cta` secondary variant, full width, always rendered (rendering
it conditionally would move the session note and shift the panel).

**Island bar (D-06), inherited from `MobileNav` and `Lightbox`, no exceptions:**
1. **Bounded focus trap** over the panel's focusables, implemented with the CORRECTED cycle
   from `Lightbox.svelte:151-160`: an index of `-1` (focus resting on the container, which
   carries `tabindex="-1"`) enters the cycle from the direction of travel. The naive
   two-wrap-point form is the exact defect Contract 13 fixes in `MobileNav`; shipping it
   again in a new island would be worse than leaving the old one.
2. **Escape closes** and returns focus to the trigger.
3. **Focus on open goes to the panel container**, not to the close button. This is a
   declared deviation from `MobileNav`, with a reason: a settings panel's first job is to
   announce what it is, and the container carries the accessible name. The deviation is safe
   only because of rule 1, which is why the two are stated together.
4. **Focus on close returns to the trigger**, always, including when the panel is dismissed
   by the scrim.
5. **The scrim carries no keyboard handler by design** (keyboard users dismiss via the close
   button or Escape), matching the two existing islands and their `svelte-ignore` comments.
6. **Body scroll is NOT locked.** `MobileNav` locks it because a full-height drawer over the
   page is a mode; a 320px popover anchored to the bar is not, and locking scroll for it
   would be a surprise. Stated because the deviation is deliberate.
7. **Its own axe AA pass in BOTH the closed and the open state**, on at least two routes.

**Persistence (D-11):** `sessionStorage` only, keys `dostepnosc:kontrast` (`"wysoki"`) and
`dostepnosc:skala` (`"115"` / `"130"`). Absent key means default. **Not `localStorage`**, a
trade the user made with the cost stated: someone who needs high contrast re-enables it on
each new visit. `sessionStorage` survives in-tab navigation and SvelteKit's client-side
routing means internal links do not reload, so the setting holds for a whole browsing
session. **The Polityka prywatności must disclose it** (Contract 8, §"Ustawienia zapisywane
w Twojej przeglądarce").

**The pre-hydration flash: we ship it, and here is the finding behind that (D-12).**
`svelte.config.js:55-69` sets `csp: {mode: 'auto'}` with `'script-src': ['self', 'https://challenges.cloudflare.com']`
and no `unsafe-inline`. **SvelteKit's `auto` mode will NOT hash a hand-authored inline script
in `app.html`.** Verified against the framework source: `csp.add_script()` is called only for
SvelteKit's own generated `init_app` bootstrap in `render.js`; nothing walks the `app.html`
template. A hand-authored inline script would therefore receive neither a hash nor a nonce
and would be blocked outright. Per D-12 this settles it: **we ship the flash and record why.**
- Widening the policy is refused (D-12).
- Dropping prerender is refused (D-12).
- **A same-origin external `<script src="/motyw.js">` in `<head>` was considered and
  rejected.** It would satisfy `script-src 'self'` with no CSP change and would remove the
  flash entirely, but it is a render-blocking request in the critical path of the one phase
  that owns SITE-05, paid by 100% of visitors on every cold load, to spare a flash seen only
  by the subset who hard-reload with a non-default setting already active in the session.
  Recorded here so a later reader sees it was weighed, not missed.
- **The flash never leaves a user in an inaccessible state.** The default theme is fully AA
  conformant, so the pre-hydration frame is merely not the preferred appearance. That is what
  makes shipping it acceptable, and the plan should say so in exactly those terms.
- No transition is added to the theme-flipping properties beyond what already exists, and the
  global `prefers-reduced-motion` block already neutralises transitions for users who asked.

### 3. High contrast, Layer 1: the token flip (D-08, D-09, D-11)

**The theme is `html[data-kontrast='wysoki']`.** The attribute is absent by default; the
island sets and removes it on `document.documentElement`. Everything below lives in
`src/app.css`, in one block, after `@theme`.

**Three HC-only values, declared as their own properties so they can never leak into the
accessible tier and never generate a Tailwind utility:**

```css
html[data-kontrast='wysoki'] {
	--hc-tlo: #000000;    /* every surface, every fill */
	--hc-tekst: #ffff00;  /* every text, every border, every icon stroke */
	--hc-uwaga: #ffffff;  /* the two attention roles ONLY: focus ring and error */
	/* ...the flip table below... */
}
```

**Why exactly three.** Yellow on black is the Polish public-body convention a visitor
recognises (D-08). White is required because two of the roles cannot be carried by yellow:
`#B91C1C` on black measures **3.25:1** and fails AA outright, and a focus ring must be
distinguishable from the border it surrounds. Every pair among the three is AAA against
black, and the one weak pair (`#FFFF00` against `#FFFFFF`, **1.07:1**) is why white appears
only where a black surface or the ring's own 2px black offset separates it from yellow.

**Measured ratios (WCAG relative luminance):**

| `#000000` | `#FFFFFF` | **21:1** | AAA (the image plates, Contract 4) |

### 5. Text scaling: three steps, and exactly what does not move (D-03)

**Three steps: normal, 115%, 130% (D-03).** Not 150%: that breaks the KeyFacts chip row and
the `TopBar` at 360px, which would drag reflow work onto two locked contracts. WCAG 1.4.4's
200% requirement is already satisfied by browser zoom; this control is convenience, not the
legal floor, and the Deklaracja does not claim otherwise.

**Mechanism: one multiplier, fourteen type tokens, a mechanical substitution.**

```css

	--font-size-14: calc(14px * var(--skala-tekstu));
	--font-size-15: calc(15px * var(--skala-tekstu));
	--font-size-16: calc(16px * var(--skala-tekstu));
	--font-size-17: calc(17px * var(--skala-tekstu));
	--font-size-18: calc(18px * var(--skala-tekstu));
```

**What actually scales:** every `font-size` declaration in the public tree, converted
token-for-token. `grep -rn 'font-size:' src/` finds **290** declarations, of which **167 are
public** (`src/lib/components/*.svelte` and `src/routes/**` excluding `admin`). The distinct
values are exactly the twelve above plus the two clamps; the `2rem` and `1.125rem` on the two
legal stubs are deleted with the stubs (Contracts 7 and 8). Line heights are unitless and
therefore scale for free.

**What must NOT scale, and does not, by construction:**

| Thing | Why it holds |
|---|---|
| **The 46px icon chip** (`KeyFacts`, `Perks`, `NewsCard`) | a px box, not a font size. v1.6 §3 is untouched at every step, which is precisely why D-03 chose 130% over 150% |
| **Every 44px tap target** | `min-height: 44px` is a px box. Targets never shrink and never grow |
| **The static map image** and every `enhanced:img` | images carry `width`/`height` and a `sizes` attribute; no font size reaches them |
| **The 52px header emblem** | a px box |
| **Radii, paddings, gaps, borders, grid tracks, breakpoints** | none is expressed as a font size |
| **The prose measure** | `65ch` and `56ch` are relative to the element's own font size, so the measure is preserved **in characters**, which is the property the rule exists for |

**Declared layout consequences at 130%, each with its fix, because a scaled string in a fixed
box is the failure mode this contract exists to prevent:**

| Site | At 130% | Fix in the same commit |
|---|---|---|
| `Header.svelte:79` `.bar { height: 64px }` and `:89` `{ height: 72px }` | a 26px wordmark plus a 15.6px tagline wraps and clips | `min-height` instead of `height`; the bar grows |

### 13. `MobileNav` focus-trap escape (D-23)

**A real WCAG 2.1 AA keyboard trap escape on every page**, absorbed from earlier phases.

`MobileNav.svelte:73-79` handles only `active === first` and `active === last`. The drawer
container carries `role="dialog"`, `aria-modal="true"` and `tabindex="-1"`, so focus can rest
on the container itself; neither branch matches, `preventDefault()` never fires, and Shift+Tab
leaks to the page beneath the modal.

**The fix shape is already proven in `Lightbox.svelte:151-160` under WR-05:** an index of `-1`
means focus is not a member of the cycle, and it enters the cycle at the end the key is
heading for.

```
const pozycja = active instanceof HTMLElement ? focusables.indexOf(active) : -1;
if (pozycja === -1) {
	event.preventDefault();
	(event.shiftKey ? last : first).focus();
	return;
}
```

**No visual change.** The drawer's geometry, treatment, transitions, reduced-motion guard and
copy are byte-identical. It is listed as a contract because it changes the behaviour of a
locked interaction and because the accepting test does not exist yet: `tests/nav.spec.ts`
proves role, first focus, Escape and focus restore but **never presses Tab**. The new island
in Contract 2 uses the corrected shape from the start.

### 14. Global `.visually-hidden`

**There is no global `.visually-hidden` in `src/app.css`.** It is redeclared in **twenty**
places today (`Footer.svelte:274`, `FormField.svelte:276`, `MapPanel.svelte:132`,

`PowtarzalnaGrupa.svelte:470`, `WierszListy.svelte:183`, `PoleWyboru.svelte:205`, plus eleven

- The global goes in `src/app.css` beside the `:focus-visible` base, with the standard

- **Every new markup this phase writes uses it**: the widget trigger's hidden name, the three

  inside the one phase whose deliverable is an accessibility certification, for zero
  user-visible benefit. Recorded as tracked debt with its reason, in the style the project
  already uses, rather than dissolved.
- There is no conflict: a component-scoped `.visually-hidden` has higher specificity than the
  global and its declarations are identical.
- **From v1.8 onward, a new component that hand-rolls a twenty-first copy is a review
  finding.**

**Focus-management contract (additions to v1.5's list and 05's):**
1. Opening the widget focuses the **panel container** (`tabindex="-1"`); closing it restores
   focus to the trigger, by every route out (close button, Escape, scrim).
2. Changing the text size or the contrast **never moves focus**. The control keeps it. A
   settings control that steals focus on change is unusable with a screen reader.
3. „Przywróć ustawienia domyślne" keeps focus on itself and announces through a
   `role="status"` line: `Przywrócono ustawienia domyślne.`
4. Following the footer's „Deklaracja dostępności" or „Polityka prywatności" link is an
   ordinary navigation: the new page's `SkipLink` is the first focusable element, as on every
   route. Neither legal page adds an in-page anchor.
5. Everything else is v1.5 Contract 10 and the 05 additions, unchanged.

native `checked` and three distinct glyph sizes; the contrast checkbox carries native
`checked` and a glyph; the trigger carries `aria-expanded`; the panel-screen errors carry an
icon and an instruction.

## Motion & Reduced Motion

- Transitions stay 150 to 200ms `ease` on colour, border-colour, shadow, opacity and
  transform, matching Phase 1.
- **The one motion this phase introduces** is the widget panel's opacity fade on open and
  close, 150ms, matching the `Lightbox`. It lives inside the component's own
  `@media (prefers-reduced-motion: reduce)` guard **in addition to** the global base-layer
  neutraliser in `app.css:93-106`. Under `reduce` the panel shows and hides instantly.
- **The widget panel does not slide.** It is anchored to its trigger, not a drawer.
- **Switching the theme or the text size animates nothing that was not already animating.**
  Some components carry `transition: background-color 150ms` and will cross-fade their fill
  once on a theme flip; that is a colour transition, not motion, and it is outside WCAG 2.3.3.
  For a visitor who asked for reduced motion the global block already forces it to 0.01ms.
  **No `[data-przelaczanie]`-style transition-suppression hack is added**, deliberately: it
  would be a mechanism whose only job is to hide something that is not a defect.
- **No spinner, no skeleton, no progress bar, anywhere in this phase**, on either the widget
  or the two panel screens. This is the same ruling 04.1 Contract 8 made and for the same
  reason: a spinner is the easiest reduced-motion violation to ship by accident.
- The two legal pages introduce no motion at all.
- No auto-scroll anywhere. Focus movement is the only thing that moves the viewport and it is
  always the result of an explicit action.

## Performance contract (SITE-05)

## Discretion Decisions Recorded (`06-CONTEXT.md` „Claude's Discretion" and gaps the discussion left open)

D-25 through D-29 were recorded by the user as decisions rather than questions and are
implemented, not re-decided. The rows below are the ones this document authored, and they are
listed so the planner implements them and the auditor can check them.

| Area | Decision |
|------|----------|
| **The pre-hydration guard (D-12's open research question)** | **Answered: SvelteKit's `auto` mode will NOT hash a hand-authored inline script in `app.html`.** `csp.add_script()` runs only over SvelteKit's own generated bootstrap. Therefore, per D-12, **we ship the flash and record why**. The same-origin external-file alternative was weighed and rejected on SITE-05 grounds (Contract 2) |
| **The `TopBar` 36px breach** | **Fixed, not recorded.** `padding-block` 4px to 0 plus 44px items leaves the bar height unchanged at 44px, so the compliant option is also the free one |
| **The global `.visually-hidden`** | **Added, and the twenty existing copies stay.** Every new markup uses the global; refactoring twenty components inside an accessibility-certification phase is risk without benefit (Contract 14) |
| **High-contrast palette size** | **Three values, not two.** `#B91C1C` on black is 3.25:1 and fails AA, so a third value is forced. White carries exactly two roles, the focus ring and the error foreground, and appears nowhere adjacent to yellow without a black separator |
| **How the theme reaches the surface** | **Two layers with stated domains**: a token flip in `app.css` for the ~70%, plus an enumerated register of component-scoped `:global(html[data-kontrast='wysoki'])` overrides for the rest. Global Layer-2 rules in `app.css` were rejected: `.inner`, `.col` and `.chip` recur across components and would leak |
| **Whether new `@theme` tokens should absorb the seventeen literals** | **No.** A semantic „on-surface" token family (`--color-on-brand` and friends) was designed and rejected: it changes the default theme's declarations, so the „default theme cannot regress" property would become something to test rather than something guaranteed by the attribute gate |
| **The muted tier in high contrast** | **Collapses into the text value.** Hierarchy is carried by size and weight. Lightening or darkening text toward the background is the exact thing the mode exists to escape |
| **The Perks accent band** | **The one place the accent flip is wrong** and it gets an explicit override to black plus a 2px border. Every other accent surface is a small chip or button where the yellow fill with a black label is right |
| **Photographs in high contrast (D-10)** | **2px yellow border, never dimmed, never desaturated, never hidden.** Applied to the hero image slot, every gallery tile, the lightbox's enlarged photo, the news cover and the static map |
| **Full-colour brand assets in high contrast** | **White image plates with a 2px yellow border**, and black text pinned on them. The header emblem, the footer lockup, the `.logo-slot` chips and the EU strip. Yellow on the white plate is 1.07:1 and is banned outright |
| **The Wave divider in high contrast** | **`display: none`.** Its only job is a colour seam between two surfaces the mode makes identical |
| **The text-scale mechanism** | **Fourteen `calc()` type tokens driven by one multiplier**, converted token-for-token across the 167 public `font-size` declarations. `zoom` was rejected: it scales geometry, and 130% on a 360px phone yields a 277px effective viewport, below the 320px reflow floor the site was designed to. Converting the whole codebase to `rem` was rejected as a larger, riskier change with the same outcome |
| **Panel scope of the scale refactor** | **Public tree only.** The 123 `font-size` declarations under `/admin` are untouched, because both attributes are structurally absent there and the conversion would be inert churn |
| **`prefers-contrast: more`** | **Not wired.** Opt-in only. A visitor who never asked should not have the site repainted |
| **`forced-colors`** | **Not overridden.** No `forced-color-adjust: none` anywhere; the system palette wins |
| **Widget placement of the panel** | **Anchored popover, not a drawer and not a full-screen dialog.** `z-index: 80`, above the sticky header's 50 and the drawer's 70 |
| **Widget first focus** | **The panel container**, a declared deviation from `MobileNav`'s close-button-first rule, safe only because the corrected `-1` cycle entry is used. Both are stated together on purpose |
| **Body scroll lock in the widget** | **Not applied.** A 320px anchored popover is not a mode |
| **Widget controls** | **Native radios in a `<fieldset>` and a native checkbox.** Arrow-key navigation, one tab stop and correct group semantics for free, the same ruling 04.1 Contract 8 made for the file input |
| **Where the two new panel screens live** | **Pulpit tiles, not nav items**, following `/admin/w-skrocie` (05 D-34). Both are edited roughly once a year and a tenth and eleventh nav chip would put four rows of navigation above every screen on a phone |
| **The statutory section list** | **Code-authored and locked; no control can add, remove, rename or reorder a section.** Only values and prose are editable. This is the safety property D-16 buys |
| **The twelve `KLAUZULA` blocks on the panel screen** | **Read-only, rendered as text with a hint naming where they live.** Never a `disabled` input (the 05 Contract 11 ruling) |
| **The klauzula's heading level on the public page** | **`h3` under an `h2` scoping them to forms.** Hoisting them to `h2` would state a scope they do not have and would break the heading order on the page this phase certifies |
| **The placeholder checkbox granularity on the deklaracja screen** | **Per block, not per file.** Koordynator, architektura and dodatkowe are confirmed at different times by different people; one file-level flag would go false while two thirds of the page was still invented |
| **EU strip placement** | **Foot of the footer, above the copyright, on every route, on a white plate, not `aria-hidden`.** It is a legal artefact, so it is announced. „Aktywny Maluch" moves into it from the brand column |
| **The EU klauzula's en dash** | **Byte-exempt**, joining the verbatim client core message. Rewriting a statutory marking to satisfy a house style rule is the wrong trade |
| **Conformance status** | **„częściowo zgodna"**, with the DOC downloads (D-29) and Turnstile named. „zgodna" would be false while either stands; „niezgodna" would be false after this phase's audit |
| **Both legal pages adopt `Seo.svelte`** | The hand-rolled `<title>` and `<meta name="robots">` are deleted, so the two pages stop being a second SEO mechanism and gain the description, canonical and OG tags every other route has. See §Findings for the consequence |
