# Phase 4 — UI Design Contract

> Visual and interaction contract for `/rekrutacja`, `/kontakt` and the two form islands. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This document is UI-SPEC Amendment v1.4** (per 04-RESEARCH.md Open Question 4). The Phase 1 contract and Amendments v1.1, v1.2 and v1.3 stay in force in full. **Nothing here re-derives a token.** Every colour, size, radius, shadow and spacing value below already exists in `src/app.css`; this document only assigns them to the form, table, map and status surfaces that Phase 1 never defined.

**Scope:** RECRUIT-01, RECRUIT-02, RECRUIT-03, RECRUIT-04, CONTACT-01, CONTACT-02, CONTACT-03, FORM-01, FORM-02.
**Stack context:** SvelteKit 2 + Svelte 5 runes + Tailwind v4 CSS-first `@theme` (no `tailwind.config.js`). Pages prerender; only the two `+server.ts` form endpoints are dynamic. shadcn/ui is React-only and does not apply.
**Language:** Polish only (SITE-06). Every string in the Copywriting Contract is the authoritative Polish copy.
**Copy rules (v1.2 §8, non-negotiable):** no emoji, no em dashes anywhere (use commas, colons, parentheses), en dash only inside numeric ranges (`8:00–15:00`), plain hyphen in day abbreviations (`pon.-pt.`).

## Spacing Scale

Inherited unchanged from Phase 1 (8-point scale, all multiples of 4):

| Token | Value | Usage in Phase 4 |
|-------|-------|------------------|
| `2xs` | 4px | Required-asterisk gap, icon-to-text inset in error messages |
| `xs` | 8px | Label to input gap, input to error-message gap, checkbox row inner gap |
| `sm` | 12px | Input/control vertical padding, checkbox-to-label gap (documented v1.0 control-padding exception, not layout spacing) |
| `md` | 16px | Form card padding (base), table cell padding, panel padding (base) |
| `lg` | 24px | Gap between form fields, form card padding (`md`+), panel padding (`md`+), grid gaps |
| `xl` | 32px | Two-column form grid gap, section sub-blocks |
| `2xl` | 48px | Section vertical padding (mobile) |
| `3xl` | 64px | Page-level spacing |
| `4xl` | 96px | Section vertical padding (desktop, `lg`) |

**Exceptions (inherited or WCAG-mandated), all multiples of 4:**
- **44×44px minimum hit area** on every interactive element (Phase 1 rule): inputs, selects, checkbox row, `<summary>`, submit button, tel/mailto links, table links.
- **Input / select height:** 48px minimum (`12px` vertical padding + 16px text at 1.5 line-height). Exceeds the 44px floor deliberately, forms are the phase's primary interaction.
- **Textarea:** 160px minimum height, `resize: vertical` only.
- **Checkbox control box:** 24×24px, inside a label row of 44px minimum height.
- **Map panel:** 260px minimum height (inherited from v1.1 ContactAndMap).

**Deliberate exception to the multiple-of-4 rule (exactly one, vendor-fixed):**
- **Turnstile widget slot:** reserved **300×65px** minimum so the hydrating widget causes no layout shift. 65px is Cloudflare's own rendered widget height, a vendor-fixed component dimension we do not control, not a layout, grid or rhythm value. Rounding down to 64px would clip the rendered widget by 1px; rounding up to 68px would leave 3px of dead space inside the reserved slot and still not match the widget. The vendor value is therefore used verbatim.
- Scope of the exception: it is the **only** non-multiple-of-4 value in the spacing and layout system, it applies solely to the reserved footprint of a third-party embed, and it is never used as a padding, margin, gap or section-rhythm value. Every spacing value the design system itself owns stays on the 4px grid.
- Not covered by this rule, and unchanged: the inherited type scale (13/14/15/16/17/20px), icon glyph sizes (18px, 22px, 44px) and the inherited v1.2 34px step circle. Those are glyph and type dimensions, not spacing tokens, and the multiple-of-4 rule has never applied to them in this project.

**Hard rules added by this amendment:**
1. **Error state is never colour alone (WCAG 1.4.1).** Every error carries an icon (`circle-alert`), a text message, `aria-invalid="true"` and a 2px danger border. Removing colour must leave the error fully perceivable.
2. **`danger` never signals "nabór zamknięty".** A closed recruitment is neutral information: band surface, ink text. Red is reserved for failures.
3. **Placeholder attributes are banned on inputs.** Guidance lives in a persistent `<p class="hint">` wired via `aria-describedby`, never in a `placeholder` that disappears on typing and fails contrast.

## Component Contracts

### 1. Form card (wrapper for both islands)

- Surface `--color-surface` `#FFFFFF`, `--radius-lg` 24px, `shadow-md`, **2px `--color-band` `#E0F2FE` border** (matches the v1.1 Recruitment card).
- Padding 24px (base) → 32px (`md`+). Max width 46rem, centred inside the section.
- Contains, in DOM order: `h2` → intro paragraph → required-fields note → status region (empty on load) → fields → Turnstile slot → consent block → klauzula `<details>` → submit row.
- `<form novalidate>`: browser-native validation bubbles are unstyleable and English in some locales, so validation messaging is ours (Polish, C-01). `novalidate` does not remove `required`/`type` attributes, which stay for semantics and mobile keyboards.

### 2. Field block (`FormField`) — the a11y contract for every input

- Vertical stack: `<label>` (Nunito 700 15px, ink) → optional `<p class="hint">` (Nunito 400 15px, muted) → control → optional error message. Gaps 8px. Gap between field blocks 24px.
- **Control:** height ≥48px, padding `12px 16px`, `--radius-sm` 8px, background `#FFFFFF`, **2px solid `--color-border-strong` `#64748B`**, text ink 16px/1.5, `width: 100%`.
- **`aria-describedby`** lists only ids that exist: `{id}-hint` and/or `{id}-err`. Never a dangling reference (a screen reader announces nothing at all when one id is missing).
- **Required marking:** `*` after the label text plus visually-hidden ` (pole wymagane)`, and `required aria-required="true"` on the control. The single optional field carries `(opcjonalnie)` in its visible label.
- **Autocomplete (WCAG 1.3.5):** `autocomplete="name"` on the parent name, `autocomplete="email"`, `autocomplete="tel"`.
- **Textarea:** same box, `min-height: 160px`, `resize: vertical`, plus a live character counter is **not** used (it adds an `aria-live` chatter surface for no benefit at this volume); the length cap is stated in the hint instead.
- **Birth month + year:** a `<fieldset>` with a visible `<legend>` and two `<select>` controls (miesiąc, rok) side by side (stacked below 640px). `<input type="month">` is rejected: its picker chrome is browser-locale dependent and cannot be forced to Polish. Selects carry Polish month names and an explicit empty first option.

| State | Border | Background | Extra |
|-------|--------|------------|-------|
| Default | 2px `border-strong` `#64748B` | `#FFFFFF` | — |
| Hover | 2px `ink` `#1E293B` | `#FFFFFF` | cursor text |
| Focus-visible | unchanged | `#FFFFFF` | global 3px `focus-ring` outline, 2px offset (never removed) |
| Invalid | 2px `danger` `#B91C1C` | `#FFFFFF` | `aria-invalid="true"` + icon + message below |
| Disabled (while sending) | 2px `border-subtle` `#E2E8F0` | `#FBFAF7` | `disabled`, cursor `not-allowed` |

- **Error message:** `<p id="{id}-err">`, Nunito 700 15px `--color-danger`, prefixed by a 18px Lucide `circle-alert` (`aria-hidden`), 8px gap. The message says **what to do**, not just that something is wrong (WCAG 3.3.3).

### 3. Consent block (`ConsentBlock`) — RODO (RECRUIT-04)

- `<label>` row: 24×24px checkbox + 12px gap + consent text (Nunito 400 15px ink, 65ch, `line-height: 1.5`). Row `min-height: 44px`, `padding: 8px 0`, `align-items: flex-start`, whole row clickable.
- Checkbox visual: `--radius-sm` 8px, 2px `--color-border-strong`, white fill. **Checked:** `--color-brand-blue` fill with a white checkmark glyph (5.93:1). **Invalid:** 2px `--color-danger` + message below. Focus uses the global ring on the real `<input>` (never `appearance:none` without a focus-visible replacement).
- **The checkbox is unticked in the markup, always.** No `checked`, no persisted value, no "remember me". Server re-validates `zgoda === true` (research §6).
- Accent is **not** used here: the consent checkbox is not a CTA.

### 4. Klauzula informacyjna (`<details>`) — new treatment in v1.4

- Native `<details>` directly beneath the consent row, 16px above it. **Never JS-driven**: native disclosure is keyboard and screen-reader correct for free.
- `<summary>`: Nunito 700 14px `--color-brand-blue`, underlined, `min-height: 44px`, `display: flex; align-items: center; gap: 8px`, custom marker removed (`list-style: none`, `::-webkit-details-marker { display: none }`) and replaced by a Lucide `chevron-down` 18px `aria-hidden` that rotates 180° when open. The rotation transition is inside the component's `prefers-reduced-motion` guard.
- Open panel: `--color-surface-warm` `#FBFAF7`, `--radius-md` 16px, padding 16px (base) → 24px (`md`), 8px top margin. Prose Nunito 400 15px `--color-muted`, max 65ch, paragraph gap 12px; inline sub-headings Nunito 700 15px ink; inline links brand-blue underlined.
- The klauzula text is long legal prose. It is authored this phase, and the copy rule that most often breaks here is the em-dash ban (C-11): use commas, colons, parentheses.
- Content obligations (checked by the plan, not styled here): administrator, IOD contact (`PLACEHOLDER`), purpose + legal basis, recipients naming **Resend** and **Cloudflare** as processors, **transfer to the USA and its legal mechanism** (Resend stores account data, logs and API records in the US regardless of sending region, 04-RESEARCH.md Pitfall 3), the **~30-day copy at the processor**, the **temporary BCC backup mailbox** (D-13), the salted-hash rate-limit security measure, retention, and data-subject rights. Nothing is stored in our infrastructure, and the wording must say exactly that rather than a blanket "nie przechowujemy".

### 5. Turnstile slot (`TurnstileWidget`)

- Container reserves **300×65px minimum** before hydration so the widget causes no layout shift. 65px is the vendor-fixed Cloudflare widget height and is the single declared exception to the multiple-of-4 spacing rule (see Spacing Scale). Placed after the last field, before the consent block, 24px gaps.
- `language: 'pl'`, light theme (matches the white card).
- On any failed submit the island calls `turnstile.reset(widgetId)` before re-enabling the submit button (tokens are single-use, 300s TTL: research Pitfall 4).
- If the widget fails to load or expires, the submit button stays enabled and the failure surfaces as the Polish `turnstile` error copy with the phone fallback. It never blocks the UI silently.

### 6. Submit row

- Primary `Cta` variant, unchanged from v1.2 §4 (pill, amber fill, ink label, `0 3px 0 accent-active`, hover `translateY(-2px)`, active/focus-visible pressed flip, 44px target, `12px 24px` padding, Body 16px/700).
- Full width below 640px, auto width above, left-aligned.
- **Sending state:** `disabled`, `aria-busy="true"`, label swaps to `Wysyłanie...`. **No spinner animation** (nothing to disable under reduced motion, nothing to fail to load). The status region simultaneously announces the sending state politely.
- Beneath the button, always visible and always prerendered: the fallback line (phone + e-mail), see §8.

### 7. Status regions, success and failure (D-11, D-12)

Three distinct surfaces, all inside the form card except where noted:

**a) Error summary (validation failure, top of the card)**
- `role="alert"`, `tabindex="-1"`, focused programmatically on failed submit.
- `--color-danger-surface` `#FEF2F2`, 2px `--color-danger` border, `--radius-md`, padding 16 → 24px.
- Heading Baloo 700 20px `--color-danger` + `circle-alert` icon; body ink 15px; then a `<ul>` of in-page links (`#field-id`), each brand-blue underlined, that move focus to the offending control.

**b) Success panel (replaces the form in place)**
- The `<form>` is removed from the DOM and replaced by a panel with `role="status"`, `tabindex="-1"`; **focus moves to its heading** (mandatory: an in-place swap is otherwise invisible to a screen-reader user).
- `--color-tint-green` `#DFF0D8` surface, `--radius-md`, padding 24 → 32px, 44px Lucide `circle-check` in `--color-brand-blue` (5.13:1). Heading Baloo 700 20px ink, body Nunito 400 16px muted, max 65ch.
- No confetti, no animation, no auto-redirect.

**c) Send-failure panel (endpoint returned 429 / 502 / network error)**
- `role="alert"`, `tabindex="-1"`, focused, rendered **above the form, with the form and every typed value intact** (D-12: a failure must never look like a success and must never destroy the parent's input).
- `--color-danger-surface`, 2px `--color-danger` border, `--radius-md`. Heading Baloo 700 20px `--color-danger`; body ink 15px stating plainly that the message was **not** sent (emphasis via `<strong>`, never capitals-only); then the direct fallback: `tel:` link and `mailto:` link, both brand-blue underlined, 44px targets.

**d) Polite status line**
- A permanently present `<p role="status" aria-live="polite" class="visually-hidden-when-empty">` that carries `Wysyłanie wiadomości...` during the request. Success and failure are announced by the panels above (`role="status"` / `role="alert"`), never duplicated here.

### 8. Static fallback contact block + `<noscript>` (research Pitfall 7)

- Always present in the **prerendered** HTML, above the form card, never revealed conditionally by JS: phone (`tel:`), e-mail (`mailto:`), and for `/rekrutacja` the Urząd Gminy address for formal wnioski.
- Treatment: `--color-tint-blue` `#CFE8FC` panel, `--radius-md`, padding 16 → 24px, Lucide `info` 22px brand-blue, ink 15px text.
- A `<noscript>` note directly above the form card with the same panel treatment, stating that the form needs JavaScript and pointing at the phone number.

### 9. Status banner (`/rekrutacja`, D-06/D-14)

- Band `#E0F2FE` surface, `--radius-md`, padding 16 → 24px, max 46rem.
- 8px brand-blue dot (decorative, `aria-hidden`) + title Baloo 700 20px ink + supporting line Nunito 400 15px `--color-muted` + deadline line Nunito 700 15px `--color-focus-ring` (matching the v1.1 Recruitment header strip).
- **Never danger-coloured.** A closed nabór is neutral information.

### 10. Kryteria + punktacja table (RECRUIT-01)

- A real `<table>` with a visible `<caption>` (Nunito 700 15px muted, left-aligned, 8px below), `<thead>` with `<th scope="col">`, and `<th scope="row">` on each kryterium.
- Two columns: **Kryterium** (ink 16px, wraps) and **Liczba punktów** (Baloo 700 17px `--color-accent-active` 5.02:1, right-aligned, `white-space: nowrap`).
- Cell padding 12px 16px; 1px `--color-border-subtle` row separators; `<tbody>` zebra `#FBFAF7` on odd rows (decorative only, carries no information).
- Fits mobile at two columns with wrapping: **no horizontal scroll container is used.** If a third column is ever added, it must be wrapped in a `tabindex="0"` `role="region"` labelled scroll container, otherwise keyboard users cannot scroll it.
- Full width up to 46rem, `border-collapse: collapse`, `--radius-md` clipping optional on the wrapper only.

### 11. Compact fee box (D-15)

- `--color-tint-yellow` `#FFE29A` surface, **2px `--color-accent` border**, `--radius-md`, padding 16 → 24px (identical to the v1.2 Recruitment info card).
- Headline value Baloo 700 20px ink; qualifying lines Nunito 400 15px ink; the ZUS condition is part of the same block and never separated from the amount.
- **Never renders an unconditional `0 zł`** (dane-bip §10.1 hard gate). Marked `// PLACEHOLDER:` in the content module pending the client's wording confirmation (D-09).

### 12. Map panel (CONTACT-02, D-17)

## Interaction & States (Phase 4 additions to the global table)

| Surface | Default | Hover | Focus-visible | Active / Invalid |
|---------|---------|-------|---------------|------------------|
| Text input / select / textarea | 2px `border-strong`, white | 2px `ink` | 3px `focus-ring`, 2px offset | 2px `danger` + icon + message |
| Consent checkbox | 2px `border-strong`, white, 24px | 2px `ink` | ring on the real input | checked: brand-blue fill + white glyph; invalid: 2px `danger` |
| `<summary>` (klauzula) | brand-blue 14px/700 underlined, chevron down | `brand-blue-hover` `#075985` | ring | open: chevron rotated 180° |
| Submit button | primary `Cta` (amber / ink, `0 3px 0`) | `accent-hover` + `translateY(-2px)` | ring, mirrors pressed | pressed flip; sending: `disabled` + `Wysyłanie...` + `aria-busy` |
| Document row link | brand-blue underlined | `brand-blue-hover` | ring | — |
| Directions button | secondary variant (blue outline) | `#E0F2FE` fill | ring | — |

**Focus management contract (the part most often missed):**
1. Validation failure → focus the error summary panel (`tabindex="-1"`).
2. Success → form removed, focus the success-panel heading (`tabindex="-1"`).
3. Send failure → focus the failure panel; **every typed value stays** and the Turnstile widget is reset.
4. Focus is never moved on keystroke, on blur, or while the parent is typing.

## Motion & Reduced Motion

- Transitions stay 150–200ms `ease` on colour, border-colour, shadow and transform, matching Phase 1.
- New motion introduced by this phase: the `<summary>` chevron rotation and the submit button's existing press transform. Both live inside component-scoped `@media (prefers-reduced-motion: reduce)` guards, in addition to the global base-layer neutraliser in `app.css`.
- **No spinner, no skeleton, no auto-scroll, no animated success.** Panel swaps are instant.

## Accessibility Contract (WCAG 2.1 AA — forms are this project's highest-risk surface)

- Every control has a programmatically associated `<label>` (`for`/`id`). No label-less inputs, no `placeholder` used as a label, no `aria-label` substituting for a visible label.
- Grouped controls (miesiąc + rok) use `<fieldset>` + visible `<legend>`.
- Errors satisfy **3.3.1 (identification)**, **3.3.2 (labels/instructions)** and **3.3.3 (suggestion)**: identified in text, wired via `aria-describedby`, and phrased as an instruction.
- `aria-invalid="true"` set only while a field is actually invalid, cleared on correction.
- One `role="alert"` region for failures, one `role="status"` for success and the polite sending line. No competing live regions.
- Exactly one `h1` per page; heading order unbroken (`h1` → `h2` → `h3`).
- Every interactive target ≥44×44px; the global 3px focus ring is never removed.
- Colour is never the only signal: errors carry icon + text, links stay underlined, the checked checkbox carries a glyph.
- Native `<details>` is used unmodified for the klauzula (keyboard operable, expandable by default).
- `prefers-reduced-motion` honoured.
- **Gate:** zero axe violations on `/rekrutacja` and `/kontakt`, including the rendered error state with `aria-invalid` set.
