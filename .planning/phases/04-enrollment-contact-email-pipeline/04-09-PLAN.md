<objective>
Close WR-02, the one remaining unremediated Warning from `04-REVIEW.md` that `04-VERIFICATION.md` confirmed still present verbatim.

`src/lib/components/TurnstileWidget.svelte` assigns `window.__onTurnstileLoad = rysuj` when the Turnstile API is not yet loaded, but its `$effect` cleanup only removes the widget and never clears that global. Two consequences: if the component unmounts before `api.js` finishes loading, the loader later invokes the stale closure and renders into a detached container, writing a `widgetId` into a destroyed component instance that the already-run cleanup can no longer reach; and on client-side navigation between `/kontakt` and `/rekrutacja`, Svelte removes and re-inserts the `svelte:head` script tag, a re-inserted script element re-executes, and `api.js` calls the named onload callback again, which is still the PREVIOUS page's closure because the new page took the `window.turnstile` fast path and never reassigned the global.

Nothing here weakens security: acceptance is decided server-side by `siteverify` and the token contract is owned by the endpoint. It is a lifecycle defect that produces orphaned widgets, possible duplicate-render errors from the Turnstile API, and an unreachable `widgetId`. On the site's only two dynamic features, a widget that silently fails to render leaves a parent unable to submit at all, which is why it is being closed rather than deferred.

Purpose: make the effect own the whole lifetime of everything it installs.
Output: a corrected widget wrapper and a Playwright case that goes red on the current code and green after the fix.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party loader (`challenges.cloudflare.com/turnstile/v0/api.js`) to the page | Untrusted external script executing in the page, invoking a named global callback this component installs. |
| component instance to `window` | A named global is shared process-wide across every component instance and every client-side navigation; ownership of it is ambiguous by construction. |
| browser to POST /api/kontakt and /api/rekrutacja | The token crosses here, but acceptance is decided server side by `siteverify`. The widget is a token producer, never an authority. |
