## Phase Goal

**As a** rodzic (parent), **I want to** read enrollment information, download the wnioski, and send an enrollment or contact message from the website, **so that** I can reach the żłobek and start the enrollment process without a visit, knowing my data is handled lawfully and never stored.

## MVP Slice (this plan)

**Slice B (Rekrutacja), plan 1 of 2.** The second user-facing capability of the phase gets its working pipeline and its interface: a waitlist zgłoszenie that a parent can fill in and send. Plan 06 mounts it on /rekrutacja alongside the enrollment information and the slice is complete.

<objective>
Extend the proven form pipeline with the zgloszenie shape, ship the /api/rekrutacja endpoint, and build the ZgloszenieForm island against the same accessibility and copy contract as the contact form (RECRUIT-03, RECRUIT-04, FORM-01, FORM-02, D-01, D-02).

Purpose: the enrollment form carries a child's data, so it is the most RODO-sensitive surface in the project. It reuses the already-proven orchestrator rather than growing a second, subtly different pipeline.
Output: a second working endpoint, a second island, and unit plus endpoint tests proving the minimal-data contract.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /api/rekrutacja | Untrusted JSON carrying a child's month and year of birth, the most sensitive data this project handles, crosses into a Pages Function. |
| Pages Function -> Resend | The constructed enrollment body crosses to the external processor. |
| Pages Function -> Workers KV | A second, independently keyed integer counter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-24 | Information Disclosure | over-collection of a child's personal data | high | mitigate | The validated type has no field for a child's name; an extra key in the request body is dropped by the validator and can never reach the mail body, proven by a unit case. The form markup contains no such control and the hint explicitly instructs the parent not to supply one. |
| T-04-25 | Elevation of Privilege | a second endpoint diverging from the proven security ordering | high | mitigate | The endpoint reuses obsluz() unchanged (grep-checked) rather than reimplementing the pipeline, so the cheap-checks-first ordering, the fail-closed Turnstile call, the rate limit and the constant recipient are shared by construction. |
| T-04-26 | Denial of Service | one form exhausting the other form's abuse budget | medium | mitigate | The KV key includes the form name, so /api/kontakt and /api/rekrutacja hold independent counters. |
| T-04-27 | Tampering | e-mail header injection through the enrollment reply-to | high | mitigate | The same bezpiecznyEmail reject-never-repair validator guards this endpoint; the subject is a second static constant and no user value reaches any header. |
| T-04-28 | Repudiation | a lost enrollment enquiry presented as sent | high | mitigate | The send is awaited, a non-2xx maps to 502 with code wysylka, and the island renders the not-sent panel with the phone fallback while keeping every typed value. |
| T-04-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in this plan. |
</threat_model>
