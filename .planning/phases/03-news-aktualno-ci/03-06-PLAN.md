<objective>
Close WR-02 (the second Blocker, falsifying the Plan-01 must-have "a malformed entry is skipped, never aborts the whole prerender") and fix WR-04 (the error page ships no document title — a WCAG 2.4.2 Level A gap in this phase's own D-08 deliverable, on a site legally required to meet AA).

WR-02: `parseData(entry.data)` calls `.trim()` and `firstParagraph(entry.tresc)` calls `.split()` with no type guard, so one post JSON missing `data` or `tresc` throws a `TypeError` that aborts the ENTIRE build (homepage, list, and every post) — the exact failure the module's own doc comment promises to prevent (the `dokumenty.ts` `withMeta` skip-with-warning precedent). The reader is the direct consumer of hand-edited/partially-committed git content, so this is a real availability threat, not a theoretical one.

WR-04: `+error.svelte` emits no `<title>` and `app.html` has no fallback, so every error response (including the phase's own unknown-slug 404) is served untitled; browser tabs and screen readers announce the raw URL.

Purpose: the site stays buildable under bad content and accessible under error states — hardening the visitor-facing resilience of an already-shipped phase.
Output: a type-guarded, unit-tested reader; a Node-built-in resilience test + `test:unit` script (no new dependency); a titled error page; and a strengthened 404 acceptance assertion.

## Slice framing (MVP / gap closure)
Vertical slice, not a layer: after this plan a real, end-to-end scenario changes — dropping a malformed `.json` into the content folder no longer takes the whole site's deploy down (it is skipped with a warning), and hitting any 404 now announces a real Polish page title. Depends on 03-05 because both edit `src/lib/server/aktualnosci.ts` (parseData); 03-05's ISO parse lands first, then this plan hardens it. The ROADMAP `**Goal:**` line is not in strict user-story form, so this is the slice's own story:

**As a** site visitor (and as staff who need the site to stay online), **I want to** have one bad or hand-edited post get skipped instead of crashing the whole build, and error pages carry a real title, **so that** the site stays available and accessible when content is imperfect.
</objective>
