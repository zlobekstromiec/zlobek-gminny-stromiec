<objective>
Close CR-01 (the sole Blocker falsifying roadmap SC3b / NEWS-03 must-have D-06): the Sveltia `aktualnosci` slug template feeds the collection's own `DD.MM.YYYY`-stored `data` value into a `date` transformation that cannot parse it, minting a permanently wrong (days 1-12, MM/DD swap) or dateless (days 13-31, Invalid Date) URL for every CMS-authored post. Per D-07 slugs are fixed at creation, so the wrong URL is forever.

Fix per the verification `missing:` block and 03-REVIEW.md CR-01: store `data` in ISO so the slug can substitute it verbatim (no fragile transformation), keep the Polish picker display, and coordinate the build reader + the two seed files to the new storage format so nothing regresses.

Purpose: Staff-published news URLs become correct and permanent — the last thing standing between Phase 3 and its "publish via the CMS" success criterion.
Output: An ISO-storage `data` field + plain slug template in config.yml, an ISO-parsing reader, and two migrated seed JSONs. Visitor-facing date display and existing slugs are unchanged.

## Slice framing (MVP / gap closure)
This is a vertical slice, not a layer: after this plan, a post created through the live CMS receives a correct date-prefixed URL end to end (editor picks a date -> ISO stored -> slug substitutes it -> reader renders the same date), and the two existing posts keep rendering. The ROADMAP `**Goal:**` line is not in strict `As a / I want to / so that` form, so this is the slice's own story:

**As a** member of nursery staff, **I want to** have every news post I publish through the CMS get a web address that matches the publication date I entered, **so that** the post's URL is correct and permanent for every day of the month.
</objective>
