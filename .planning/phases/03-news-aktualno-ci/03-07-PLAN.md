<objective>
Close the single residual blocker from `03-VERIFICATION.md` (status `gaps_found`, 8/10): the Plan-01 must-have "a malformed post entry never aborts the whole prerender" is still falsified. `postFromEntry` in `src/lib/server/aktualnosci.ts` type-guards `entry.tresc` only inside the excerpt-fallback branch, which is skipped whenever `zajawka` is a non-empty string; the return statement then object-spreads the raw entry, so `tresc` and `obraz` reach consumers unvalidated. Reproduced consequences: an entry `{ tytul, data, zajawka }` with no `tresc` yields `post.tresc === undefined` and `marked.parse(undefined)` throws during the `entries()`-driven prerender of `/aktualnosci/[slug]`, aborting the entire build; a non-string `obraz` throws `TypeError` at the basename split in `NewsCard.svelte:44` and `src/routes/aktualnosci/[slug]/+page.svelte:39`. The same defect is independently documented as WR-01 in the fresh `03-REVIEW.md`.

This is the third recurrence of one bug class (03-06 closed two crash shapes and missed a third), so the fix is structural rather than "one more guard": stop emitting anything that was not produced by a type guard. `postFromEntry` takes `unknown`, validates every field it emits, and builds its result key by key.

Purpose: the deploy survives imperfect content. Staff hand-edit and partially commit post JSON through a git CMS with no schema validation, so one bad file must cost one post, never the whole site. Preserves D-03 (every well-formed entry renders; the date is sort/display metadata only) and D-01 (an imageless post renders the tint fallback, never a broken box) — a bad `obraz` now degrades into exactly the D-01 path.
Output: a reader whose output shape is fully guarded, a unit suite that goes red first and pins the contract afterwards, and a build-level proof that a malformed post no longer takes the site down.
