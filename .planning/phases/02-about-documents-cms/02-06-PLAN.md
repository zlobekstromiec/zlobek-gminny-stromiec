# Plan 02-06: Admin UX gap closure (icons, Polish chrome, warm light theme)

## Objective

UAT feedback from the 02-05 live-loop checkpoint: the Sveltia editor rendered
icon names as raw text (CSP-blocked jsDelivr fonts), half-English chrome
(CSP-blocked unpkg locale fetch), and a dark, hard-to-read theme. Close all
three gaps without patching the pinned bundle and without weakening the
/admin/* CSP.

## Tasks

1. Self-host fonts: vendor the Material Symbols variable woff2 (the exact file
   the bundle references) plus Nunito 400/700 latin/latin-ext under
   static/admin/fonts/; same-family @font-face rules in a body-linked
   admin.css win the duplicate resolution over the bundle's CSP-blocked rules.
2. Polish chrome + forced light theme: generate locale-pl.js from the installed
   @sveltia/cms locales/pl.json (version-locked via scripts/cms-sync.mjs);
   preboot.js seeds sveltia-cms.prefs (theme light, locale pl, absent fields
   only) and the sveltia-cms.locale cache before the bundle boots.
3. Warm readable theme: map the site's locked accessible tokens onto the
   --sui-* custom-property system ([data-theme=light] scope only; stock dark
   kept for explicit user choice). Nunito at 16px base.
4. Guidance layer: collection descriptions, missing field hints, app_title in
   config.yml; instrukcja updated (chrome now Polish, light theme default).

## Verification

Local wrangler pages dev against the real _headers CSP: icons render as glyphs
(ligature test 24px), login chrome fully Polish, html[data-theme=light] from
first paint, explicit dark pref survives reload, zero successful external
requests, bundle byte-identical after cms:sync, npm run check/lint/test all
green (43/43).
