# Phase 2 — UI Design Contract

> Visual and interaction contract for the **About, Documents & CMS** phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a delta spec.** The project-wide design system is LOCKED in Phase 1 (`01-UI-SPEC.md` + Amendments v1.1/v1.2). Every token, type size, weight, color, radius, shadow, spacing value, motion rule, and accessibility rule is inherited **verbatim and unchanged**. This document adds ONLY the new surfaces this phase introduces:
> 1. `/o-nas` page composition (ABOUT-01)
> 2. `/dokumenty` page composition (DOCS-01)
> 3. CMS admin Polish copy contract at `/admin` (CMS-03) — the only surface with a locale caveat
> 4. Homepage `Recruitment` docs-panel copy realignment (D-18)
>
> **Do NOT re-derive colors, type, spacing, or components.** Where this spec is silent, the Phase 1 contract governs.

**Scope:** ABOUT-01, ABOUT-02, DOCS-01, DOCS-02, CMS-01, CMS-02, CMS-03.
**Stack context:** SvelteKit 2 + Svelte 5 (runes) + Tailwind CSS v4 (`@tailwindcss/vite`, CSS-first `@theme{}` — there is **no** `tailwind.config.js`). Both new routes prerender to static HTML on Cloudflare (zero-JS, consistent with existing content pages). shadcn/ui is React-only and **does not apply**. The CMS admin (`/admin`) is a self-hosted Sveltia SPA — outside SvelteKit routing and outside this design system.
**Language:** Polish only (SITE-06, CMS-03). All strings below are the authoritative Polish copy. **Copy rules (locked, v1.2 §8):** no emoji; no em dashes in authored copy or comments; en dash only inside numeric ranges; day abbreviations use plain hyphen (pon.-pt.); use commas, colons, and parentheses instead of em dashes.

## Spacing Scale

**Inherited unchanged from Phase 1.** No new spacing tokens. The two new pages use the established section rhythm:

- Page section vertical padding: `48px` (base) → `64–80px` (`lg`), matching existing content sections (DayPlan uses 48→64; AboutTeaser/Recruitment use 48→80).
- Container: max-width `72rem`, centered, gutters `16px` → `24px` (`md`) → `32px` (`lg`).
- Prose measure: running narrative capped at ~`52–65ch`.
- Card inner padding: `16px` (mobile) → `24–28px` (desktop).

**Exceptions:** Interactive targets (document download links, CMS-driven links) keep the **minimum 44×44px hit area** (WCAG 2.5.5). Document rows follow the existing `.doc-row` pattern: `min-height: 48px`, `padding: 8px 0`.

## Typography

**Inherited unchanged from Phase 1 (+ Amendments v1.1/v1.2).** Exactly two weights (Regular 400, Bold 700); two families (Baloo 2 display, Nunito body). No new sizes are introduced — the extended v1.1/v1.2 scale (13/15/17/19/26px alongside the locked h1/h2 clamps and 16px body / 14px label) covers every element on both new pages.

Role mapping for the new pages (all drawn from the inherited scale):

| Element | Family | Size | Weight | Line Height |
|---------|--------|------|--------|-------------|
| Page title (`h1`, both pages) | Baloo 2 | `clamp(2rem, 5vw, 2.75rem)` (locked h1 clamp) | 700 | 1.1 |
| Section heading (`h2`: Misja, Wartości, Kadra, category groups) | Baloo 2 | `clamp(1.5rem, 3vw, 1.75rem)` (locked h2 clamp) | 700 | 1.2 |
| Card/sub-heading (`h3`: value-card title, docs group aside) | Baloo 2 | 20px | 700 | 1.2 |

- Narrative fields (D-08) render a **limited markdown subset only** (paragraphs, bold, links) via `marked` — no headings, no inline images, no tables reach the DOM, so the locked type hierarchy stays intact. ### `/dokumenty` page (DOCS-01, DOCS-02) — prerendered, zero-JS

**Route:** `src/routes/dokumenty/+page.svelte` (remove `/dokumenty` from `KNOWN_FUTURE_ROUTES` when it lands). Entries: folder collection `src/lib/content/dokumenty/*.json` read at build (`import.meta.glob`), grouped by `kategoria`. File type + size computed at build via `fs.statSync` + extension (D-14) — never stored/typed by staff. Download files live in `static/dokumenty/` (served verbatim).

**Composition:**
1. **Page header** — `h1` „Dokumenty" on `#FFFFFF`; lead paragraph explaining the page and the download affordance (see Copywriting). Optional single decorative flourish, `aria-hidden`.
2. **Category groups** — each rendered as a `<section aria-labelledby>` with an `h2` category heading, in fixed order: **Rekrutacja**, then **Statut i uchwały**, then **RODO**. Category values come from the fixed `select` (D-15) so no typo categories can appear.
   - **Dormant-category rule (D-13):** a group renders **only when it contains at least one document.** An empty category emits **nothing** — no heading, no empty panel. The „RODO" group stays invisible until its first document lands (Phase 4). Implement as: filter entries by category, skip the whole `<section>` when the filtered array is empty.
3. **Document row** — **reuse the inherited `.doc-row` pattern** from `Recruitment.svelte` (the WCAG-correct one). Each row is a single `<a>` wrapping name + meta so a screen reader announces them together:
   - `.doc-name` — Nunito 15px 700, `brand-blue`, underlined, `overflow-wrap: anywhere`; hover `brand-blue-hover`.
   - `.doc-meta` — Nunito 13px 700 `muted`, **inside the link**, format: `{TYPE} · {size} · wersja z {DD.MM.RRRR}` (e.g. „PDF · 240 KB · wersja z 02.04.2026"). Middot `·` separators (consistent with the homepage docs panel).
   - Row: `min-height: 48px`, `padding: 8px 0`, `border-bottom: 1px solid border-subtle`, flex space-between, gap 12px, wrapping on narrow screens.
   - Optional leading Lucide `file-text`/`file` icon (20px, `aria-hidden`) — decorative; the TYPE in the meta is the accessible signal.
   - Files keep their source format (D-17): DOC/DOCX badges for fillable forms, PDF for uchwały/zarządzenia. The TYPE badge is just the uppercased extension.
   - Optional per-document „Źródło (BIP)" provenance link (D-16): a secondary `brand-blue` underlined external link with the inherited new-tab treatment (`target="_blank" rel="noopener noreferrer"` + visually-hidden „(otwiera się w nowej karcie)" suffix). Only rendered when the field is set.
4. **Group surface:** category sections alternate `#FFFFFF` / `#FBFAF7` bands for visual separation, or sit on a single surface with generous vertical rhythm — planner discretion within the inherited spacing scale.

**EMPTY STATE (required — whole page has zero documents):** if the collection is empty (e.g. before the BIP seed lands), replace the groups with a friendly panel (`#FBFAF7`, `radius-md`, centered, Lucide `folder`/`file-text` `aria-hidden`):
- Heading (Baloo 20px): „Wkrótce udostępnimy dokumenty"
- Body (Nunito 16px `muted`): „Trwa przygotowywanie dokumentów do pobrania. Zajrzyj tutaj wkrótce."

(This mirrors the inherited Aktualności empty-state pattern. In practice the page ships seeded with the BIP set, placeholder-flagged, so the empty state is a safety net.)

## Accessibility Contract (WCAG 2.1 AA — inherited baseline extends to both new routes)

- `<html lang="pl">`; each page has exactly one `<h1>`, correct heading order (no skips: page `h1` → section `h2` → card `h3`).
- Landmarks via shared layout: one `<header>`, `<nav aria-label="Główna nawigacja">`, one `<main id="main">`, one `<footer>`. Category groups on `/dokumenty` are `<section aria-labelledby>`.
- All contrast per the inherited Color pairings; verify text over any band/tint against the actual surface.
- Every document link ≥44px hit area (`min-height: 48px` rows); file type + size announced **inside** the link (no orphaned meta).
- No meaning by color alone (links underlined; TYPE conveyed as text, not just an icon).
- Facility images get informative Polish `alt`; decorative blobs/chips/flourishes are `aria-hidden`. enhanced-img emits width/height (no CLS).
- Each new route has a Playwright + `@axe-core/playwright` spec asserting zero AA violations (`tests/o-nas.spec.ts`, `tests/dokumenty.spec.ts`).
- **CMS-03 caveat (Pitfall 2, must be acknowledged, not silently accepted):** Sveltia's editor chrome (Save/Publish/menus) ships **English + Japanese only** — Polish is not an available UI locale as of 2026-08-13. All config-driven text (labels/hints/help) IS Polish. CMS-03's „...editor UI where supported" wording covers this gap. Requires a `checkpoint:human-verify` client acknowledgement, and the D-21 instrukcja carries annotated Polish screenshots so Polish-only staff can operate the English shell. Re-verify Sveltia's shipped locale list against the pinned bundle at build (fast-moving project — Polish may land).
