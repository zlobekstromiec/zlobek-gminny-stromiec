<objective>
Finish the panel as a product a non-technical person can open twice a month and still know what to do: a real pulpit, an in-panel instrukcja rewritten end to end for the new login and the new screens, and one enforced Polish-only sweep over every rendered admin surface.

Purpose: SC2 says every surface of the panel is Polish with no English chrome anywhere. Until now that has been enforced by a unit suite that runs in no gate. This plan adds a browser-level check that runs inside `npm run test`, which is the AG-3 second enforced check the phase's validation contract requires. It also produces the document the UAT in Plan 11 hands to a real staff member.

Output: the pulpit card grid, the Pomoc screen, a fully rewritten Polish instrukcja, and a Polish-only spec covering every admin route the phase created.
</objective>

<planner_decisions>
- **P-27 (one instrukcja, two entry points):** the Pomoc route renders the same content the printable document holds rather than duplicating it. Keep the document as the single authored source under the docs directory and have the route render it, so the two can never drift and the footer link and the nav item point at the same thing.
- **P-28 (the Polish-only sweep runs in the enforced gate):** `tests/admin-polski.spec.ts` visits every admin route the phase created, extracts the rendered text of the page, and asserts no banned English chrome word appears as a whole word. This is a Playwright spec on purpose: `npm run test` is a gate the project actually runs, while the unit suite is not. The banned list is the same one the unit copy sweep uses, imported rather than retyped, plus the documented exceptions for the native file input's own chrome, which the spec must exclude by scoping to the page's own rendered elements.
</planner_decisions>
