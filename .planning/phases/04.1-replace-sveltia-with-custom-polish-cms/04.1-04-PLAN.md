<planner_decisions>
- **P-11 (RESEARCH Open Question 4, resolved):** `X-GitHub-Api-Version` is pinned to `2022-11-28` on every GitHub request, declared once in `repo.ts`. The current docs render a newer example value, but the pinned 2022 version remains accepted and is the widely deployed choice; the real risk is omitting the header, not choosing between the two. The comment must record the choice and the date it was made so a future reader knows it was deliberate.
- **P-12 (RESEARCH assumption A5, resolved by measurement, not by reasoning):** GitHub's docs list 200, 409 and 422 for update-ref but do not map them to non-fast-forward. Task 3 runs ONE deliberate stale-ref call against the real repository, records the status actually returned in the SUMMARY, and maps that status in the error branch. Whatever it turns out to be, both 409 and 422 stay mapped to the conflict outcome, because the cost of over-mapping is a slightly wrong Polish message and the cost of under-mapping is a lost edit reported as success.
- **P-13 (dry-run seam):** `zapiszAtomowo` short-circuits to a synthetic success when `PANEL_DRY_RUN` is `'1'`. That flag is bound only by `preview:test` and must never become a Cloudflare Pages variable, exactly as the forms dry-run flag never did. Without this seam the Playwright suite would commit to the real repository on every run.
</planner_decisions>

Build the write path as four small modules, each unit-drivable with no network.

`src/lib/server/admin/repo.ts` holds the constants no request may influence: `REPO` (`zlobekstromiec/zlobek-gminny-stromiec`), `GALAZ` (`main`), `WERSJA_API` (the pinned value from P-11, with the comment recording the choice and its date), `AGENT` (a fixed user agent string; GitHub rejects requests without one), and `komunikatCommita(zakres, opis, uchwyt)` which returns the D-04 message shape `tresc(<zakres>): <opis> (edytor: <uchwyt>)`. That function must strip anything outside a conservative character class from the handle and must assert to itself that the result contains no at sign, because a full address in a commit message is a one-line mistake with an irreversible consequence in a PUBLIC repository's history.

`src/lib/server/admin/serializuj.ts` exports one pure function `serializujJson(dane)` returning `JSON.stringify(dane, null, '\t')` with a trailing newline. Its header comment must explain WHY this is equivalent to prettier's output here and why that equivalence needs a test: prettier keeps a JSON object expanded when the source has a newline after the opening brace and collapses it when it does not, and a stringify with an indent always emits that newline, so the two agree; that agreement is a formatter heuristic rather than a configured option. It must also record that the first panel save of `day-plan.json` and `o-nas.json` will expand their currently one-line nested objects, that this is expected, and that adding the content directory to the prettier ignore list is explicitly rejected because it would hide future regressions.

`src/lib/server/admin/github.ts` mints the installation token. Follow RESEARCH Code Example 1: base64url helpers, a PEM to ArrayBuffer converter that accepts only PKCS#8 and whose comment names the PKCS#1 failure it will otherwise produce, a three-claim RS256 JWT with `iat` sixty seconds in the past and `exp` well inside GitHub's ten-minute ceiling and `iss` set to the client ID, and an exchange for an installation access token. Cache the imported `CryptoKey` AND the installation token in module-scoped variables, which in workerd means once per isolate and is the correct lifetime; the comment must record that the import is the expensive half of the operation and the signature itself is cheap. Take the clock as a parameter with a default so the cache expiry is testable. Never log the key, the JWT or the token. Use WebCrypto only; the Node built-in cryptography module does not exist on workerd.

`src/lib/server/admin/commit.ts` exports `zapiszAtomowo(opts)` following RESEARCH Code Example 2 exactly: read the ref, compare the expected head SHA and return the conflict outcome BEFORE writing any blob, read the head commit for its tree SHA, create one blob per file with the encoding chosen by a flag so image and document bytes pass through as base64 without the worker ever decoding them, build one tree with the head tree as its base and with deletions expressed as entries whose sha is null, create one commit whose only parent is the head, and update the ref with force false so GitHub itself rejects a non-fast-forward and closes the race between the check and the write. Return a discriminated result of the shape ok-with-sha or not-ok-with-a-reason of conflict or error, following the result-union pattern in `handle.ts` rather than inline status numbers. Accept `fetchImpl` by injection.

One deliberate detail in the blob step: for a base64 file, assemble the request body by string concatenation around the payload rather than by serializing an object that holds it. A base64 payload contains no character JSON would have to escape, so concatenation is a single copy while serialization walks and re-scans the whole string. Later plans push a photo of a few hundred kilobytes and a document of up to ten megabytes through this exact call, and the difference is the whole reason the encoding happens in the browser in the first place. Write the reason in a comment next to the concatenation so it is not "simplified" back later, and keep the utf-8 branch on ordinary serialization where escaping is genuinely required. Implement the P-13 dry-run short circuit as the very first statement, with a comment naming the flag's harness-only status. The whole function must stay well inside the fifty-subrequest ceiling: it is about eight calls and must never grow a loop that scales with content size.

`tests/admin-serializuj.unit.ts` is PROPERTY based, not example based, because an example-based test would have passed the original Phase 3 defect. Generate content objects across the real field shapes: an empty object, a one-key object, an empty array, an array of one-key objects, a nested array of two-key objects matching the day plan rows including an en dash inside a time range, strings longer than the configured print width, strings containing newline escapes, strings containing Polish diacritics including the stroked l, a boolean, an integer, and a deeply nested combination of all of the above. Also assert the output ends with exactly one newline and that no line begins with two spaces.

`tests/admin-commit.unit.ts` drives `zapiszAtomowo` with an injected fetch that records every request. Assert the full behaviour list in the behavior block above, plus: every request carries the pinned API version header, an authorization header and a user agent; the blob request for a base64 file declares the base64 encoding and passes the payload through unchanged; the commit message is produced by `komunikatCommita` and contains no at sign; a non-ok response from any step yields the error outcome and never a partial success; and a simulated non-fast-forward at update-ref yields the conflict outcome. Do not leave the probe script in the tree.
