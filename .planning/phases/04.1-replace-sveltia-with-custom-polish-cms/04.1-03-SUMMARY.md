**A two-step Polish e-mail-code login that a person completes with JavaScript switched off, whose step 1 response is byte-identical and structurally time-identical whether or not the address is on the allowlist, plus the panel shell every later screen inherits, proven by 18 new Playwright cases including five axe scans and two mutation checks.**

## Accomplishments

- **Slice A is real.** A person types an address, the server puts a six-digit code in that inbox only if the address is on the allowlist, they type the code and land on the pulpit. No GitHub account, no OAuth redirect, no third-party screen anywhere in the flow. Walked end to end in a real browser with scripting disabled.
- **The enumeration oracle is closed on the side a browser can see, and honestly left open on the side it cannot.** Past field validation the step 1 action has exactly ONE return statement, so the two allowlist branches cannot diverge by accident, and a Playwright case compares the rendered card (not the document, whose CSP nonce changes every response) for the two addresses. The timing half is deferred to Plan 10 with a named reference rather than papered over.
- **The attempt cap now has its second enforced check.** 04.1-02-SUMMARY.md recorded that the five-attempt burn was proven only in a unit suite that runs in no automated gate. It is now driven end to end through the real Worker and the real KV binding inside `npm run test`, and a mutation confirms the case is load bearing.
- **The panel wears the locked design system and introduces nothing.** Every colour is an existing `--color-` token, every size is on the inherited scale, the `h1` is the locked h2 clamp reassigned one step down, and the only 3D button treatment in the panel is the single primary action, exactly as Contract 9 reserves it.
- **Five axe states, not one.** A login screen that is clean on load and broken the moment it has something to say is unusable by the people the Deklaracja dostępności exists for, so the clean state, the inline-error state, the alert-panel state, the session-expired state and the authenticated shell are all scanned.
- **`npm run test` grew from 128 to 146 cases** with every pre-existing case unchanged, and `npm run test:unit` stayed at 278.

## Decisions Made

- **The login route is excluded from the shell by a pathname branch, and the file says why.** The plan offered a `+page@.svelte` layout reset as the preferred option. It was rejected on inspection: breaking out of `src/routes/admin/+layout.svelte` also breaks out of `src/routes/admin/+layout.ts`, whose single line `prerender = false` is what keeps the whole panel out of the static build. A prerendered login screen is a worse outcome than a four-line branch, and both branches render exactly one `SkipLink` and exactly one `<main id="main">`, so the landmark contract holds either way.
- **P-08 was implemented exactly as the plan wrote it, and the residual was measured rather than assumed.** The Resend send goes to `platform.ctx.waitUntil`; the KV store is still awaited. Ten requests per branch against `wrangler pages dev`: **4.2 ms mean for the allowlisted address, 3.1 ms for the other**, so about **1.1 ms** of address-correlated delta remains, all of it the awaited KV write. Deferring the store as well would remove it, and was considered and rejected: it would make the moment a code becomes exchangeable unobservable, which the attempt-cap acceptance test would then have to sleep through, trading an enforced check for a theoretical improvement of 1.1 ms against the 200 to 500 ms the deferral already removed. The number is recorded here so Plan 10's live distribution check knows what it is looking for.
- **A store failure on step 1 is swallowed.** Reporting it would answer „that address is on the list" to anyone able to provoke a KV error. The editor still has a recoverable path: a code that was never stored reads as „Kod stracił ważność" on exchange, and that panel's instruction is „Wyślij kod ponownie", which is the correct instruction for this state too.
- **An address removed from the allowlist between issue and exchange is told the code expired, not that it is unwelcome.** „That address is not allowed" is the one sentence D-02 forbids this screen to say, and the resend instruction is harmless for somebody who genuinely is no longer an editor.
- **A missing `ADMIN_SESSION_SECRET` reuses the „Nie udało się wysłać kodu" family panel** rather than gaining a new copy export. Adding an export would have turned `tests/admin-copy.unit.ts` red on its export-count case, and that panel already says „try again shortly, and if it keeps happening contact whoever gave you access", which is exactly right for an unconfigured deployment.
- **The publish-delay panel sits inside `<main>`, as its last child.** The contract lists it between `<main>` and `<footer>`; rendering it as a sibling would orphan a paragraph outside every landmark. Its reading position and its visual position are unchanged.
- **White is written as `var(--color-surface)`.** The token's value is that same white, the rendered colour is identical to the raw hex `Cta.svelte` writes, and the panel's no-raw-hex gate stays literal-clean.
- **`maxlength="6"` is a literal in `PoleKodu.svelte`, not `DLUGOSC_KODU`.** That constant lives in `$lib/server/`, which SvelteKit refuses to import into a client component, and correctly so.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The panel's own hourly ceiling made the acceptance suite unrunnable**

- **Found during:** Task 3, designing the attempt-cap case
- **Issue:** `podLimitemKodu` passes its own hard constants, 5 codes per client per hour and 20 per day, and unlike the two public endpoints it had no override. The Playwright suite shares one client address and needs four code requests per run, and the hour bucket persists in the local KV between runs, so the second run of the day would have been refused by the limiter and the suite would have reported a security failure that was really a harness limit.
- **Fix:** `podLimitemKodu` gained two optional TRAILING parameters with defaults, the same append rule that added `teraz` in 04-08 and `prefiksDobowy` in 04.1-02, so no existing call site changed. The login route passes the parsed `RATE_LIMIT_MAX` for both, exactly as `src/routes/api/kontakt/+server.ts` already does, and that variable is unset in production so a real deployment gets the constants.
- **Files modified:** `src/lib/server/admin/kod.ts` (outside the plan's `files_modified` list)
- **Verification:** `npm run test:unit` 278/278 unchanged; the attempt-cap case passes across repeated runs.
- **Committed in:** `03496bc`

**2. [Rule 2 - Missing critical functionality] FormField needed a fourth optional prop for the focus contract**

- **Found during:** Task 2
- **Issue:** P-10 lists three additions. The UI-SPEC focus-management contract requires the address field to be focused when it carries an inline error and the code field to be focused when step 2 renders, on a screen that must work with JavaScript disabled. An effect never runs there, so the `autofocus` attribute is the only mechanism, and `FormField` had no way to emit it.
- **Fix:** added optional `autofokus`, defaulting to false so no existing call site emits the attribute (Svelte omits boolean attributes that are false), with a `svelte-ignore a11y_autofocus` and a comment stating it is only ever set on the single control a page exists to collect. `PoleKodu` and `PanelKomunikat` carry the same prop for the same reason. At most one element per rendered document receives it, and a panel outranks a field, because a panel explains why the field is there.
- **Files modified:** `src/lib/components/FormField.svelte`, and the new components
- **Verification:** `npm run check` 0 errors 0 warnings; the five axe scans are clean; the tab-order case passes.
- **Committed in:** `df484c9`

**3. [Rule 1 - Bug] The byte-parity and attempt-cap cases raced on a single KV entry**

- **Found during:** Task 3, first run
- **Issue:** there is exactly one pending-code entry per address and exactly one allowlisted address in the harness, and `fullyParallel` is on. The very first wrong code came back with „Za dużo prób", because two cases had been interleaving on one attempt counter. Left alone this would have been far worse than a red run: the cap could equally have appeared to PASS while counting another case's attempts.
- **Fix:** the new describe is `test.describe.serial`, with the reason and the observed symptom written above it, plus an explicit instruction that the right fix if it ever becomes a bottleneck is a second allowlisted address in the harness bindings and not weaker isolation.
- **Files modified:** `tests/admin-auth.spec.ts`
- **Verification:** 36/36 across repeated runs.
- **Committed in:** `55a1a64`

## Acceptance Criteria Not Met As Written

- **Task 1: „`grep -nE '#[0-9A-Fa-f]{3,8}' src/lib/components/admin/*.svelte src/routes/admin/+layout.svelte` returns nothing".** It returns one line: `{#each pozycje as pozycja (pozycja.href)}`. The pattern matches `#eac` inside the `{#each` block opener, because `e`, `a` and `c` are hex digits. No rewrite can remove it, since a keyed each block is the correct Svelte idiom for a list. The criterion was run in the form it actually means, a hex COLOUR literal (`#` followed by exactly 3, 4, 6 or 8 hex digits at a word boundary), which returns nothing. There is no colour literal in any new component or route.
- **Task 3: „For each scanned page also assert ... that the nav exposes its Polish accessible name".** The login screen deliberately has NO nav (Component Contract 2: no shell, no nav, no session). Asserting one there would contradict the contract. The nav's accessible name and its seven sections are asserted on the shell, and the login screen instead carries a case asserting the nav, the header bar and „Wyloguj" are ABSENT, which is the property that actually matters there.
