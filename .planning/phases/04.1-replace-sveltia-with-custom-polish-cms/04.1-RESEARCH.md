## User Constraints (from CONTEXT.md)

### Locked Decisions

**Logowanie: e-mail one-time code**

- **D-01: Self-built Polish e-mail code login, NOT Cloudflare Access.** Staff enters an e-mail address, receives a numeric code by e-mail, and exchanges it for a signed session cookie. Built on infrastructure that already exists and is already unit-tested: the Resend sender on `send.zlobekstromiec.pl`, the `FORMS_KV` namespace, the salted-hash rate limiter in `src/lib/server/forms/ratelimit.ts`, and the sanitizers in `sanitize.ts`.
  - Cloudflare Access one-time PIN was evaluated and rejected on the phase's own success criterion 2. Access is free to 50 users and would remove the code-generation and session work, but the PIN screen is Cloudflare's page, its full Polish localisation is not guaranteed, and replacing an English third-party login with a different English third-party login defeats the reason this phase exists. Secondary reasons: the configuration would live in a dashboard rather than the repo (worse handover), and local dev plus Pages previews would need a bypass path.
  - Cost: free. Login codes draw on the same Resend free tier as the two forms (100/day, 3000/month), which a handful of daily logins does not threaten.
- **D-02: The allowlist of permitted e-mail addresses is ONE encrypted Cloudflare Pages secret** (for example `ADMIN_EMAILS`, comma separated). Nothing personal is committed. **This is a hard constraint, not a preference: `zlobekstromiec/zlobek-gminny-stromiec` is a PUBLIC repository**, so staff e-mail addresses in git would be both a harvesting target and personal data published by a public body.
  - Known Phase 4 gotcha that applies here: a Pages secret only reaches deployments created AFTER it is set, so adding an editor is "set the secret, then trigger a rebuild".
  - An address not on the list must be treated identically to one that is, with no signal that it is unknown, so the panel cannot be used to enumerate who works at the żłobek.
- **D-03: Session lasts 30 days and renews on use,** so a person who edits weekly effectively stops seeing the login screen on that device. A visible „Wyloguj" control is mandatory for shared computers.
- **D-04: One machine identity authors every commit; the editor is named by a short non-personal handle in the commit message,** for example `tresc(aktualnosci): dodano wpis "Dzien otwarty" (edytor: anna.k)`. A full e-mail address must never reach a commit author field or message, for the same public-repo reason as D-02. This supersedes 02 D-19 (per-editor GitHub accounts), which is dead because staff no longer have GitHub accounts.
- **D-05: The allowlist starts with `devzlobekstromiec@gmail.com` plus any working private address the staff already use, and swaps to `@ugstromiec.pl` addresses later.** Rationale: `zlobek@ugstromiec.pl` does not exist yet (pending Gmina approval), and gating this phase on Gmina IT would repeat the FORM-01 pattern of shipping an unverifiable requirement. Because the list is a secret (D-02), the swap costs one secret update plus a rebuild and no code change.

**Write path: how edits persist**

- **D-06: Content stays in git. The panel commits to this repository through the GitHub API.** A runtime store (KV, D1, R2) was rejected: it would violate ROADMAP SC5, force a rewrite of every reader built in Phases 2-3, end the prerendered zero-JS model that is a foundational project property, and remove the build-time file access that `enhanced-img` needs. This closes the open write-path research question recorded in 05 D-11.
- **D-07: One atomic commit per save, using the GitHub Git Data API** (create blobs, build a tree, create a commit, update the ref), NOT the simple Contents API. Rationale: an aktualności entry is two files, the JSON and its cover image. One commit per file would mean two commits, two Pages builds, roughly four minutes, and a window where the post is live without its photo.
- **D-08: The panel authenticates to GitHub as a GitHub App owned by the `zlobekstromiec` Org and installed on this one repository,** minting short-lived installation tokens from a private key held as a Pages secret. Chosen over a fine-grained PAT for durability at handover: an App has no expiry date to lapse silently and survives the `devzlobekstromiec` user account being removed, whereas an expiring PAT is a time bomb in a project whose whole point is that no developer is around afterwards. It also gives the bot author identity that D-04 assumes. Permissions must be scoped to Contents:write on this repository and nothing more.
- **D-09: The panel emits prettier-shaped JSON (tabs, trailing newline) so content files stay inside the normal quality gate.** This closes the Phase 3 UAT blocker recorded in STATE.md, where CMS-written 2-space JSON blocked ALL local commits through the prettier pre-commit hook. A unit test asserting panel output is prettier-clean is required, because this exact defect has already bitten the project once. `.prettierignore` is deliberately NOT used: it would hide future regressions in panel output.
- **D-10: A save that would overwrite a change made since the entry was opened is REFUSED, with a Polish message telling the editor the entry changed and to reload.** The Git Data API needs the current SHA anyway, so conflict detection is effectively free, and the failure it prevents (silently destroying a colleague's edit) is the worst kind.
- **D-11: One „Zapisz" per page, not per section.** An editing session on o-nas (misja, wartości, plan dnia, kadra, facility text) produces one commit and one build regardless of how many fields were touched. Rationale: **Cloudflare Pages allows 500 builds per month on the free plan** and every save is a build; developer commits count against the same ceiling.

**Zdjęcia: upload and cover images**

- **D-12: The browser resizes and re-encodes the photo BEFORE anything is sent.** A 5 MB phone photo becomes roughly 200-400 KB. Rationale is threefold: the free Workers plan allows about 10 ms of CPU per request and base64-encoding a multi-megabyte file is real CPU rather than I/O wait; git history keeps every version of every image forever; and uploads must work on a weak connection at the żłobek. A useful side effect is that the browser's own decoder handles iPhone HEIC on iOS. The editor sees a preview of exactly what will be published.
- **D-13: The panel crops to the card's fixed aspect ratio automatically, centred, and shows the result before saving.** A drag-to-position cropper was considered and deferred (see Deferred Ideas): it would produce better results for portrait photos but costs a real interactive component that must be keyboard operable and axe-clean.
- **D-14: The panel generates the filename; staff never type one.** An ASCII slug derived from the entry (for example `2026-08-20-dzien-otwarty.jpg`), stripping Polish diacritics the same way the Sveltia slug rules had to. **Constraint carried from T-03-03: the basename lookup IS the path-traversal defence**, so generated names must be guaranteed to resolve inside `src/lib/assets/uploads/` and an unknown basename must continue to yield the tint fallback rather than a filesystem read.
- **D-15: Alt text is REQUIRED before an image can be saved,** with a short Polish hint explaining what to write (what is in the photo, not „zdjęcie"). The site is a public body under WCAG 2.1 AA and Phase 6 must certify that baseline in a legal document, so accessibility is made structurally impossible to forget rather than left to staff discipline. The Phase 3 reader continues to treat `obraz_alt` as optional and degrade safely, so this is a panel-level rule that can never break the build.

**Panel: scope and behaviour**

- **D-16: Scope is everything editable today PLUS one recruitment open/closed switch.** That is o-nas, plan dnia, dokumenty, aktualności with covers (ROADMAP SC3), and `recruitmentOpen`, currently a boolean a developer flips by hand in `src/lib/content/site.ts`. One boolean written to a file the panel already handles, and it removes the last thing the żłobek genuinely needs a developer for during the year. Full "Ustawienia strony" editing (contact details, keyFacts) stays out (see Deferred Ideas).
- **D-17: Server-rendered admin routes using SvelteKit form actions, with hydrated islands ONLY where they earn it** (image crop and upload). Matches the pattern the whole site already follows, degrades without JavaScript, inherits the accessibility approach that is already AA proven, and keeps each screen independently testable. A client-side SPA was rejected as a second architecture in an otherwise prerendered, near zero-JS codebase. The `/admin` routes must be excluded from prerender and carry `noindex`.
- **D-18: Publish feedback is an honest Polish message, with no new infrastructure.** After a save the panel states the change is saved and will appear on the site within about two minutes, and links to the affected page. This keeps the promise 02 D-12 already made in the instrukcja. Polling the Cloudflare API for real build status was considered and deferred: it would be genuinely reassuring but costs another API token as a Pages secret, polling code and a failure mode.
- **D-19: The panel reuses the locked design system's tokens (colours, fonts, radii) in a denser, calmer layout suited to forms.** It should feel like the same product a staff member already knows, and it inherits the accessible-tier palette and focus styles that are already AA proven. The roadmap marks this phase UI hint: yes, so `/gsd-ui-phase 4.1` should pin the details before planning.

**Migracja i wymagania**

## Summary

This phase is unusual in that almost nothing needs to be *chosen*. CONTEXT.md locks 21 decisions and `04.1-UI-SPEC.md` locks the entire visual and copy contract down to the wording of the conflict panel. What remained genuinely unknown was the *how* of four platform mechanisms on workerd, and this research resolves all four with verified, empirically-tested findings rather than recalled API shapes.

The single highest-value finding is a trap that would have burned a plan: **the private key GitHub hands you for a GitHub App is PKCS#1, and Cloudflare's WebCrypto flatly refuses it.** GitHub's own docs confirm the format ("the PEM file you download will be in `PKCS#1 RSAPrivateKey` format"), and a direct WebCrypto test in this session confirms `importKey('pkcs8', ...)` throws `DOMException: Invalid keyData` on that key and succeeds only after an `openssl pkcs8 -topk8` conversion. This is a one-time operator step that must appear in the plan as an explicit, ordered task, because it happens outside the repo and is invisible to every code review.

The second finding reshapes the write path's cost model. A CPU benchmark run in this session shows that base64-encoding a 400 KB image costs about 6.6 ms, which alone would nearly exhaust the Cloudflare free plan's 10 ms per-request CPU budget, while RSA-2048 signing costs only 0.33 ms and HMAC-SHA256 about 0.01 ms. This both validates D-12 and produces a concrete architectural rule: because the UI-SPEC already has the island write the processed photo into a hidden field **as a data URL**, the server must strip the `data:image/jpeg;base64,` prefix and forward the base64 payload *verbatim* to the GitHub blob API. It must never decode and re-encode. That single rule keeps the entire save path comfortably inside the free-tier budget.

Third, D-09 turned out to have a hidden dependency worth stating precisely. There is no `.prettierrc` and no `.editorconfig` in this repo. The config is `prettier.config.js` (tracked, `useTabs: true`, `printWidth: 100`). Empirical probing confirms that `JSON.stringify(obj, null, '\t') + '\n'` is byte-identical to prettier's output for this repo's content shapes, including short objects and nested arrays, because prettier preserves an object as expanded when the original has a newline after the opening brace. That is the concrete serialization rule the panel must implement, and it needs a unit test because it depends on a prettier heuristic, not on a configured option.

Finally, the teardown is cleaner than feared. Sveltia has **zero coupling to `src/` or `tests/`**: `git grep @sveltia -- src tests` returns nothing, and no test references `/admin`. Removal is a pure deletion of a bundle, a script, a config block, an eslint ignore, a prettierignore entry and one vendored Worker directory.

**Primary recommendation:** Build the panel with **zero new npm dependencies**. Every mechanism this phase needs (RS256 JWT, HMAC session cookies, base64, image decode/resize/encode, HTTP to GitHub and Resend) is a platform API already present in workerd and the browser. Adding `jose`, `@octokit/*` or an image library would add supply-chain surface, bundle weight and a workerd-compatibility risk for capability the runtime already provides.

|------------|-------------|----------------|-----------|
| Image decode, centre-crop, resize, JPEG re-encode | Browser / Client | - | D-12: the free Workers plan gives ~10 ms CPU; decoding a 5 MB photo is not affordable server-side. Browser also gets HEIC decoding for free. |

| Content validation (all field rules, alt-text requirement) | Frontend Server (form action) | - | D-17 requires it to work without JavaScript, so the server is the only tier that can hold the rule. |
| JSON serialization to prettier shape | Frontend Server | - | Deterministic pure function; belongs next to the writer and is unit-testable in isolation. |
| GitHub App JWT mint + installation token | Frontend Server | GitHub API (external) | Private key is a Pages secret and may never reach a browser. |
| Atomic multi-file commit | Frontend Server | GitHub API (external) | Git is the store (D-06). |
| Conflict detection (stale SHA) | Frontend Server | GitHub API (external) | The head SHA must be read and compared server-side; a client-supplied SHA is an input, not a source of truth. |
| Content rendering to visitors | CDN / Static (prerendered) | - | Unchanged. `/admin` is the only non-prerendered addition beyond the two existing form endpoints. |
| Publish (build + deploy) | CDN / Static (Cloudflare Pages git integration) | - | D-18: the panel does not orchestrate the build, it only tells the truth about the delay. |

**Tier trap to avoid:** the alt-text requirement (D-15) is tempting to enforce in the island because that is where the image is. It must be enforced on the **server**, in the form action, or it evaporates the moment JavaScript is unavailable. The island may additionally warn early, but the server holds the rule.

`aktualnosci.ts` is the strictest consumer and is the de facto output contract. It types the entry `unknown`, guards every field, constructs the result key by key (never spreads), and **skips a malformed entry with a warning rather than throwing**. Practical consequences for the panel:

- `tytul` and `tresc` must be non-empty strings or the post silently disappears from the site. The panel must make both required.
- `data` must match `^\d{4}-\d{2}-\d{2}$` with month 1-12 and day 1-31. The UI-SPEC's three-select date control must emit exactly this, zero-padded.
- The slug is the **on-disk filename**, never re-derived from fields. Renaming a title must not rename the file (D-07/D-08 of Phase 3). The panel must therefore treat the filename as immutable after creation.
- `obraz` is matched by **basename** (`obraz.split('/').pop()`), which is the path-traversal defence (T-03-03, D-14).

### The basename-resolution idiom (duplicated verbatim in three files)

`src/lib/components/NewsCard.svelte`, `src/routes/aktualnosci/[slug]/+page.svelte` and `src/routes/o-nas/+page.svelte` each contain:

```ts
const uploads = import.meta.glob<Picture>('$lib/assets/uploads/*.{jpg,jpeg,png,webp}', {
	query: { enhanced: true }, eager: true, import: 'default'
});
const byName: Record<string, Picture> = {};
for (const [path, mod] of Object.entries(uploads)) {
	const base = path.split('/').pop();
	if (base) byName[base] = mod;
}
const cover = $derived(obraz ? byName[obraz.split('/').pop() ?? obraz] : undefined);
```

An unknown basename yields `undefined`, which degrades to the tint fallback. This is a **lookup in a build-time map, not a filesystem read**, which is exactly why it is traversal-safe. Any panel-generated filename must land in that glob (extension in `jpg|jpeg|png|webp`, note **avif is excluded**) or the image will silently not render. Extracting this idiom into a shared helper is explicitly in Claude's discretion.

### Current `_headers` and CSP split

`_headers` sets the global security baseline on `/*` and a **path-scoped CSP block on `/admin/*`** (lines 17-24) naming `https://api.github.com`, `https://sveltia-cms-auth.devzlobekstromiec.workers.dev`, `https://github.com` and the GitHub avatar hosts. Deliberately, **no CSP is set on `/*`** because SvelteKit's hydration bootstrap is an inline script whose hash changes each build; the site CSP lives in `svelte.config.js` `kit.csp` (`mode: 'auto'`). Current `kit.csp` directives include `'img-src': ['self','data:']`, `'form-action': ['self']`, `'connect-src': ['self','https://challenges.cloudflare.com']`.

Consequence for this phase: once `static/admin/` is deleted, `/admin` becomes SvelteKit routes and is automatically covered by `kit.csp`. The `/admin/*` block in `_headers` must be **deleted, not edited** (D-20). Note `img-src` already allows `data:`, so a data-URL preview needs no CSP change; a `URL.createObjectURL()` preview would require adding `blob:`. Prefer the data URL, which the UI-SPEC already specifies.

### Test setup, scripts and gates

- **Playwright** (`playwright.config.ts`): `testDir: 'tests'`, `baseURL: http://localhost:4173`, `webServer: 'npm run build && npm run preview:test'`. Default `testMatch` picks up `*.spec.ts` only, which is why `*.unit.ts` is invisible to it.
- **`@axe-core/playwright` 4.13** is installed; the axe block is inlined per spec file.
- **Unit tests**: `node --test tests/*.unit.ts`, **180 tests currently passing**, run in 140 ms. Node type-stripping runs these `.ts` files directly.
- **npm scripts**: `check` = `wrangler types --check && svelte-kit sync && svelte-check`; `lint` = `prettier --check . && eslint .`; `test` = `playwright test`; `test:unit` = `node --test tests/*.unit.ts`; `build` = `wrangler types --check && vite build`.
- **pre-commit** (`.pre-commit-config.yaml`) runs exactly two local hooks: `npm run check` and `npm run lint`. **`test:unit` is in no gate at all** and `npm run test` is Playwright-only. This is the AG-3 gap the CONTEXT.md deferred list flags, and it now applies to the most security-sensitive code in the project.

### Prettier configuration (settles D-09)

There is **no `.prettierrc` and no `.editorconfig`**. The config is `prettier.config.js` (tracked, not ignored):

```js
{ useTabs: true, singleQuote: true, trailingComma: 'none', printWidth: 100,
  plugins: ['prettier-plugin-svelte', 'prettier-plugin-tailwindcss'], ... }
```

`.prettierignore` excludes `/static/`, `/.planning/`, `/.claude/`, `/sveltia-cms-auth/`, lockfiles and build output. **`src/lib/content/` is NOT ignored**, which is why CMS-written 2-space JSON blocked all commits in Phase 3 UAT.

### Environment and secrets convention

- `wrangler.jsonc` is the source of truth for bindings. `FORMS_KV` id `55f55448fe1345e28a79da5a3e9e9ca9`. `compatibility_date: 2026-08-12`, `compatibility_flags: ["nodejs_als"]`.
- **Never create a root `.dev.vars`.** `wrangler types` bakes its keys into the committed `worker-configuration.d.ts` as required members, which Pages CI cannot reproduce, so `wrangler types --check` fails every deploy. Local and Playwright runs pass secrets as `--binding` flags via `npm run preview:test`.
- New secrets are declared **optional** in `src/app.d.ts` `interface Env`, read from `event.platform.env.*`, never `import.meta.env`.
- The scoped `CLOUDFLARE_API_TOKEN` in `.envrc` has **no Workers KV permission**, so `wrangler kv namespace create` fails with `Authentication error [code: 10000]`. If the planner wants a separate admin KV namespace it must be created in the dashboard or the token widened. Reusing `FORMS_KV` with a distinct key prefix avoids this entirely.

## Standard Stack

### Core

**No new runtime or dev dependencies are required by this phase.** Every capability is a platform API.

| Capability | Use | Available where | Why standard |
|------------|-----|-----------------|--------------|
| RS256 JWT signing | `crypto.subtle.importKey('pkcs8', ...)` + `crypto.subtle.sign({name:'RSASSA-PKCS1-v1_5', hash:'SHA-256'}, ...)` | workerd `[CITED: developers.cloudflare.com/workers/runtime-apis/web-crypto]` | Cloudflare docs list RSASSA PKCS1 v1.5 as supported for both `sign()/verify()` and `importKey()`. A JWT is three base64url segments; a library buys nothing and costs bundle plus risk. |
| HMAC session cookie | `crypto.subtle.importKey('raw', ..., {name:'HMAC',hash:'SHA-256'})` + `sign`/`verify` | workerd `[CITED: same]` | Measured at ~0.01 ms per signature. |
| Cookie read/write | SvelteKit `event.cookies` | SvelteKit 2 | Handles `Set-Cookie` correctly including on redirects, which manual header writing does not. |
| HTTP to GitHub / Resend | global `fetch` | workerd | The project already calls Resend with plain `fetch` and no SDK (`mailer.ts`). Be consistent. |

### Pattern 1: Mint a GitHub App installation token on workerd

**What:** Sign a 3-claim RS256 JWT with WebCrypto, exchange it for a 1-hour installation token.
**When to use:** Once per save, or once per isolate with caching.

The **imported CryptoKey must be cached at module scope**. Benchmarking in this session put `importKey` at 3.7 ms cold versus 0.33 ms for the signature itself; against a 10 ms budget, re-importing per request is the expensive half. Module scope in workerd means "once per isolate", which is the correct lifetime.

### Pattern 2: Atomic multi-file commit via the Git Data API

**What:** blob -> tree -> commit -> update-ref, exactly as D-07 specifies.
**When to use:** Every save.

`base_tree` is what makes this cheap: you pass the head commit's tree SHA and only the entries you are changing, and GitHub merges them. Entries in `tree` override matching paths from `base_tree` `[CITED: docs.github.com/en/rest/git/trees]`. Setting an entry's `sha` to `null` deletes that path, which is how the delete flow works without a separate mechanism. Note `tree.sha` and `content` are mutually exclusive and using both returns an error.

Subrequest budget: the full save is about 8 outbound calls (token, get-ref, get-commit, 2 blobs, tree, commit, update-ref) against a free-plan ceiling of **50 subrequests per request** `[CITED: developers.cloudflare.com/workers/platform/limits]`. Comfortable, but the ceiling is real and rules out any per-field or per-file loop that scales with content size.

### Pattern 3: Stateless session that is still revocable

**What:** An HMAC-signed cookie carrying `{ email, exp }`, verified in `handle()`, **plus a re-check of that e-mail against `ADMIN_EMAILS` on every request**.
**Why it matters:** A purely stateless cookie cannot be revoked. If an editor leaves and D-02's secret is updated, a plain signed cookie keeps working for up to 30 days. Re-reading `ADMIN_EMAILS` from `platform.env` costs nothing (it is already in memory) and the HMAC verify is ~0.01 ms, so this buys instant revocation for free and with no KV read on the hot path.

Renew-on-use (D-03) is then simply: if the cookie verifies and is older than some fraction of its life, re-issue it with a fresh `exp` in the same response.

Cookie flags: `httpOnly: true, secure: true, sameSite: 'lax', path: '/admin', maxAge: 30*24*3600`. `sameSite: 'lax'` (not `strict`) because the login flow redirects; `path: '/admin'` keeps the cookie off every prerendered page request.

### Pattern 4: Enumeration-safe OTP request (D-02)

**What:** The step-1 action must be byte-identical and **time-identical** for allowlisted and non-allowlisted addresses.

Byte-identical is straightforward and the UI-SPEC already specifies the copy. **Time-identical is the hard half and is a genuine open question** (see §Open Questions 1): the allowlisted path awaits a Resend call of roughly 200-500 ms, the non-allowlisted path does not. That difference is trivially observable and is a real enumeration oracle against a public body's staff list.

Options, in the planner's court:
1. Hand the send to `event.platform.ctx.waitUntil()` so both paths return immediately. **Note:** `waitUntil` is banned by a Phase 4 plan acceptance gate, but that gate is **path-scoped to `src/lib/server/forms/` and `src/routes/api/`** (verified: the gate is `grep -c 'waitUntil' src/lib/server/forms/ src/routes/api/ -r`), and it exists because a *parent's enrollment* must not be reported as sent when it failed. A login code has a user-driven retry ("Wyślij kod ponownie") and no silent-loss consequence, so the rationale does not transfer. This must be an explicit, documented decision, not an accident.
2. Await the send but also await an equivalent artificial delay on the non-allowlisted path. Simple, wastes wall-clock, and the delay must be tuned to a number that will drift.
3. Accept and document the timing difference. Cheapest, but it concedes SC1's spirit.

**Recommendation: option 1**, with a comment naming the Phase 4 ban and why this module is outside it.

### Anti-Patterns to Avoid

- **Decoding the uploaded image server-side.** Measured at ~6.6 ms just to base64 a 400 KB buffer. Forward the base64 the island already produced.
- **Using the Contents API (`PUT /repos/.../contents/{path}`) for convenience.** It is one file per commit, so an aktualność costs two commits, two builds and a window where the post is live without its photo. D-07 forbids it.
- **Enforcing alt-text only in the island.** Evaporates without JavaScript.
- **`JSON.stringify(obj, null, 2)`.** This is the exact defect that blocked every commit in Phase 3 UAT.
- **Re-deriving the slug from the title on edit.** The filename is authoritative; renaming breaks the URL and orphans the post.
- **Adding `src/lib/content/` to `.prettierignore`.** D-09 explicitly rejects this: it would hide future regressions in panel output.
- **A KV read on every admin page view to validate the session.** Unnecessary given Pattern 3, and it adds a failure mode to the auth gate.
- **Reading secrets from `import.meta.env`.** Project-wide ban; use `event.platform.env.*`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| E-mail address validation for the login field | A new regex | `bezpiecznyEmail()` from `sanitize.ts` | Already rejects header-injection characters, caps at 254, and is unit-covered. A second regex will drift from the first. |
| Rate limiting the code endpoint | A fresh counter | `podLimitem()` from `ratelimit.ts` | Encodes three hard-won lessons: the window lives in the key (a KV write overwrites expiration), it refuses to hash without a salt, and it fails open deliberately. |
| JSON pretty-printing | A custom formatter or a prettier API call at runtime | `JSON.stringify(obj, null, '\t') + '\n'` (verified equivalent) | Running prettier in a Worker is not possible; a custom formatter would drift from the gate. |
| EXIF orientation correction | Reading EXIF bytes, rotating a canvas | `createImageBitmap(file, { imageOrientation: 'from-image' })` | The browser already applies EXIF orientation by default. Manual rotation double-rotates on modern browsers. |
| HEIC decoding | A HEIC decoder library | The browser's own decoder + iOS picker conversion | iOS typically hands a JPEG to `<input type="file">` from the photo library; where it does not, Safari decodes HEIC natively. A WASM decoder would be a megabyte of bundle for a case the platform covers. |
| JWT construction / base64url | A JWT library | ~25 lines over `crypto.subtle` | Fixed 3-claim payload; the library is all generality you do not need. |
| Cookie serialization | Manual `Set-Cookie` strings | `event.cookies.set()` | SvelteKit attaches cookies correctly to redirect responses, which manual header writing gets wrong. |
| Constant-time string compare for the OTP | `a === b` | Compare **hashes** of the code, or a length-independent XOR loop | A plain `===` on the code leaks length and prefix timing. Comparing SHA-256 digests sidesteps it entirely. |
| Polish diacritic stripping | An ad-hoc character map | `String.prototype.normalize('NFD')` + strip combining marks, then a explicit `ł -> l` pass | `ł` has no decomposition and is the one character an NFD-only approach silently drops. This is the classic Polish slug bug. |

**Key insight:** this phase's genuine complexity is not in any single mechanism, it is in the *couplings*: the serialization must match a formatter's heuristic, the filename must land in a Vite glob, the image encoding must survive a CPU budget, and the login must not leak an oracle. Each is cheap to implement and expensive to get subtly wrong, which is why the pure modules need unit tests more than the plumbing does.

## Common Pitfalls

### Pitfall 1: The GitHub private key will not import (highest severity)

**What goes wrong:** `crypto.subtle.importKey('pkcs8', ...)` throws `DOMException: Invalid keyData` on the `.pem` downloaded from GitHub.
**Why it happens:** GitHub issues **PKCS#1** (`-----BEGIN RSA PRIVATE KEY-----`). GitHub's docs state it plainly: "If you're using a library that requires a specific file format, the PEM file you download will be in `PKCS#1 RSAPrivateKey` format." `[CITED: docs.github.com/.../managing-private-keys-for-github-apps]` WebCrypto's `pkcs8` format means **PKCS#8** (`-----BEGIN PRIVATE KEY-----`) and there is no PKCS#1 import path.
**How to avoid:** Convert once, outside the repo, and store the PKCS#8 result as the Pages secret:
```bash
openssl pkcs8 -topk8 -inform PEM -outform PEM -nocrypt \
  -in downloaded-from-github.pem -out github-app-key-pkcs8.pem
head -1 github-app-key-pkcs8.pem   # must read: -----BEGIN PRIVATE KEY-----
```
**Warning signs:** `Invalid keyData` at the first save attempt, on the deployed site only if the local dev used a differently-generated key. **This is an operator step invisible to code review, so it must be its own ordered task in the plan with the `head -1` assertion as its acceptance check.** `[VERIFIED: WebCrypto import tested both formats in this session]`

### Pitfall 2: `JSON.stringify(obj, null, 2)` blocks every commit in the repo

**What goes wrong:** Content written by the panel fails `prettier --check .`, so the pre-commit hook blocks all local commits until someone runs `prettier --write`.
**Why it happens:** `prettier.config.js` sets `useTabs: true`, and `src/lib/content/` is not in `.prettierignore`.
**How to avoid:** `JSON.stringify(obj, null, '\t') + '\n'`, asserted by a unit test.
**Warning signs:** This has already happened once (STATE.md, `2026-08-14-test.json`). `[VERIFIED: reproduced and the fix confirmed prettier-clean in this session]`

### Pitfall 3: `/admin` gets prerendered, or the build fails on form actions

**What goes wrong:** `src/routes/+layout.ts` sets `prerender = true` and every route inherits it. A prerendered page cannot have form actions, and a prerendered admin panel is not an admin panel.
**How to avoid:** `src/routes/admin/+layout.ts` with `export const prerender = false;`. Page options in a `+layout.js` act as defaults for all child pages `[CITED: svelte.dev/docs/kit/routing]`, so one file covers the subtree.
**Warning signs:** A build-time error about prerendering a page with actions, or `/admin/index.html` appearing in `.svelte-kit/cloudflare`. Add a build-output assertion to the plan's acceptance gate.

### Pitfall 4: The generated filename does not match the Vite glob

**What goes wrong:** The image commits successfully, the build succeeds, and the cover silently renders as the tint fallback.
**Why it happens:** The three consumers glob `*.{jpg,jpeg,png,webp}` and key by basename. A `.JPG` uppercase extension, an `.avif`, or a filename with a diacritic that the slug pass missed will not be in `byName`.
**How to avoid:** Force the extension to lowercase `.jpg` (the island re-encodes to JPEG anyway, so the extension is fully determined), and unit-test the slug function against Polish inputs including `ł`, `ą`, `ż`, `ź`, `ó`, `ś`, `ć`, `ń`, `ę`.
**Warning signs:** A post renders with the fallback tint despite an `obraz` value being present.

### Pitfall 5: The login is an enumeration oracle by timing

Covered in Pattern 4 and Open Question 1. The byte-identical response is necessary but not sufficient.

### Pitfall 6: The site-wide daily rate limit is shared with the public forms

**What goes wrong:** A burst of login attempts consumes `rl:doba:<date>`, and parents' enrollment submissions start being refused, or vice versa.
**Why it happens:** `podLimitem()` uses a per-form hourly key but a **single site-wide daily key** (`PREFIKS_DOBOWY = 'rl:doba'`) whose default ceiling of 40 exists to protect the Resend budget.
**How to avoid:** Decide deliberately. Passing a distinct, higher `limitDobowy` from the admin caller is the smallest change; a separate daily prefix is cleaner but touches a module with a careful threat model.
**Warning signs:** Parents reporting "Za dużo prób wysyłki" on a day when nobody flooded the contact form.

### Pitfall 7: A Pages secret does not reach the running deployment

**What goes wrong:** `ADMIN_EMAILS` or the private key reads as `undefined` in production and every login fails.
**Why it happens:** A Pages secret only reaches deployments created **after** it is set (recorded in Phase 4 and in CLAUDE.md).
**How to avoid:** Set all admin secrets, then trigger a rebuild, then test. Bake this ordering into the deployment plan. The same rule makes "adding an editor" a two-step operation that the instrukcja must state.
**Warning signs:** Works locally with `--binding` flags, fails on the live site.

### Pitfall 8: English chrome sneaks in through the native file input

**What goes wrong:** SC2 says no English chrome anywhere. The browse button inside `<input type="file">` and the OS file picker render in the **browser and OS locale**, not the page's `lang="pl"`.
**How to avoid:** Nothing can force it, and every replacement (a styled button, a drop zone) is worse for keyboard and screen-reader users. `04.1-UI-SPEC.md §8` already records this as a **documented, accepted exception**. The plan must carry that exception into the SC2 verification so a reviewer does not log it as a defect.
**Warning signs:** An SC2 reviewer on an English-locale machine reporting "Choose File".

### Pitfall 9: `wrangler types --check` fails after adding secrets

**What goes wrong:** The deploy breaks with "Types at worker-configuration.d.ts are out of date".
**Why it happens:** Creating a root `.dev.vars` makes `wrangler types` emit its keys as **required** members that Pages CI cannot reproduce.
**How to avoid:** Declare new admin secrets as **optional** in `src/app.d.ts` `interface Env`, and never create `.dev.vars`. Pass them to local and Playwright runs as `--binding` flags in `preview:test`.

### Pitfall 10: One concurrent build, 500 per month

**What goes wrong:** Two saves in quick succession, or a save during a developer push, queue behind each other and the honest "about two minutes" becomes four.
**Why it happens:** Pages Free allows "1 build at a time" and 500 builds/month `[CITED: developers.cloudflare.com/pages/platform/limits]`.
**How to avoid:** Nothing to fix, but D-11's one-save-per-page rule is the mitigation and the instrukcja should say "about two minutes, longer if someone else just saved."

## Code Examples

### 1. Mint a GitHub App installation token (workerd, no dependencies)

```ts
// Source: docs.github.com/.../generating-a-json-web-token-jwt-for-a-github-app
//         + docs.github.com/en/rest/apps/apps (create an installation access token)
// Verified in this session: PKCS#1 fails importKey, PKCS#8 succeeds.

const ALG = { name: 'RSASSA-PKCS1-v1_5', hash: 'SHA-256' } as const;

let kluczCache: CryptoKey | undefined; // module scope = once per isolate (3.7 ms saved)
let tokenCache: { token: string; wygasa: number } | undefined;

function b64url(bajty: ArrayBuffer | string): string {
	const s = typeof bajty === 'string'
		? bajty
		: String.fromCharCode(...new Uint8Array(bajty));
	return btoa(s).replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
}

function pemDoArrayBuffer(pem: string): ArrayBuffer {
	// Accepts ONLY PKCS#8 ("BEGIN PRIVATE KEY"). A PKCS#1 key from GitHub
	// ("BEGIN RSA PRIVATE KEY") throws DOMException: Invalid keyData below.
	const b64 = pem.replace(/-----[^-]+-----/g, '').replace(/\s+/g, '');
	const bin = atob(b64);
	const buf = new Uint8Array(bin.length);
	for (let i = 0; i < bin.length; i++) buf[i] = bin.charCodeAt(i);
	return buf.buffer;
}

async function jwtAplikacji(clientId: string, pkcs8Pem: string): Promise<string> {
	kluczCache ??= await crypto.subtle.importKey(
		'pkcs8', pemDoArrayBuffer(pkcs8Pem), ALG, false, ['sign']
	);
	const teraz = Math.floor(Date.now() / 1000);
	// iat 60 s in the past for clock drift; exp max 10 minutes ahead (GitHub rule).
	const naglowek = b64url(JSON.stringify({ alg: 'RS256', typ: 'JWT' }));
	const tresc = b64url(JSON.stringify({ iat: teraz - 60, exp: teraz + 540, iss: clientId }));
	const wejscie = `${naglowek}.${tresc}`;
	const podpis = await crypto.subtle.sign(ALG, kluczCache, new TextEncoder().encode(wejscie));
	return `${wejscie}.${b64url(podpis)}`;
}

export async function tokenInstalacji(
	env: { GITHUB_APP_CLIENT_ID?: string; GITHUB_APP_PRIVATE_KEY?: string; GITHUB_APP_INSTALLATION_ID?: string },
	teraz: number = Date.now()
): Promise<string> {
	if (tokenCache && tokenCache.wygasa > teraz + 60_000) return tokenCache.token;

	const jwt = await jwtAplikacji(env.GITHUB_APP_CLIENT_ID!, env.GITHUB_APP_PRIVATE_KEY!);
	const res = await fetch(
		`https://api.github.com/app/installations/${env.GITHUB_APP_INSTALLATION_ID}/access_tokens`,
		{
			method: 'POST',
			headers: {
				Authorization: `Bearer ${jwt}`,
				Accept: 'application/vnd.github+json',
				'X-GitHub-Api-Version': '2022-11-28',
				// GitHub REQUIRES a User-Agent; requests without one are rejected.
				'User-Agent': 'zlobek-panel-redakcyjny'
			}
		}
	);
	if (!res.ok) throw new Error(`github: token ${res.status}`);
	const dane = (await res.json()) as { token: string; expires_at: string };
	tokenCache = { token: dane.token, wygasa: Date.parse(dane.expires_at) };
	return dane.token;
}
```

Note on `X-GitHub-Api-Version`: the docs page currently renders `2026-03-10` as the example value, while `2022-11-28` remains the widely-deployed pinned version. Pin **one** value explicitly rather than omitting the header, and record which. `[CITED: docs.github.com/en/rest/apps/apps]`

### 2. Atomic two-file commit with free conflict detection

```ts
// Source: docs.github.com/en/rest/git/{blobs,trees,commits,refs}
// D-07 (atomic), D-10 (refuse stale save).

interface PlikDoZapisu {
	sciezka: string;                  // e.g. 'src/lib/content/aktualnosci/x.json'
	tresc: string;                    // utf-8 text, or base64 when base64 === true
	base64?: boolean;
}

export async function zapiszAtomowo(opts: {
	token: string; repo: string; galaz: string;
	pliki: PlikDoZapisu[]; usun?: string[];
	komunikat: string;
	oczekiwanySha?: string;           // head SHA captured when the editor opened the form
	fetchImpl?: typeof fetch;         // injected for tests, per the obsluz() precedent
}): Promise<{ ok: true; sha: string } | { ok: false; powod: 'konflikt' | 'blad' }> {
	const f = opts.fetchImpl ?? fetch;
	const gh = async (sciezka: string, init?: RequestInit) => {
		const r = await f(`https://api.github.com/repos/${opts.repo}${sciezka}`, {
			...init,
			headers: {
				Authorization: `Bearer ${opts.token}`,
				Accept: 'application/vnd.github+json',
				'X-GitHub-Api-Version': '2022-11-28',
				'User-Agent': 'zlobek-panel-redakcyjny',
				'Content-Type': 'application/json',
				...(init?.headers ?? {})
			}
		});
		if (!r.ok) throw new Error(`github ${sciezka} ${r.status}`);
		return r.json() as Promise<Record<string, string>>;
	};

	try {
		// 1. current head
		const ref = await gh(`/git/ref/heads/${opts.galaz}`) as unknown as { object: { sha: string } };
		const headSha = ref.object.sha;

		// 2. D-10: refuse a save built on a stale view. Checked BEFORE any write,
		//    so a refusal costs nothing and creates no orphan blobs.
		if (opts.oczekiwanySha && opts.oczekiwanySha !== headSha) {
			return { ok: false, powod: 'konflikt' };
		}

		const commit = await gh(`/git/commits/${headSha}`) as unknown as { tree: { sha: string } };

		// 3. one blob per file. 'base64' lets the image bytes pass through
		//    WITHOUT the Worker ever decoding them (CPU budget, D-12).
		const wpisy = await Promise.all(
			opts.pliki.map(async (p) => {
				const blob = await gh('/git/blobs', {
					method: 'POST',
					body: JSON.stringify({
						content: p.tresc,
						encoding: p.base64 ? 'base64' : 'utf-8'
					})
				});
				return { path: p.sciezka, mode: '100644', type: 'blob', sha: blob.sha };
			})
		);

		// sha: null deletes a path in the resulting tree.
		const usuniecia = (opts.usun ?? []).map((sciezka) => ({
			path: sciezka, mode: '100644', type: 'blob', sha: null
		}));

		// 4. base_tree merges everything not mentioned here.
		const tree = await gh('/git/trees', {
			method: 'POST',
			body: JSON.stringify({ base_tree: commit.tree.sha, tree: [...wpisy, ...usuniecia] })
		});

		// 5. one commit, therefore one Pages build (D-11).
		const nowy = await gh('/git/commits', {
			method: 'POST',
			body: JSON.stringify({ message: opts.komunikat, tree: tree.sha, parents: [headSha] })
		});

		// 6. force:false makes GitHub itself reject a non-fast-forward, which closes
		//    the race between the check at step 2 and this write.
		await gh(`/git/refs/heads/${opts.galaz}`, {
			method: 'PATCH',
			body: JSON.stringify({ sha: nowy.sha, force: false })
		});

		return { ok: true, sha: nowy.sha };
	} catch (e) {
		// A 409/422 from update-ref is the race form of a conflict, not a generic failure.
		const wiadomosc = e instanceof Error ? e.message : '';
		if (wiadomosc.includes('409') || wiadomosc.includes('422')) {
			return { ok: false, powod: 'konflikt' };
		}
		return { ok: false, powod: 'blad' };
	}
}
```

// VERIFIED in this session against prettier 3.8.3 with this repo's prettier.config.js

export const handle: Handle = async ({ event, resolve }) => {

	// address from ADMIN_EMAILS (plus a rebuild) logs that person out on their next

	if (!sesja || !naLiscie(sesja.email, env?.ADMIN_EMAILS)) {

			// An expired session must not silently discard a POST.
			return new Response(null, { status: 303, headers: { location: '/admin/logowanie?powod=wygasla' } });

};

### 5. Browser image island: decode, centre-crop, resize, encode

```ts
// Runs in the browser only (D-12). imageOrientation defaults to 'from-image', so EXIF
// rotation is applied by the decoder; it is passed explicitly because that default
// changed during the spec's life and older engines defaulted the other way.
export async function przygotujZdjecie(
	plik: File,
	proporcja: number,          // 16/9 for aktualnosci, 4/3 for o-nas
	maksDluzszyBok = 1600,
	jakosc = 0.82
): Promise<string> {                                   // returns a data URL
	const bitmapa = await createImageBitmap(plik, { imageOrientation: 'from-image' });

	// centred crop to the target aspect
	const zrodloProporcja = bitmapa.width / bitmapa.height;
	let sw = bitmapa.width, sh = bitmapa.height, sx = 0, sy = 0;
	if (zrodloProporcja > proporcja) {
		sw = Math.round(bitmapa.height * proporcja);
		sx = Math.round((bitmapa.width - sw) / 2);
	} else {
		sh = Math.round(bitmapa.width / proporcja);
		sy = Math.round((bitmapa.height - sh) / 2);
	}

	let dw = sw, dh = sh;
	if (Math.max(dw, dh) > maksDluzszyBok) {
		const skala = maksDluzszyBok / Math.max(dw, dh);
		dw = Math.round(dw * skala);
		dh = Math.round(dh * skala);
	}

	// OffscreenCanvas where available, <canvas> otherwise: toBlob has wider support.
	const plotno: OffscreenCanvas | HTMLCanvasElement =
		typeof OffscreenCanvas !== 'undefined'
			? new OffscreenCanvas(dw, dh)
			: Object.assign(document.createElement('canvas'), { width: dw, height: dh });
	const ctx = plotno.getContext('2d') as CanvasRenderingContext2D;
	ctx.drawImage(bitmapa, sx, sy, sw, sh, 0, 0, dw, dh);
	bitmapa.close();

	const blob: Blob = 'convertToBlob' in plotno
		? await plotno.convertToBlob({ type: 'image/jpeg', quality: jakosc })
		: await new Promise((res) =>
			(plotno as HTMLCanvasElement).toBlob((b) => res(b!), 'image/jpeg', jakosc));

	// A data URL, not an object URL: it survives a form POST as a plain field value,
	// it needs no CSP blob: allowance for the preview, and the base64 it already
	// contains is forwarded VERBATIM to the GitHub blob API so the Worker never
	// re-encodes (measured: base64 of 400 KB costs ~6.6 ms of a 10 ms budget).
	return await new Promise((res) => {
		const fr = new FileReader();
		fr.onload = () => res(fr.result as string);
		fr.readAsDataURL(blob);
	});
}
```

### Behaviours NOT inferable from unit tests

These are the ones that need held-out, property-based, or genuinely manual checks. A unit test written against the same mental model that wrote the code will pass on all of them regardless of correctness.

1. **Enumeration-safety of the login (D-02).** A unit test asserts the two response bodies are equal, which is exactly what the implementer intended and proves nothing about **timing**. Needs a black-box check on the deployed site: request a code for a known and an unknown address 10 times each and compare the response-time distributions. If they separate, the oracle exists. This is the single most likely SC1 defect to ship undetected.
2. **Atomicity of the two-file commit (D-07).** A unit test with an injected fetch proves the *request shape*. It cannot prove GitHub applied both blobs in one commit. Needs a real commit against the real repo and an inspection that `git show --stat <sha>` lists exactly two files.
3. **Conflict refusal on a stale SHA (D-10).** Requires two concurrent sessions. Automatable in Playwright with two browser contexts, but the interesting case is the **race** between the step-2 check and the `update-ref`, which only `force: false` covers and which no test will reliably reproduce. Verify by reasoning plus a deliberate manual two-tab test.
4. **Prettier-cleanliness of emitted JSON (D-09).** Must be **property-based, not example-based**. Generate content objects across the real field shapes (empty arrays, single-key objects, strings over `printWidth: 100`, strings containing `\n`, Polish diacritics) and assert `serializujJson(x) === prettier(serializujJson(x))` for each. An example-based test would have passed the original Phase 3 defect if the example happened to be a long object.
5. **Reader compatibility (SC5).** Property-based: feed panel output through `postFromEntry()` / `withMeta()` and assert a non-null result AND no `console.warn`. A hand-written fixture proves only that one fixture works.
6. **The image actually renders after publish.** The basename must land in the Vite glob. Only a real build proves it. Assert in Playwright against the built preview that the `<enhanced:img>` for a seeded upload renders a `<picture>`, not the tint fallback.
7. **Secrets reach the deployment.** Works locally with `--binding` and fails live is the classic Pages-secret ordering bug. Only a live check catches it.

| V4 Access Control | **yes** | Single gate in `hooks.server.ts` covering pages **and** actions. Deny by default: everything under `/admin` except `/admin/logowanie` requires a session. |
| V5 Input Validation | **yes** | Reuse `bezpiecznyEmail()` / `bezpiecznyTekst()`. Per-collection field rules in `walidacja.ts`. Data-URL regex with a hard length cap before any processing. Generated filenames only (D-14), never user-supplied. |
| V6 Cryptography | **yes** | WebCrypto only: RS256 for the GitHub JWT, HMAC-SHA256 for sessions, SHA-256 for OTP and rate-limit hashing. **Never hand-roll.** OTP digits from `crypto.getRandomValues`, never `Math.random`. |
| V7 Error Handling / Logging | **yes** | Follow the existing rule: **nothing that could carry personal data is logged.** A staff e-mail address is personal data on a public body's system. Log binding names and status codes only. |
| V12 File Upload | **yes** | Type allowlist enforced by the regex; size cap before decode; filename generated server-side; the destination directory is fixed and the basename lookup is the traversal defence (T-03-03). |
| V14 Configuration | **yes** | Secrets from `platform.env` only. GitHub App scoped to **Contents:write on one repository** and nothing more (D-08). |

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Staff e-mail enumeration via the login | Information Disclosure | Identical body **and timing** for known/unknown (D-02, Pattern 4). The timing half is the unsolved part. |
| OTP brute force (10^6 space) | Spoofing | Attempt cap that **burns the code**, short TTL, plus the KV rate limiter. 6 digits is only safe with a hard attempt cap. |
| Session cookie forgery | Spoofing | HMAC-SHA256 over the payload with a secret of adequate length; reject on any verify failure. |
| Stale-session privilege retention after an editor leaves | Elevation of Privilege | Allowlist re-check on every request (Pattern 3). Without it, revocation takes up to 30 days. |
| Path traversal via image filename | Tampering | Filenames are generated, never accepted; the basename map lookup cannot escape the glob (T-03-03, D-14). |
| Committing a staff e-mail into a PUBLIC repo | Information Disclosure | D-04: a short non-personal handle in the message, machine identity as author. Worth a **grep gate on the emitted commit message** in the plan, because this is a one-line mistake with an irreversible consequence in git history. |
| Private key exposure | Information Disclosure | Pages secret only; never in `wrangler.jsonc`, never in `.dev.vars`, never logged. A key that leaks grants write to the repo. |
| CSRF against admin actions | Tampering | `sameSite: 'lax'` + `form-action 'self'` already in `kit.csp`. SvelteKit form actions are same-origin by default. |
| Stored XSS via content fields into the public site | Tampering | Narrative fields are a **markdown subset** rendered at build by `marked`; the strict validated-fields rule (02 D-05/D-08) is the control. Do not widen it. |
| Denial of the Pages build budget | Denial of Service | 500 builds/month is a real ceiling; only authenticated staff can trigger a build, and D-11 caps it at one per save. |

## Open Questions

1. **How is login timing equalised between allowlisted and non-allowlisted addresses?**
   - What we know: the response body and the step-2 screen are byte-identical by the UI-SPEC. The allowlisted path awaits Resend (~200-500 ms); the other does not.
   - What's unclear: whether to use `ctx.waitUntil()` (crossing a Phase 4 convention that is path-scoped and does not strictly apply), an artificial delay, or to accept and document the gap.
   - Recommendation: `waitUntil()` for the login code send only, in `src/lib/server/admin/`, with a comment naming the Phase 4 ban and why the rationale does not transfer. Verify with the timing-distribution check in Validation.

2. **Where does `recruitmentOpen` live after D-16?**
   - What we know: it is currently `export const recruitmentOpen = false;` in `src/lib/content/site.ts`, a TypeScript module the panel cannot safely rewrite. CONTEXT.md flags this as "the one D-16 detail the planner must resolve deliberately".
   - Recommendation: move the **value** to a small JSON file (for example `src/lib/content/nabor.json` as `{ "otwarty": false }`) and have `site.ts` import it and continue to export `recruitmentOpen` and the derived `recruitment` object unchanged. Every consumer keeps its current import, so SC5 holds and no component changes. This mirrors 05 D-03's reasoning for moving fee amounts into JSON.

3. **Does the admin daily rate limit share the forms' budget?** See Pitfall 6. Needs an explicit decision.

4. **Which `X-GitHub-Api-Version` is pinned?** See A4. Pick one, record it in a comment.

5. **Is the OTP e-mail's Polish copy covered by the copy sweep?** The UI-SPEC has a "Login code e-mail" copy section and notes CMS-03 covers it. Confirm `tests/admin-copy.unit.ts` sweeps the mail body too, not only the page copy.
