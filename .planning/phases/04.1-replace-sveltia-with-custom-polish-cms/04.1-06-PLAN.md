<planner_decisions>
- **P-16 (slug lifetime):** `slug.ts` runs at CREATE time only. The generated filename is `YYYY-MM-DD-<slug-of-title>.json` and the slug half is capped so the whole name stays short. On edit the filename is read from the route parameter and is never recomputed, because the filename is the public URL and Phase 3 already made that the rule.
- **P-17 (name collision):** if the generated filename already exists among the entries the reader returns, the create is refused with a Polish message rather than overwriting. Silently overwriting another post is a data-loss class defect and is not worth a random suffix that would make the URL unpredictable. The new copy string is added to `src/lib/content/panel.ts` and therefore joins the sweep.
- **P-18 (cover deletion deferred by one plan):** this plan's delete removes only the JSON file, because covers do not exist yet. Plan 07 extends the same action to also delete an orphaned cover in the same commit. The delete action is written so that extension is a list append, not a rewrite.
</planner_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| editor form input to committed JSON | narrative fields become published content, so their constraints are a security control, not a formatting preference |
| route parameter to file path | the slug from the URL selects which file is written and deleted |
| panel output to the public reader | the reader is the last line of defence and must never receive something it rejects |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-12 | Tampering | stored cross-site scripting through a narrative field | medium | mitigate | Narrative fields stay the constrained markdown subset the Phase 2 and 3 renderers already sanitize; the escape helper and the safe-href allow-list in the post renderer are untouched. No rich-text editor is introduced, enforced by a grep. |
| T-04.1-24 | Tampering | path traversal through the slug route parameter | high | mitigate | The written path is built from the entry the reader returned, and the reader derives the slug from the on-disk filename, so a fabricated slug resolves to no entry and the action returns not found. The create path is built by `nazwaPlikuWpisu` from a validated ISO date and a strict character-class slug. |
| T-04.1-25 | Tampering | a create silently overwriting an existing post | medium | mitigate | P-17 refuses the create with a Polish message. Enforced by the collision Playwright case. |
| T-04.1-26 | Denial of Service | an oversized narrative field | low | mitigate | Every text reader is capped by the shared field primitives, and the cap is a named exported constant the tests read. |
| T-04.1-27 | Tampering | a destructive action reachable by a link a crawler or a prefetch could follow | medium | mitigate | The delete link only opens a confirmation page; the deletion itself is a POST action on that page. Enforced by the no-POST-form assertion on the list. |
| T-04.1-13 | Tampering | a save overwriting a colleague's edit | medium | mitigate | Inherited from Plan 04: the head SHA is compared before any write. |
| T-04.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero packages installed. |
