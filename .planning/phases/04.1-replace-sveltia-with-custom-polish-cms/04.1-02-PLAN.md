`wygenerujKod()` draws from `crypto.getRandomValues` over a `Uint32Array` and rejects values in the biased tail before taking a modulo, so the digits are uniform. Never `Math.random`.

`kluczKodu(adres, sol)` mirrors the salted-digest shape in `ratelimit.ts`: SHA-256 over a salt-prefixed string, truncated to 8 bytes rendered as hex, joined behind `PREFIKS_KODU`. The address must not survive into the key in any readable form, and a comment must record that this is the same RODO reasoning the rate limiter states, because KV keys are operator-visible.

`skrotKodu(adres, kod, sol)` is a separate SHA-256 over salt, address and code, returned as hex. `sprawdzKod` compares hashes, never the codes: a plain equality on a six-digit string leaks prefix timing, and comparing digests sidesteps it. The comparison itself is a length-independent loop.

`zapiszKod(kv, adres, kod, sol, teraz)` writes a JSON value holding `skrot`, `wygasa` and `proby: 0` with `expirationTtl` set to a cleanup-only multiple of `TTL_KODU_S`, and returns a discriminated result. `sprawdzKod(kv, adres, kod, sol, teraz)` reads the entry, and returns one of exactly these outcomes: `ok`, `zly-kod`, `wygasl`, `za-duzo-prob`, `blad`. A wrong code increments `proby` and rewrites the entry; reaching `MAKS_PROB` deletes the entry and returns `za-duzo-prob`. A correct code deletes the entry and returns `ok`. An expired `wygasa` deletes the entry and returns `wygasl`.

`teraz: number` is the last parameter with no second clock read inside, because the unit suite freezes time. Every KV call sits inside a try/catch whose catch returns `blad`, and the accompanying comment must state explicitly that this module fails CLOSED and that this is a deliberate divergence from the fail-open degrade documented in `ratelimit.ts`, which is an abuse control behind Turnstile rather than the authentication boundary. A missing binding returns `blad` for the same reason.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| login form to server | the address and the typed code are untrusted input |
| server to Cloudflare KV | KV holds only a salted hash and an attempt count, never the code or the address |
| server to Resend | the code leaves the system exactly once, to one address, over the verified sending domain |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-05 | Spoofing | kod.ts brute force over a 10^6 space | high | mitigate | Hard cap of five attempts that BURNS the code, 15-minute TTL, plus the per-client hourly limiter. Pinned by the attempt-cap unit case and by the mutation check; the Plan 03 Playwright case that exhausts attempts is the second enforced check required by AG-3. |
| T-04.1-05b | Information Disclosure | plaintext code at rest in KV | high | mitigate | Only a salted SHA-256 is stored; the unit suite asserts the stored value does not contain the code as a substring. |
| T-04.1-05c | Spoofing | timing leak from comparing codes | medium | mitigate | Compare SHA-256 digests with a length-independent loop, never the codes. |
| T-04.1-06 | Denial of Service | login flood consumes the forms' daily Resend budget, or a busy form locks staff out | medium | mitigate | P-04 gives the panel its own daily prefix `rl:doba:adm` and its own ceiling of 20. Pinned by the distinct-key unit case. |
| T-04.1-15 | Elevation of Privilege | a KV failure treated as an authentication success | high | mitigate | P-06: every store and verify failure returns a refusal outcome. Pinned by two unit cases and by a mutation check that flipping the catch to success turns them red. |
| T-04.1-07 | Information Disclosure | staff address in a KV key, a log line or the mail payload of another form | high | mitigate | The KV key is a salted digest; no module here logs a value; the code e-mail uses its own payload builder so it can never inherit the forms recipient constants. |
| T-04.1-16 | Tampering | the forms mail payload builder gains a request-reachable parameter | high | mitigate | `mailer.ts` is not edited at all; enforced by a diff assertion in the acceptance criteria. |
| T-04.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing; every mechanism is a platform API. Any deviation requires the Package Legitimacy Gate first. |
