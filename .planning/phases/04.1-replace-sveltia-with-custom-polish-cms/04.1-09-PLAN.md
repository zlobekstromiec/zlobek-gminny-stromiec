<planner_decisions>
- **P-25 (facility photo naming):** an o nas photo is named from a slug of its alt text, prefixed to keep the uploads directory readable, capped in length, and made unique against the existing basenames through the helper `uploads.ts` already exposes. Unlike an aktualność cover there is no date and no entry slug to key on, and the alt text is the only human-meaningful thing the photo has. When the derived name is already taken by a DIFFERENT photo, append an ascending numeric suffix rather than overwriting.
- **P-26 (repeatable rows are server state, not client state):** add and remove are submit buttons carrying a form action and an index, handled by named actions that re-render with the submitted values and commit nothing. This is the only shape that works with JavaScript disabled, and it is why the UI-SPEC requires the persistent note telling the editor that adding a row does not save.
</planner_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| indexed form fields to arrays | the index is client supplied and must never select a path or an identity |
| narrative fields to published markdown | the constrained subset is a security control |
| pending photo data URLs to git blobs | several binaries can enter in one request |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-34 | Tampering | a crafted field index reaching a path or an array bound | medium | mitigate | Indexed fields are collected into a dense ordered array by the shared reader and the index is never used to build a path; the remove action removes by position within the submitted set only. Pinned by the removed-middle-index unit case. |
| T-04.1-12 | Tampering | stored cross-site scripting through misja, lead, kadra or obiekt text | medium | mitigate | The narrative fields stay the constrained markdown subset the Phase 2 renderer already sanitizes; no rich-text affordance is added. |
| T-04.1-29 | Information Disclosure | a facility photo published with no alternative text | medium | mitigate | Alt is required per photo on the server and the refusal is proven with JavaScript disabled. |
| T-04.1-11 | Denial of Service | several photos in one request exceeding the CPU or subrequest budget | medium | mitigate | The server never encodes bytes; each photo is one extra blob call, and the whole save stays far inside the fifty-subrequest ceiling. The number of facility photos is small by the nature of the page. |
| T-04.1-23 | Denial of Service | one editing session producing many builds | medium | mitigate | D-11: one page, one save, one commit; the add and remove actions write nothing, enforced by the single-orchestrator-call grep. |
| T-04.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero packages installed. |
</threat_model>
