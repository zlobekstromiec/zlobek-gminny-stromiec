## Decisions Made

- **The `__Host-` cookie in the harness needs an explicit domain and path, never a url.** Passing `url: 'http://localhost:4173'` to `context.addCookies` is refused outright with "Invalid cookie fields". Probed directly: Chromium DROPS the Secure flag when the seeding url is plain http (an ordinary-named cookie seeded that way comes back with `secure: false`), and the `__Host-` prefix then fails its own validation because the prefix requires Secure. `domain: 'localhost'`, `path: '/'`, `secure: true` and no url is accepted, stores a genuinely Secure host-only cookie, and Chromium then sends it to `http://localhost` because localhost is a trustworthy origin. This is the observed behaviour the plan asked to be recorded as fact rather than assumption.
- **Panel POST cases must carry an Origin header.** SvelteKit's CSRF layer answers 403 to a form POST with no Origin, and it runs before hooks. Without `origin: http://localhost:4173` the POST cases would have been measuring the CSRF check and not the gate.
- **The refusal cases are paired with a positive control.** A correctly signed, allowlisted cookie returning 200 is asserted alongside the tampered, foreign-signed and de-allowlisted cases, so those three cannot pass for some unrelated reason.
- **`_headers` gained a comment where the block was.** It states that there is deliberately no path-scoped block for /admin and that kit.csp must not be widened to accommodate the panel, so the block cannot be reintroduced by a future reader who finds its absence surprising.

## CSP After the `_headers` Removal

Confirmed against `wrangler pages dev` with the admin bindings. Both `/admin/logowanie` (200, unauthenticated) and an authenticated `/admin` (200) return a `content-security-policy` HTTP header from `kit.csp`, with a fresh nonce per response:

```
default-src 'self'; frame-src 'self' https://challenges.cloudflare.com;
connect-src 'self' https://challenges.cloudflare.com; font-src 'self';
img-src 'self' data:; object-src 'none';
script-src 'self' https://challenges.cloudflare.com 'nonce-<per-response>';
style-src 'self' 'unsafe-inline'; base-uri 'self'; form-action 'self'
```

`kit.csp` was NOT widened. The removed block was not merely dead, it was actively wrong for the new panel: it permitted `frame-src https://github.com`, `connect-src ... sveltia-cms-auth.devzlobekstromiec.workers.dev` and `img-src` on two githubusercontent hosts, none of which the SvelteKit panel needs. The one inline allowance in the surviving policy is `style-src 'unsafe-inline'`, which predates this phase.

## Deviations from Plan

### Approved Architectural Deviation

**1. [Rule 4 - Architectural, USER APPROVED] Sveltia removed in Plan 01 instead of Plan 11**

- **Found during:** Task 3 (proving the gate from a browser)
- **Issue:** `static/admin/` is a Cloudflare Pages static asset, and Pages resolves static assets BEFORE invoking the Worker. The bare `/admin` therefore returned Sveltia's `index.html` with a 200 and never reached `handle()`. The plan's own assertions (`GET /admin` returns 303, `POST /admin` returns 303, and the build gate `test ! -d .svelte-kit/cloudflare/admin`) could not hold while the bundle existed.
- **Decision superseded:** D-20, which said Sveltia would be removed only in Plan 11 after the new panel passed UAT on the live deployment.
- **Who approved:** the user, at the Plan 01 decision checkpoint, having been shown the consequence and accepted it.
- **Fix:** deleted `static/admin/`, `sveltia-cms-auth/` and `scripts/cms-sync.mjs`; removed the `cms:sync` script and the `@sveltia/cms` dependency and regenerated the lockfile with `npm install`; removed the two dead eslint ignore blocks and the `.prettierignore` entry; deleted the path-scoped `/admin/*` CSP block from `_headers`.
- **Files modified:** `package.json`, `package-lock.json`, `_headers`, `eslint.config.js`, `.prettierignore`, and 13 deleted files.
- **Verification:** `npm run check` 0 errors, `npm run lint` clean, `npm run test:unit` 216/216, `npm run build` 0 with both build gates passing, `npm run test` 128/128.
- **Committed in:** `6422376`
- **Accepted consequence:** staff have no working editor until Plan 10 completes. There is no substitute path in the meantime other than a developer editing the JSON directly.

**2. [Rule 1 - Bug] The fixture's `__Host-` cookie seeding was wrong as first written**

- **Found during:** Task 3b (first run of `tests/admin-auth.spec.ts`)
- **Issue:** `context.addCookies` with `url: 'http://localhost:4173'` throws "Invalid cookie fields", failing all three authenticated cases.
- **Fix:** seeded with an explicit `domain: 'localhost'` and `path: '/'` and no url, after probing six field combinations directly to establish the cause rather than guessing. The probe script was a scratch file and is not committed.
- **Files modified:** `tests/fixtures/admin.ts`
- **Verification:** 18/18 green.
- **Committed in:** `f3fa34f`
