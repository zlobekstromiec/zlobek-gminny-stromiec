## What Was Built

**The slug generator, and specifically the one line most implementations get wrong.** `slugAscii` normalises to NFD and strips combining marks, which handles eight of the nine Polish diacritics and every other accented Latin alphabet a pasted title might carry, and then runs an EXPLICIT pass for the stroked l in both cases. That letter has no canonical decomposition, so an NFD-only implementation emits it unchanged into a filename and nobody notices until somebody tries to open the post. The pass is written as code points rather than as the letters, so it survives every editor and diff round trip. `nazwaPlikuWpisu` joins the ISO date and the slug; a title made only of punctuation produces the date alone rather than a name ending in a dangling hyphen, because that hyphen would be the last character of a public URL.

**The validator is accountable to the public reader, not to itself.** `walidujWpis` builds its result KEY BY KEY from guarded locals, in the key order the two seed files already use, omitting an absent optional entirely rather than emitting an explicit undefined. The proof is not a fixture: 192 generated combinations (three titles, four bodies including markdown emphasis, a link and a list, four dates including a leap day and both ends of a month, with and without a zajawka, with and without the placeholder flag) are serialized with the real `serializujJson`, parsed back as the build would, and fed through `postFromEntry` with a plausible path. Every one returns non-null and emits **zero console warnings**, with the warning function captured for the duration of each case. That is SC5, and it is the reason the panel and the website cannot disagree about what a valid post is.

**The collection list vocabulary the dokumenty plan will reuse.** `WierszListy` makes the entry title the primary link's accessible name (never the word „Edytuj"), keeps the meta inside that same anchor, and renders both row actions as anchors with a visually hidden suffix naming the entry. The file contains no submit control and no posting element at all, permanently: deletion happens only on the confirmation page. `PustaLista` and `OdznakaZastepcza` complete the set, and `PrzyciskLink` is the link wearing the panel's button treatment that „Dodaj wpis" needs.

**The project's first destructive route.** `/admin/aktualnosci/[slug]/usun` opens a question, focuses it, restates exactly what disappears by quoting the title and the Polish date, never promises recovery, and puts the danger control behind the back link in the focus order. No typed confirmation, no second confirmation. The deletion is a POST on that page, expressed as a tree entry whose sha is null, which is why it costs no blob and needs no mechanism of its own.

**The two editor screens, from one set of fields.** `PolaWpisu` holds the field groups both screens render, so a create screen cannot offer a field the edit screen forgets. The date is three Polish selects reading the project's one month table; the body is a 240px textarea with a native disclosure beneath it whose syntax examples render inside code elements; the placeholder checkbox reuses the consent visual and none of its semantics. The photo group of Plan 07 has a commented insertion point rather than a stub control.

## Path Traversal Is Closed By Construction, Not By A Check

Worth stating plainly because it is the phase's highest-severity route threat (T-04.1-24). Neither editor route nor the delete route concatenates a route parameter into a path. The parameter is used to LOOK UP an entry among the ones the public reader returned, and that reader derives every slug from a real on-disk filename, so a fabricated slug matches nothing and the screen answers „Nie znaleziono tej treści". The path that is finally written comes from the entry. On the create side the path is built by `nazwaPlikuWpisu` from a validated ISO date and a slug whose character class admits only lowercase letters, digits and single hyphens; the unit suite drives `../../etc/passwd`, `..\\..\\windows`, `a/b/c` and `wpis.json` through it and asserts no slash, no backslash and no double dot survives.

## Deviations from Plan

### Auto-fixed

**1. [Rule 3 - Blocking] The client could not import the field vocabulary or the year window from `$lib/server`.**

- **Found during:** Task 1 and Task 3
- **Issue:** exactly the problem Plan 05 hit with the nabór radios. The page rendering the controls needs the identical names the action parses, and the three date selects must offer only years the validator accepts, but SvelteKit refuses at build time to bundle anything under `src/lib/server/` into client code.
- **Fix:** `src/lib/pola-wpisu.ts` (control names, query markers, the echo shape and its reader) and `src/lib/daty.ts` (`ROK_MIN`, `ROK_MAKS`, `DNI_MIESIACA`, `lataDoWyboru`) are neutral modules both sides import. `walidacja/pola.ts` now imports the year window and re-exports it, so exactly one declaration exists and nothing that already imported it had to change.
- **Commits:** `83514ce`, `5f6c7ec`

**2. [Rule 1 - Bug] A create redirecting to the new entry's edit screen would have answered „Nie znaleziono tej treści" for two minutes.**

- **Found during:** Task 3
- **Issue:** the plan says the create redirects to the edit screen of the new slug carrying a saved marker, and also says the edit screen returns a not-found result when the slug does not resolve. Those two are contradictory here, because `readAktualnosci` globs the content folder at BUILD time: the newly written file does not exist for anything to read until Cloudflare has rebuilt, and under the harness dry-run flag it never exists at all. An editor would have saved successfully and landed on a page telling them their entry was gone.
- **Fix:** the create redirects to the LIST with the new slug in the marker. The list renders the „Zapisano" panel, repeats the two-minute promise and links straight to the new public page, which is the honest version of the same journey. The edit screen's own save still redirects to itself, where the entry genuinely does exist in the build.
- **Commit:** `5f6c7ec`

**3. [Rule 2 - Missing critical functionality] The delete action had no stale-save protection.**

- **Found during:** Task 2
- **Issue:** the plan describes the delete action without a head SHA. D-10 applies to a deletion at least as strongly as to an edit: removing an entry on the strength of a view somebody else has since changed destroys work with no warning.
- **Fix:** the confirmation page reads the head on load and carries it in a hidden field, exactly as the editor screens do, and degrades the same way when the head cannot be read.
- **Commit:** `398ac8f`

**4. [Rule 2 - Missing critical functionality] The delete page's h1 did not receive focus after a client-side navigation.**

- **Found during:** Task 3, writing the browser case
- **Issue:** an editor reaches the confirmation page by clicking „Usuń" in the list, which is a client-side navigation. No fresh document is parsed, so the `autofocus` attribute does nothing and the question Contract 11 exists to make somebody read would have been announced to nobody.
- **Fix:** both mechanisms, exactly as `PanelKomunikat` already carries both: the attribute for the JavaScript-disabled path and an effect for the client-side one. Focusing twice is a no-op.
- **Commit:** `a6c6bcb`

**5. [Rule 2 - Missing critical functionality] The D-15 alt rule was implemented before its control exists.**

- **Found during:** Task 1
- **Issue:** the plan defers the photo control to Plan 07, but D-15 makes „a photo present without alt text is refused" a SERVER rule so it survives with JavaScript disabled. Leaving the rule for Plan 07 would mean the first version of the photo island decides whether it exists.
- **Fix:** `walidujWpis` already refuses an image without an alt and already omits both fields when there is no image, with unit cases for each direction. Plan 07 adds the control, not the rule.
- **Commit:** `83514ce`

**6. [Rule 1 - Bug] The row separator was compiled away by Svelte's style scoping.**

- **Found during:** Task 2
- **Issue:** `.wiersz + .wiersz` inside `WierszListy.svelte` is never satisfiable, because two instances of a component are not siblings within its own scoped stylesheet. The compiler reported it as an unused selector, which is exactly right.
- **Fix:** the separator moved to the list page, which owns the list element and is where a between-rows rule belongs anyway.
- **Commit:** `398ac8f`

**7. [Rule 1 - Bug] Four comments would have made their own acceptance gates permanently red.**

- **Found during:** Tasks 2 and 3
- **Issue:** the same collision class Plan 02 hit with `Math.random` and Plan 03 hit twice. A comment saying „there is no button and no form in this file", one naming the native date input's type value, one naming the attribute that suppresses browser validation bubbles, and one listing the four banned rich-text technologies each made a literal grep match the very file that honours the rule.
- **Fix:** all four reworded to describe rather than name, each with a sentence recording why it is worded that way, following the precedent 04-02, 04.1-02 and 04.1-03 already set. Every gate is now literal-clean.
- **Commits:** `398ac8f`, `5f6c7ec`

**8. [Rule 1 - Bug] A raw control byte and a control-character regular expression in the first draft of the validator suite.**

- **Found during:** Task 1
- **Issue:** the hostile-input case was first written with literal NUL and DEL bytes in the source, which is exactly the defect 04.1-04 had to correct in `repo.ts`: the file became binary to `grep`, and a character class written that way survives no editor, diff or patch round trip reliably. The escaped rewrite then tripped eslint's `no-control-regex`, which refuses such a class for the same reason.
- **Fix:** the hostile input is written with unicode escapes and the assertion checks code points rather than matching a regular expression, so no suppression comment was needed. Verified afterwards that the file contains zero raw control bytes.
- **Commit:** `83514ce`

### Additions Beyond The Plan's File List

- **`src/lib/components/admin/PrzyciskLink.svelte`.** „Dodaj wpis" and „Anuluj" navigate and commit nothing, so they have to be anchors. `Przycisk.svelte` renders a real button, which is right for „Zapisz" and „Usuń wpis" and wrong here; `Cta.svelte` is the public component and carries only the site's arrow icon, while the panel's contract asks for a Lucide glyph chosen per action.
