<planner_decisions>
- **P-19 (cover filename):** the cover for an aktualność is named after the entry's own filename stem with a lowercase `.jpg` extension, so it is date prefixed, unique by construction for a given post and immediately recognisable in the uploads directory. The extension is fixed because the island always re-encodes to JPEG, and it must be lowercase and inside the accepted glob set, which excludes avif.
- **P-20 (stored value shape):** the `obraz` field stores a BARE BASENAME, matching the existing o-nas seed convention. The public reader keys by basename, so storing a path would add nothing and would give a future editor something traversal-shaped to type. Staff never type it in any case, because the panel generates it.
- **P-21 (replace semantics):** choosing a new file replaces the pending one in place; the file already in git is only overwritten at save, by committing a blob at the same path. There is no separate delete-then-add, because that would be two tree entries for one logical change.
</planner_decisions>

`src/lib/server/admin/obraz.ts` exports `MAKS_BASE64`, `PROPORCJA_WPISU` (16 divided by 9) and `base64ZDataUrl(wartosc)`. The function checks the type, then the length against the cap BEFORE running any pattern, then matches a strict data URL pattern allowing only jpeg, png and webp with a base64 payload, and returns the payload substring. It never calls a base64 encoder or decoder, never allocates a byte array, and never touches the pixels. Use the same glob pattern the three public consumers use so the accepted extension set cannot drift, and take only the keys, never the processed picture values, because this module runs on the server. Its header comment must record that an unknown basename yields the decorative tint fallback rather than a filesystem read, which is exactly why the lookup is traversal safe, and that a generated name outside the glob's extension set would silently publish a post whose cover never renders.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser file picker to hidden field | the data URL is entirely client controlled and is untrusted on arrival |
| hidden field to git blob | the only path by which binary content enters the repository |
| generated basename to the build glob | a name outside the glob publishes a post whose cover silently does not exist |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-10 | Tampering | path traversal through an image filename | high | mitigate | Filenames are generated from a validated ISO date and a strict character-class slug, never accepted from the request; the destination directory is a module constant; the public lookup is a basename map over a build-time glob and cannot escape it. Enforced by the basename unit case and by the rendered-picture Playwright case. |
| T-04.1-11 | Denial of Service | an oversized payload burning the request CPU budget | medium | mitigate | The length cap is checked before any pattern runs and before any allocation, and the server never encodes or decodes bytes. Enforced by the ordering unit case and its mutation check. |
| T-04.1-28 | Tampering | a disallowed content type smuggled through the data URL | medium | mitigate | A strict pattern allows only jpeg, png and webp with a base64 payload; anything else yields null and a Polish field error. |
| T-04.1-29 | Information Disclosure | a published photo with no alternative text, failing the accessibility baseline Phase 6 must certify | medium | mitigate | D-15 is enforced in the server-side validator, proven with JavaScript disabled, so it cannot be bypassed by turning scripting off. |
| T-04.1-30 | Tampering | a post going live without its photo | medium | mitigate | D-07: both blobs enter one tree and one commit. Enforced by the single-orchestrator-call grep and by the two-file stat output of the real commit. |
| T-04.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero packages installed; the decoder, the canvas and the encoder are all browser platform APIs, which is why no cropper or EXIF library is added. |
</threat_model>
