<planner_decisions>
- **P-08 (RESEARCH Open Question 1, resolved):** the step 1 action hands the Resend call to `event.platform.ctx.waitUntil(...)` so the allowlisted and non-allowlisted branches return at the same speed. The Phase 4 ban on deferring a send is real but is grep-scoped to `src/lib/server/forms/` and `src/routes/api/`, and it exists because a parent must never be told an enrolment was sent when it failed. A login code has a user-driven retry („Wyślij kod ponownie") and no silent-loss consequence, so the rationale does not transfer. The deferral therefore happens in `src/routes/admin/logowanie/+page.server.ts`, which is outside both banned paths, and the file must carry a comment naming the Phase 4 ban and why it does not apply here. The residual risk is that a send failure is invisible to the user in that request; the UI-SPEC already covers it with the „Nie udało się wysłać kodu" panel reachable through a retry, and the timing check in Plan 10's UAT is the enforced verification.
- **P-09 (button component):** `Cta.svelte` renders an anchor, so it cannot be the panel's „Zapisz" / „Wyślij kod" / „Zaloguj się" control. A sibling `src/lib/components/admin/Przycisk.svelte` renders a real `<button>` with variants `primary`, `secondary` and `danger`, reproducing the `Cta` primary and secondary treatments exactly (including the `0 3px 0` hard shadow on primary only) and adding the flat danger variant from UI-SPEC Component Contract 11. No new colour value is introduced.
- **P-10 (FormField extension):** `FormField.svelte` gains one optional prop, `nazwa`, rendered as the control's `name` attribute, plus `number` in its `Typ` union and an optional `wysokoscMin` for the taller `tresc` textarea. All three are additive with no default that changes existing output, so `KontaktForm.svelte` and `ZgloszenieForm.svelte` render byte-identically and the existing Playwright suite is the proof.
</planner_decisions>

`src/routes/admin/logowanie/+page.server.ts` exports `prerender = false` inherited from the admin layout and two named actions.

Action `wyslij` (step 1): read the address with `bezpiecznyEmail` from the forms sanitizer. A missing or malformed address returns an inline field error using the exact Polish strings from the copy module and re-renders step 1 with the typed value preserved. Otherwise the action ALWAYS returns the identical step 2 result: same status, same shape, same fields, same echoed address. Between those two points, and only when the address is on the allowlist, it generates a code, stores its hash, and schedules the Resend send. Order the work so the two branches are indistinguishable: run the rate-limit check first for every address, then the allowlist test, and hand the send to the execution context's post-response hook so the response is not waiting on Resend (P-08). The file header must carry the P-08 comment naming the Phase 4 ban, its grep scope, and why the rationale does not transfer. A rate-limit refusal renders the „Za dużo prób logowania" alert panel; note in a comment that this response is deliberately allowed to differ, because the limiter is keyed on the client and not on the address, so it leaks nothing about who is on the list.

Action `zaloguj` (step 2): read the address (from a hidden field, re-sanitized, never trusted) and the code. A missing code is an inline field error. Otherwise call `sprawdzKod` and map its outcome union onto the UI-SPEC login state matrix: `ok` re-checks the allowlist, derives the handle, signs the session, sets the cookie and redirects with 303 to `/admin`; `zly-kod` is an inline field error on the code input with the address and step preserved; `wygasl` is the „Kod stracił ważność" alert panel; `za-duzo-prob` is the „Za dużo prób" alert panel with step 2 and a working resend button still visible; `blad` is the „Nie udało się wysłać kodu" family failure panel. Never reveal whether the address was on the list.

`src/routes/admin/wyloguj/+page.server.ts` exports a default action only (no GET handler at all, so a GET keeps the framework's own refusal), clears the cookie and redirects with 303 to `/admin/logowanie?powod=wylogowano`.

| Boundary | Description |
|----------|-------------|
| anonymous visitor to /admin/logowanie | the only unauthenticated admin surface; every field on it is untrusted |
| step 2 hidden address field to server | client-supplied and re-sanitized on arrival, never trusted as identity |
| server to Resend | one message, to one address, only when that address is on the allowlist |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04.1-03 | Information Disclosure | step 1 action response body reveals allowlist membership | high | mitigate | Identical status, shape and copy for both branches, taken from one copy module. Enforced by the byte-parity Playwright case. |
| T-04.1-04 | Information Disclosure | step 1 response TIME reveals allowlist membership | high | mitigate | P-08 defers the Resend call to the post-response hook so neither branch awaits it. | T-04.1-17 | Tampering | CSRF against the login or logout action | medium | mitigate | SameSite Lax cookie, `form-action 'self'` already in kit.csp, SvelteKit form actions are same-origin. Logout is POST-only, enforced by a Playwright case. |
| T-04.1-18 | Spoofing | identity taken from the client-supplied hidden address field | high | mitigate | The address is re-sanitized and re-checked against the allowlist before a session is signed; the code hash is keyed on that same address, so a swapped address cannot match a stored code. |
