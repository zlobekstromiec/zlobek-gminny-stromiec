# Phase 04.1: UI Design Contract (Panel redakcyjny)

> Visual and interaction contract for the custom Polish admin panel that replaces Sveltia CMS. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This document is UI-SPEC Amendment v1.5.** The Phase 1 contract and Amendments v1.1, v1.2, v1.3 and v1.4 stay in force in full. **Nothing here introduces a new colour value, a new font, a new font weight or a new type size.** Every value below already exists in `src/app.css` or in an approved amendment. This document assigns those values to the internal editing surfaces that no previous phase defined, and it enumerates the authoritative Polish microcopy for every one of them.
>
> **This is a delta spec.** Where it is silent, Phase 1 (tokens, focus ring, motion, copy rules) and Amendment v1.4 (form field, consent, error and success surfaces) govern verbatim.

**Scope:** CMS-01, CMS-02, CMS-03 (all three re-scoped by this phase, per 04.1 D-21). ROADMAP Phase 04.1 success criteria 1, 2 and 3 are UI criteria and this contract is what makes them checkable.
**Stack context:** SvelteKit 2 + Svelte 5 runes + Tailwind v4 CSS-first `@theme` in `src/app.css` (there is no `tailwind.config.js`, and there never will be). shadcn/ui is React-only and does not apply. `/admin` routes are server-rendered and dynamic: excluded from prerender, `noindex`, not linked from any public page.
**Language:** Polish only, every surface, no exceptions (SITE-06, CMS-03, ROADMAP SC2). Nav, buttons, labels, hints, validation, confirmations, empty states, errors, page titles and the login e-mail itself.
**Copy rules (v1.2 §8, non-negotiable, apply to shipped copy, code comments, test names and commit messages):** no emoji, no em dashes anywhere (use commas, colons, parentheses), en dash only inside numeric ranges (`7:00–8:30`), plain hyphen in day abbreviations (`pon.-pt.`).
**Primary user:** żłobek staff with low technical confidence (PITFALLS.md §8 records "staff cannot use the CMS" as a live project risk). Every choice below favours the person who is afraid of breaking the website over the person who wants a fast tool.

## Layout & Density

Inherited breakpoints (`sm` 640, `md` 768, `lg` 1024, `xl` 1280). The panel is **desktop-comfortable and phone-usable**: staff will mostly edit on a laptop, but a quick aktualność from a phone must work.

### Panel shell (all `/admin` routes except `/admin/logowanie`)

| Region | Below `lg` (1024px) | `lg` and above |
|--------|--------------------|----------------|
| Header bar | full width, 64px tall, sticky | full width, 64px tall, sticky |
| Nav | wrapping chip row directly under the header, 8px gaps, horizontal padding matching the gutter | vertical list in a 240px left sidebar, sticky below the header |
| Main | single column, gutters 16px (base) → 24px (`md`) | column beside the sidebar, gutter 32px |
| Content max width | 100% | forms 46rem, lists 60rem, both left-aligned inside the column, never centred on a wide screen |

One `<nav>` element serves both layouts; the difference is a media query, not a second markup tree.

### Density delta (this is the „denser, calmer" half of D-19)

The public site breathes at 48px → 96px section rhythm. The panel is a tool, so it compresses. Every value stays on the 4px grid and every value already exists in the inherited scale:

| Measure | Public site | Panel |
|---------|-------------|-------|
| Section vertical padding | 48px → 96px | **24px → 32px** |
| Page header to first control | 32px | **24px** |
| Gap between field blocks | 24px | **24px (unchanged)** |
| Gap between field groups (`fieldset`) | n/a | **32px** |
| Card / panel padding | 24px → 32px | **16px → 24px** |
| List row min-height | 48px | **48px (unchanged, WCAG floor)** |
| Decorative blobs, waves, tints, hard shadows, hover raises | present | **absent** (see below) |

**What the panel deliberately does NOT inherit,** because a tool that bounces is a tool that distracts:
- no `Wave` dividers, no expressive blobs, no `TopBar`, no public `Header`, no public `Footer`;
- no `0 3px 0` hard-shadow 3D button treatment except on the single primary „Zapisz" action (see Component Contract 9);
- no card hover raise (`translateY`), no `shadow-lg`;
- no surface alternation across sections. The panel background is `--color-surface-warm` `#FBFAF7`; content sits on `--color-surface` `#FFFFFF` cards. Two surfaces, everywhere, always.

**What the panel DOES inherit so it reads as the same product:** the brand emblem, Baloo 2 + Nunito, the exact token set, the 4px accent bottom border on the header bar, the nav chip treatment from v1.2 §3 (hover `tint-yellow`, active `accent` + `aria-current`), the global focus ring, the `FormField` contract from v1.4, and every copy rule.

## Spacing Scale

Inherited unchanged from Phase 1 (8-point scale, all multiples of 4). Panel assignments:

| Token | Value | Usage in the panel |
|-------|-------|--------------------|
| `2xs` | 4px | Required-asterisk gap, icon-to-text inset inside messages and badges |
| `xs` | 8px | Label to control gap, control to error gap, nav chip gaps, badge padding (vertical) |
| `sm` | 12px | Control vertical padding, badge padding (horizontal), row action gaps (documented v1.0 control-padding exception, never a layout value) |
| `md` | 16px | Card padding (base), list row horizontal padding, panel padding (base), gutter (base) |
| `lg` | 24px | Card padding (`md`+), gap between field blocks, panel padding (`md`+), section vertical padding, gutter (`md`) |
| `xl` | 32px | Gap between field groups, section vertical padding (`lg`), gutter (`lg`) |
| `2xl` | 48px | Gap between the last field group and the save row |
| `3xl` | 64px | Header bar height; bottom padding of the main column so the save row never sits flush with the viewport edge |

**Exceptions, all inherited, all WCAG-mandated:**
- **44×44px minimum hit area** on every interactive element: nav chips, row action links, buttons, file input, radios, checkboxes, „Wyloguj".
- **Input / select height 48px minimum** (12px vertical padding + 16px text at 1.5), exceeding the 44px floor deliberately, exactly as v1.4 fixed it.
- **Textarea 160px minimum height**, `resize: vertical`. The `tresc` textarea of an aktualność opens at **240px** (still a 4px multiple), because a full post typed into a 160px window is a documented staff frustration.
- **Sidebar width 240px** at `lg` and above.
- **Image preview slot** reserves its cropped aspect box before the image paints, so the island causes no layout shift: 16:9 for aktualności covers, 4:3 for o-nas photos.

**There is no non-multiple-of-4 value in this phase.** The single vendor exception recorded in v1.4 (the 300×65px Turnstile slot) does not appear in the panel: Turnstile is not used on any admin surface (the allowlist plus the rate limiter are the gate, and a bot cannot receive the code e-mail).

## Typography

Inherited unchanged. **No new size, no new weight, no new family.** The panel compresses the hierarchy by moving each role one step down the existing scale, which is what makes it read as denser without inventing anything.

| Role | Element in the panel | Family | Size | Weight | Line height |
|------|---------------------|--------|------|--------|-------------|
| Page title | admin `h1` (`Aktualności`, `Pulpit`, `Edycja wpisu`) | Baloo 2 | `clamp(1.5rem, 3vw, 1.75rem)` (the locked **h2 clamp**, reused one step down: a deliberate density decision, not a new size) | 700 | 1.2 |
| Section heading | `h2` inside a form (`Kadra`, `Zdjęcia`), list group heading, card title on the Pulpit | Baloo 2 | 20px (the inherited card-title sub-step) | 700 | 1.2 |
| Sub-heading | `h3`, repeatable-row legend (`Wartość 1`) | Nunito | 17px | 700 | 1.4 |
| Body | Paragraphs, list row primary text, control text, help prose | Nunito | 16px | 400 | 1.5 |
| Body (15px step) | Field labels (700), hints (400), validation messages (700), row meta (400), panel body text | Nunito | 15px | 700 / 400 | 1.5 |
| Label | Buttons, `<summary>`, nav chips, badges, table column headers | Nunito | 14px | 700 | 1.4 |
| Label (13px step) | „Zalogowano jako", footer line, timestamp meta | Nunito | 13px | 400 (meta) / 700 (badge text) | 1.4 |
| Code entry | the one-time code `<input>` | Nunito | 19px, `letter-spacing: 0.3em` | 700 | 1.4 |

- **Every input renders at 16px minimum** (the code input at 19px). Below 16px iOS Safari zooms the viewport on focus, which is a mobile usability defect. This is an inherited hard rule and it is not negotiable for density.
- **The panel's `h1` uses the h2 clamp.** This is a role reassignment inside the locked scale, not a fifth size. Heading order stays semantically correct (`h1` → `h2` → `h3`) and is never skipped.
- Running help prose caps at **65ch**; field hints cap at **65ch**.

**Hard rules added by this amendment:**
1. **`danger` means „this did not happen".** The stale-save refusal (D-10) is a failure of the save, so it is danger-coloured. „Nabór zamknięty" on `/admin/nabor` is neutral information and is never danger-coloured, exactly as v1.4 fixed for the public status banner.
2. **`tint-green` means „this happened".** It is used by the „Zapisano" panel and nowhere else in the panel.
3. **Placeholder attributes remain banned on every control** (v1.4 hard rule 3). Guidance lives in a persistent hint wired via `aria-describedby`.
4. **No state is signalled by colour alone.** The „Treść zastępcza" badge carries text, not a coloured dot. Errors carry an icon and an instruction. The active nav chip carries `aria-current="page"`.

## Component Contracts

### 1. Panel shell (`src/routes/admin/+layout.svelte`)

A **separate layout** from the public site: no `TopBar`, no `Header`, no `Footer`, no `Wave`. It reuses `SkipLink` and `Seo` verbatim.

- **Header bar:** `--color-surface` `#FFFFFF`, sticky top, height 64px, `shadow-sm` once scrolled, **4px `--color-accent` bottom border** (the inherited public-header cue).
  - Left: the brand emblem (`src/lib/assets/brand/logo-mark.png` through `enhanced:img`, 40px height, decorative, empty `alt`) plus the wordmark „Panel redakcyjny" (Baloo 700 20px, `ink`), the whole pair being a link to `/admin` with `aria-label="Panel redakcyjny, przejdź do pulpitu"`.
  - Right, in this order: „Zalogowano jako: {uchwyt}" (Nunito 400 13px `muted`, hidden below `sm` where space is scarce, and never the full e-mail address, per D-04); „Otwórz stronę żłobka" (secondary link, `target="_blank" rel="noopener noreferrer"`, Lucide `external-link` 18px `aria-hidden`, visually-hidden suffix „(otwiera się w nowej karcie)"); „Wyloguj" (see Contract 12).
- **Nav:** one `<nav aria-label="Sekcje panelu">`. Chips reuse the v1.2 §3 contract verbatim: `--radius-sm`, padding `12px 16px`, min-height 44px, Nunito 700 14px `ink`; hover `--color-tint-yellow` background; active (`aria-current="page"`) `--color-accent` background with `ink` label. Order: `Pulpit`, `Aktualności`, `O nas`, `Plan dnia`, `Dokumenty`, `Nabór`, `Pomoc`. At `lg` the same list renders as a vertical sidebar on `--color-band` `#E0F2FE`, chips full width, left-aligned.
- **Main:** one `<main id="main">`, exactly one `<h1>` per screen.
- **Persistent info line** at the bottom of every edit screen, above the footer: `--color-tint-blue` `#CFE8FC` panel, `--radius-md`, padding 16px, Lucide `info` 22px `brand-blue`, ink 15px, carrying the publish-delay promise (see Copywriting). This is the D-18 honesty contract made structural rather than remembered.
- **Footer:** one line, Nunito 400 13px `muted`, on the warm background: the institution name plus a link to the instrukcja. No columns, no logos, no BIP link. The panel is not a public page.
- **`Seo`:** `noindex, nofollow` on every admin route, Polish `<title>` of the form `{Sekcja}, panel redakcyjny`. No admin route is linked from any public page or sitemap, and `/admin` is excluded from prerender.

### 2. Login screen (`/admin/logowanie`): the whole e-mail-code flow

No shell, no nav, no session. A centred single card on the warm background: `--color-surface` `#FFFFFF`, `--radius-lg`, `shadow-md`, 2px `--color-band` border, padding 24px → 32px (`md`), max width **28rem**, vertically offset 48px from the top (not centred in the viewport: a vertically centred card jumps when an error message appears).

Above the card: the brand emblem at 52px, centred, decorative. Inside, in DOM order: `h1` „Panel redakcyjny" → lead → status region (empty on load) → the step form.

**This screen requires no JavaScript at all.** Both steps are SvelteKit form actions with a full page response.

#### Step 1: address entry

- One `FormField` (`typ="email"`, `autocomplete="email"`, `required`), label „Adres e-mail", hint per the copy table.
- Primary button „Wyślij kod", full width below `sm`, auto width above.

#### Step 2: code entry (rendered after the step 1 action returns)

- **Non-enumerating by construction (D-02):** the step 2 screen, its heading, its body copy and its timing are byte-identical whether or not the address is on the allowlist. The server sends an e-mail only in the allowlisted case, and nothing in the response differs. No „nie znaleziono", no „sprawdź adres", no faster response path, no different error.
- The entered address is echoed back as plain text (`Wysłaliśmy kod na: anna.kowalska@example.com`) so a typo is visible, plus a „Wpisz inny adres e-mail" link back to step 1.
- **One single `<input>` for the code, never six boxes.** Six per-digit boxes need JavaScript to move focus, break paste, and are a documented screen-reader hazard. Contract: `inputmode="numeric"`, `autocomplete="one-time-code"`, `pattern="[0-9]*"`, `maxlength="6"`, `required`, rendered at Nunito 700 19px with `letter-spacing: 0.3em`, width 12rem, otherwise the inherited `FormField` control box.
- Primary button „Zaloguj się". Beneath it, two secondary actions on one row (wrapping below `sm`): „Wyślij kod ponownie" (a `<button>` inside its own form, never a link, because it performs an action) and „Wpisz inny adres e-mail" (a link back to step 1).
- **Every failure state is a panel above the form, `role="alert"`, `tabindex="-1"`, focused on render**, `danger-surface` with a 2px `danger` border, heading Baloo 700 20px `danger`, body ink 15px. The typed address is never lost.

#### Login state matrix

| State | Presentation | Focus |
|---|---|---|
| Address missing or malformed | Inline field error on the e-mail field (`aria-invalid`, icon, message) | the field |
| Code sent (allowlisted or not) | Step 2 screen with the neutral confirmation body | the code input |
| Code wrong | Inline field error on the code input, address and step preserved | the code input |
| Code expired | Alert panel with the „wyślij ponownie" instruction | the panel |
| Too many code attempts | Alert panel, code burned, step 2 stays visible with a working „Wyślij kod ponownie" | the panel |
| Rate limited (too many codes requested) | Alert panel naming the wait, no field error | the panel |
| E-mail send failure | Alert panel, retry instruction | the panel |
| Session expired (arrived by redirect) | Neutral band panel above the card (`#E0F2FE`, ink text), **not** danger: an expired session is expected, not a failure | the panel |
| Just logged out | Neutral band panel, same treatment | the panel |

### 3. Pulpit (`/admin`)

The landing screen after login. Its job is to make the next action obvious to somebody who opens the panel twice a month.

- `h1` „Pulpit", lead paragraph naming the publish delay.
- A grid of **entry cards**, 1 column (base) → 2 (`md`) → 3 (`lg`), gap 24px. Each card: `--color-surface`, `--radius-md`, 1px `--color-border-subtle`, padding 16px → 24px, containing an `h2` (20px Baloo, `brand-blue`, the whole card is one link), a one-sentence Polish description (15px `muted`), and where meaningful a count or a current-state line (15px `ink`, for example „Liczba wpisów: 2" or „Obecnie: nabór zamknięty").
- **No hover raise and no shadow change.** Hover darkens the card border to `--color-border-strong` and underlines the heading. Focus uses the global ring on the card link.
- The card is a single link with the heading as its accessible name; the description is inside the same `<a>` so it is announced with it (the same „meta inside the link" rule the document rows follow).

### 4. Collection list screen (`/admin/aktualnosci`, `/admin/dokumenty`)

- **Page header row:** `h1` on the left, the primary action button on the right (`Dodaj wpis` / `Dodaj dokument`, Lucide `plus` 18px `aria-hidden`). Below `sm` the button drops to its own full-width row beneath the `h1`.
- **Rows, not a table.** A `<ul>` of rows on `--color-surface` inside one card, separated by 1px `--color-border-subtle`. Each row: min-height 48px, padding `12px 16px`, flex, wrapping below `sm`.
  - Primary: the entry title as a link to its edit screen (Nunito 700 16px `brand-blue`, underlined, hover `brand-blue-hover`). The link text is the title itself, so the accessible name is never „Edytuj".
  - Meta, inside the same link: for aktualności `15.07.2026`; for dokumenty `PDF · wersja z 02.04.2026` (Nunito 400 15px `muted`, middot separators, consistent with the public document rows).
  - **„Treść zastępcza" badge** when `placeholder: true`: `--color-tint-yellow` background, 2px `--color-accent-active` border, `--radius-sm`, padding `4px 12px`, Nunito 700 13px `ink`, text „Treść zastępcza". Text plus border, never a bare colour swatch.
  - Row actions on the right: „Edytuj" (link, Lucide `pencil` 18px) and „Usuń" (link to the confirmation page, Lucide `trash-2` 18px, `danger` text). Each carries a visually-hidden suffix naming the entry (`Usuń wpis: Wielkie otwarcie żłobka`), because a list of eight identical „Usuń" links is a WCAG 2.4.4 failure. Both are ≥44×44px.
  - **„Usuń" is a link to a page, never a button that deletes.** Deletion happens only from the confirmation screen (Contract 11).
- **Dokumenty grouping:** rows grouped by `kategoria` under `h2` headings in the fixed order `Rekrutacja`, `Statut i uchwały`, `RODO`. Unlike the public page, an **empty category still renders its heading** with a one-line „Brak dokumentów w tej kategorii." note, because in the panel the editor needs to see that the drawer exists.
- **Empty state (required, both lists):** a centred panel on `--color-surface-warm`, `--radius-md`, padding 24px, Lucide `file-text` 32px `muted` `aria-hidden`, Baloo 700 20px heading, Nunito 400 16px `muted` body, and the primary „Dodaj wpis" / „Dodaj dokument" button repeated inside the panel. Copy in the Copywriting Contract.
- Ordering: aktualności newest first (matching the public list); dokumenty by category then by name.

### 5. Edit form screen (every content type)

The screen is a plain server-rendered `<form method="POST">` with a SvelteKit form action. It works with JavaScript disabled apart from the optional photo island.

DOM order, fixed:

1. **Back link** „Wróć do listy" (or „Wróć do pulpitu" for singletons), `brand-blue` underlined, Lucide `chevron-left` 18px.
2. `h1` (`Nowy wpis` / `Edycja wpisu` / `O nas` / `Plan dnia` / `Nabór`).
3. **Save-result region** (empty on load): the „Zapisano", conflict or failure panel (Contract 10) lands here.
4. **Validation summary region** (empty on load): Contract 10a.
5. **Required-fields note:** „Pola oznaczone gwiazdką (*) są wymagane."
6. **Field groups**, each a `<fieldset>` with a visible `<legend>` styled as the 20px `h2` step, on one `--color-surface` card per group, `--radius-md`, 1px `--color-border-subtle`, padding 16px → 24px, 32px between groups.
7. **Save row** (Contract 9).
8. The persistent publish-delay info panel from the shell.

- **Every control is the inherited `FormField`** from v1.4: label (Nunito 700 15px ink) → optional hint (Nunito 400 15px muted) → control (48px, 2px `border-strong`, `--radius-sm`) → optional error (Nunito 700 15px danger, `circle-alert` icon, phrased as an instruction). `aria-describedby` lists only ids that exist. `aria-invalid` is set only while the field is actually invalid.
- **Validation is server-side and it is the only validation that matters.** HTML `required` and `type` attributes stay for semantics and mobile keyboards, the form carries `novalidate` so the browser's own English-in-some-locales bubbles never appear, and every message the editor sees is authored Polish. A JS-enhanced pre-check may be added later but must never be the only check.
- **Dates are three selects, never `<input type="date">`.** The date picker chrome is browser-locale dependent and cannot be forced to Polish, which is the same reasoning that rejected `<input type="month">` in v1.4. A date is a `<fieldset>` with a visible `<legend>` and three `<select>` controls (`Dzień`, `Miesiąc`, `Rok`) side by side, stacked below 640px, Polish month names reused from `MIESIACE_WYBOR` in `src/lib/content/forms.ts`, each with an explicit empty first option „Wybierz". One error message for the whole group, associated via `aria-describedby` on the fieldset. Stored as ISO `YYYY-MM-DD` for aktualności (the shape the Phase 3 reader requires) and as `DD.MM.YYYY` for the dokument `wersja` field (its existing shape).
- **Numbers** (`kadra_opiekunki`, `kadra_personel`) use `<input type="number" inputmode="numeric" min="0" max="99">` with a Polish hint giving an example.
- **The „Treść zastępcza (do potwierdzenia)" checkbox** is the last control of the last group on every screen that has one, reusing the `ConsentBlock` checkbox visual (24×24px, 2px `border-strong`, checked `brand-blue` fill with a white glyph) but never its consent semantics or copy.

### 6. Narrative fields: the limited formatting affordance (02 D-05 / D-08)

**No WYSIWYG, no toolbar, no contenteditable, no rich-text library.** A narrative field is a plain `<textarea>` plus a native `<details>` help panel. Reasons, in order: the panel must degrade without JavaScript (D-17); a toolbar is an interactive component with its own accessibility bar and no budget; and the stored value must stay the constrained markdown subset the Phase 2 and 3 renderers already sanitize (bold, links, lists only).

- **Textarea:** the inherited control box, `min-height: 160px` (240px for `tresc`), `resize: vertical`, 16px ink text.
- **Help:** a native `<details>` directly beneath the textarea, 8px gap, reusing the v1.4 `<summary>` contract (Nunito 700 14px `brand-blue`, underlined, 44px min-height, custom marker removed and replaced by a Lucide `chevron-down` 18px that rotates 180° when open, rotation inside the component's reduced-motion guard). Open panel: `--color-surface-warm`, `--radius-md`, padding 16px, prose Nunito 400 15px `muted`, examples rendered inside `<code>` at the same size so the syntax is copyable.
- **Summary label:** „Jak formatować tekst". The panel explains exactly three things and explicitly states what is not supported (see Copywriting).
- **No live preview.** A preview needs either JavaScript or a server round-trip that risks being mistaken for a save. The publish-delay promise plus „Otwórz stronę żłobka" is the preview.
- Any character limit is stated in the hint, never enforced by a live counter (an `aria-live` counter is chatter for no benefit, v1.4 ruling).

### 7. Repeatable groups without JavaScript (wartości, plan dnia rows, zdjęcia)

The one genuinely hard no-JS pattern. Contract:

- Each item is a `<fieldset>` with a visible `<legend>` numbering it in Polish (`Wartość 1`, `Wiersz 3`, `Zdjęcie 2`) on a `--color-surface` card, 16px padding, 16px between items.
- **„Usuń tę wartość"** is a `<button type="submit" formaction="?/usunWiersz" name="index" value="{i}">`, secondary variant, `danger` text label, inside the same form. **„Dodaj wartość"** is a `<button type="submit" formaction="?/dodajWiersz">`, secondary variant, Lucide `plus` 18px, placed after the last item.
- Both actions **re-render the page with every typed value preserved and commit nothing to git.** This is stated in a persistent note directly above the add button: „Dodanie lub usunięcie wiersza nie zapisuje zmian. Na końcu kliknij Zapisz."
- After an add, focus moves to the first control of the new item (`autofocus` on the server-rendered response). After a remove, focus moves to the add button. Both are announced by a `role="status"` line („Dodano wiersz 4." / „Usunięto wiersz 2.").
- Reordering is **out of scope** for this phase in both directions (no drag, no arrows). Plan dnia rows and wartości are authored in order; to reorder, the editor retypes. Recorded here so the executor does not invent it. Arrow-button reordering is a natural Phase 5 addition when the gallery makes ordering matter.

### 8. Image upload and automatic crop: the only hydrated island

This is the single component in the phase that earns hydration (D-17), and it must clear the bar `MobileNav.svelte` set: keyboard operable, reduced-motion honest, axe clean.

**Markup and behaviour:**

- A `<fieldset>` with legend „Zdjęcie (opcjonalnie)" containing, in DOM order: a native `<input type="file" accept="image/jpeg,image/png,image/webp">` with a real visible `<label>`; a `role="status" aria-live="polite"` line; the preview slot; the action buttons; the alt-text field.
- **The file input stays a native file input.** It is not hidden behind a styled `<button>`, it is not replaced by a drop zone, and it is never `appearance: none` without a focus replacement. Native is keyboard operable, screen-reader labelled and touch friendly for free, and a drop zone is a mouse-only affordance.
- **On selection, in the browser (D-12):** decode → centre-crop to the target aspect → resize so the longest edge is at most **1600px** → re-encode as JPEG at **quality 0.82** → write the result into a hidden field as a data URL. The original file is never uploaded. Typical result: a 5 MB phone photo becomes roughly 200 to 400 KB. iPhone HEIC is handled by the browser's own decoder.
- **Crop is automatic and centred (D-13).** There is no drag handle, no zoom, no rotation, no grid overlay. Targets: **16:9** for an aktualność cover (matching `NewsCard`'s `aspect-ratio: 16 / 9`, so the card and the post page show the same framing) and **4:3** for an o nas facility photo (so the two-column grid stays even).
- **Preview slot:** reserves the target aspect box before the image paints (no layout shift), `--radius-md`, 1px `--color-border-strong`, `object-fit: cover`, max width 32rem. Beneath it a `<p>` caption „Tak zdjęcie pojawi się na stronie." (Nunito 400 15px `muted`). The preview is the crop result, so what the editor sees is exactly what publishes.
- **Buttons under the preview:** „Wybierz inne zdjęcie" (secondary, moves focus to the file input) and „Usuń zdjęcie" (secondary with `danger` label, clears the pending image and the preview, moves focus back to the file input, and announces „Usunięto zdjęcie z formularza."). Neither commits anything.
- **Status line copy:** „Przygotowywanie zdjęcia..." while working, then „Zdjęcie gotowe. Zostało przycięte do proporcji 16:9 i zmniejszone." Announced politely, never assertively.
- **No spinner, no progress bar, no animation of any kind.** There is nothing to disable under reduced motion because there is nothing moving. The status text is the progress indicator. This is deliberate: a spinner is the easiest reduced-motion violation to ship by accident.
- **Alt text is required (D-15).** The alt field sits directly beneath the preview inside the same fieldset, labelled „Opis alternatywny (alt) *", with the Polish hint that explains what to write. **The save is refused when a photo is present and the alt field is empty**, with a field-level error, on the server, so the rule holds without JavaScript. The reader keeps treating `obraz_alt` as optional and degrading safely (03-07), so this rule can never break the build.
- **Client-side rejections** (wrong type, absurd size) surface as the same field-error treatment as a server error, never as a browser `alert()`.
- **No-JavaScript degradation, stated honestly:** a `<noscript>` panel inside the fieldset (`tint-blue`, `info` icon) says that adding a photo needs JavaScript and that every other field can be filled and saved normally. Text content is never blocked by the photo. The server additionally rejects an oversized raw upload with a Polish message rather than burning the Workers CPU budget.

### 9. Save row and the primary action (D-11)

- **Exactly one „Zapisz" per page.** It is the last thing in the form, left-aligned, separated from the last field group by 48px, full width below `sm`.
- Treatment: the inherited primary `Cta` variant, unchanged (pill, `--color-accent` fill, `ink` label, `0 3px 0 accent-active`, hover `translateY(-2px)`, focus-visible mirroring the pressed state, 44px target, `12px 24px` padding, Nunito 700 16px). This is the one place the panel keeps the 3D treatment, precisely because it is the one moment that should feel like the site.
- To its right (below it under `sm`): „Anuluj" as a secondary link back to the list. No third action.
- **Saving state:** with JavaScript the button becomes `disabled aria-busy="true"` and the label swaps to „Zapisywanie...". Without JavaScript the browser's own navigation is the feedback. No spinner either way.
- Above the button, always present, Nunito 400 15px `muted`: „Zmiany zapisują się jako jedna całość. Pojawią się na stronie po około 2 minutach."

### 10. Save feedback surfaces

All three are panels rendered at the top of the form after the action returns (POST then redirect then GET for the success case, so a refresh never re-saves), `--radius-md`, padding 16px → 24px, max width 46rem.

**a) Validation summary (nothing was saved because fields need fixing)**
`role="alert"`, `tabindex="-1"`, focused. `--color-danger-surface`, 2px `--color-danger` border. Heading Baloo 700 20px `danger` with a `circle-alert` icon, body ink 15px, then a `<ul>` of in-page links (`#field-id`) that move focus to each offending control. Inherited verbatim from v1.4 §7a.

**b) „Zapisano" (D-18)**
`role="status"`, `tabindex="-1"`, focused. `--color-tint-green` `#DFF0D8`, Lucide `circle-check` 32px `brand-blue`. Heading Baloo 700 20px `ink` „Zapisano", body Nunito 400 15px `ink` carrying the honest promise, plus a `brand-blue` underlined link to the affected public page with the standard new-tab treatment and the visually-hidden „(otwiera się w nowej karcie)" suffix. **No live build-status polling, no progress, no auto-refresh, no confetti** (D-18, and the polling option is explicitly deferred).

**c) Stale-save refusal (D-10) and save failure**
`role="alert"`, `tabindex="-1"`, focused, rendered **above the form with every typed value intact**. `--color-danger-surface`, 2px `--color-danger` border. Heading Baloo 700 20px `danger`, body ink 15px.
- The conflict panel says what happened, why the panel refused, and what to do, and it **warns the editor to copy their text before reloading**, because reloading is the instruction and it costs the unsaved edit. A „Odśwież stronę" link to the same edit URL sits inside the panel.
- The generic failure panel (GitHub API error, network) states plainly that nothing was saved and that the typed values are still in the form.

### 11. Destructive actions: the confirmation page

- **Delete is a page, not a modal.** A dialog needs JavaScript, a focus trap, and an escape route; a page needs none of them and is impossible to dismiss by accident. Route: `/admin/{kolekcja}/{id}/usun`.
- Composition: back link „Anuluj" → `h1` phrased as a question („Usunąć ten wpis?") → a card restating exactly what is about to disappear, quoting the entry title and date → the consequence sentence → the button row.
- **Button row:** „Usuń wpis" as the **danger button** and „Anuluj" as a secondary link. The danger button is deliberately the *only* new button variant in this phase: pill geometry identical to the primary `Cta`, fill `--color-danger` `#B91C1C`, label white (6.47:1), 2px `--color-danger` border, **flat, with no `0 3px 0` hard shadow and no hover raise**. The primary action of the site is joyful and springy; deleting content is not. Hover darkens the fill by switching the label row to the same fill with an `ink`-free treatment: concretely, hover keeps the fill and adds a 2px inner white ring via `box-shadow: inset 0 0 0 2px #FFFFFF`, so no new colour value is introduced. Focus uses the global ring.
- **The delete button is never the first focusable element** on the page and is never auto-focused. Focus lands on the `h1` (`tabindex="-1"`).
- **No typed confirmation** („wpisz USUŃ") and no double confirmation: for this user group that is friction that teaches people to click through warnings. One clear page, two clearly different buttons.
- The copy never promises recovery. It says the operation cannot be undone in the panel, which is true, and stops there.
- After deletion: redirect to the list with a `role="status"` „Zapisano"-family panel (tint-green) confirming the removal and the two-minute delay.

### 12. „Wyloguj" (D-03)

- **Mandatory and visible on every panel screen**, in the header bar, because these are shared computers.
- It is a `<button type="submit">` inside its own tiny `<form method="POST" action="/admin/wyloguj">`, never a GET link: a link can be prefetched or fetched by a browser feature and log the editor out unexpectedly.
- Treatment: secondary button variant (pill, 2px `brand-blue` border, `brand-blue` label, hover `#E0F2FE` fill), Nunito 700 14px, Lucide `log-out` 18px `aria-hidden`, 44px target. Below `sm` the label stays visible (an icon-only logout is a guessing game for this user group); if space forces it, the icon-only form must carry `aria-label="Wyloguj"`.
- No confirmation dialog. Logging out is cheap and reversible.
- After logout: redirect to `/admin/logowanie` with the neutral band panel „Wylogowano. Do zobaczenia."

### 13. Recruitment switch (`/admin/nabor`, D-16)

- **A radio group, not a toggle switch.** A styled toggle is a JavaScript-flavoured control with an ambiguous on/off reading; two radios are native, keyboard operable, screen-reader unambiguous and work with JavaScript off.
- `<fieldset>` with visible `<legend>` „Stan naboru", two radios each with a label and a 15px `muted` description of exactly what a visitor will see in that state. Radio visual: 24×24px, 2px `--color-border-strong`, `--radius-pill`, checked `--color-brand-blue` fill with a white centre dot; row min-height 44px; whole row clickable.
- Beneath the group, a preview panel (`--color-band`, `--radius-md`) showing the current public status-banner headline for the selected state, so the editor sees the consequence before saving.
- One „Zapisz" (Contract 9), one commit, one build.

## Motion & Reduced Motion

- Transitions stay 150 to 200ms `ease` on colour, border-colour, shadow and transform, matching Phase 1.
- The only motion the panel introduces: the `<summary>` chevron rotation and the primary button's press transform. Both already live inside component-scoped `@media (prefers-reduced-motion: reduce)` guards, in addition to the global base-layer neutraliser in `app.css`.
- **The image island animates nothing.** No spinner, no progress bar, no fade-in on the preview, no skeleton. Panel swaps and preview paints are instant.
- No auto-scroll anywhere. Focus movement is the only thing that moves the viewport, and it is always the result of an explicit action.

## Accessibility Contract (WCAG 2.1 AA, non-negotiable: this is a public body and Phase 6 certifies the baseline in a legal document)

- `<html lang="pl">` inherited; landmarks per screen: one `<header>`, one `<nav aria-label="Sekcje panelu">`, one `<main id="main">`, one `<footer>`; `SkipLink` („Przejdź do treści") is the first focusable element on every admin screen.
- Exactly one `<h1>` per screen; heading order never skipped (`h1` → `h2` → `h3`), including inside `fieldset` legends styled as headings.
- Every control has a programmatically associated visible `<label>`. No `aria-label` substituting for a visible label, no placeholder-as-label, no label-less input anywhere in the panel.
- Grouped controls use `<fieldset>` with a visible `<legend>`: date triples, repeatable items, the photo group, the recruitment radios.
- Errors satisfy 3.3.1 (identified in text), 3.3.2 (labels and instructions present) and 3.3.3 (the message says what to do). `aria-invalid="true"` is set only while a field is invalid and cleared on correction.
- Exactly one `role="alert"` region and one `role="status"` region are live at a time. No competing live regions, no duplicate announcements.
- Every interactive target is ≥44×44px. The global 3px `focus-ring` at 2px offset is present on every focusable element and is never removed, including the native file input.
- Colour is never the only signal: the placeholder badge carries text, errors carry an icon plus text, the active nav chip carries `aria-current`, the checked radio carries a glyph, links stay underlined.
- The image island is fully keyboard operable end to end: tab to the file input, choose a file with the keyboard, hear the status announcement, tab to the alt field, tab to the buttons. Nothing in the flow requires a pointer.
- `prefers-reduced-motion` honoured; the island contains no motion to honour.
- Repeated action links are disambiguated by a visually-hidden entry name (2.4.4).
- **Gate:** zero axe violations on `/admin/logowanie` (both steps, including the error states), `/admin`, `/admin/aktualnosci` (populated and empty), an edit screen (clean, and with `aria-invalid` rendered), the photo island with a preview loaded, and a delete confirmation page. The panel must also be operable with JavaScript disabled for everything except adding a photo.

## Discretion Decisions Recorded (CONTEXT.md „Claude's Discretion")

These were mine to choose. They are recorded here so the planner implements them rather than re-deciding them, and so the auditor can check them.

| Area | Decision |
|------|----------|
| Code shape | 6 digits, numeric only, generated with a CSPRNG, single use |
| Code lifetime | 15 minutes (stated in the UI and the e-mail, so the two can never drift) |
| Code attempts | 5 wrong attempts burn the code; the editor requests a new one. No account lockout: locking an address out is a denial-of-service handed to anyone who knows a staff e-mail |
| Code request limit | Reuse `src/lib/server/forms/ratelimit.ts` unchanged: per-client hour bucket and a site-wide UTC daily bucket, fail open on KV trouble, refuse to hash without a salt |
| Session cookie | `__Host-` prefixed, `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, 30 days, renewed on use (D-03) |
| Editor handle (D-04) | The local part of the address, lowercased, non-ASCII stripped, 20 characters maximum. Shown as „Zalogowano jako: anna.k" and used in commit messages. The full address never reaches a commit, a log or the DOM of any page other than the login echo line |
| Image maximum edge | 1600px |
| JPEG quality | 0.82 |
| Crop aspect | 16:9 for aktualności covers, 4:3 for o nas photos, both centred, both automatic (D-13) |
| Crop preview | The re-encoded result itself, painted into a reserved aspect box, so the preview cannot disagree with what publishes |
| Delete flow | A confirmation page, never a modal; one danger button plus a cancel link; no typed confirmation |
| Replace flow | Choosing a new file replaces the pending one in place; the old file is only overwritten in git at „Zapisz" |
| Admin route layout | Listed in „New Surfaces This Phase Introduces"; components under `src/lib/components/admin/`, server helpers under `src/lib/server/admin/` |
| Reordering | Out of scope this phase, in both the wartości list and the plan dnia rows. Recorded so it is not silently invented |
| Edit logging | Git history only. No second log, no analytics, no admin audit page. Every save is already an attributed commit, and a second store would be personal data in a place nobody would remember to purge |
| Instrukcja | Rewritten end to end (the Sveltia version documents a login that will not exist). Same printable single-page shape, sections: logowanie, pulpit, dodanie wpisu, dodanie zdjęcia z opisem alternatywnym, dokumenty, plan dnia, nabór, co zrobić gdy zmiany nie widać, co zrobić gdy panel odmówi zapisania |

## Notes for Planner / Executor

- `/admin` routes **must opt out of prerender explicitly** (`export const prerender = false` in `src/routes/admin/+layout.ts` or `+layout.server.ts`), because `prerender = true` is set once in `src/routes/+layout.ts` and inherited. They must also stay out of `KNOWN_FUTURE_ROUTES` reasoning and out of the sitemap, and carry `noindex, nofollow`.
- The panel is the **third dynamic route group** in the project. Secrets come from `event.platform.env.*`, never `import.meta.env`. Do not create a root `.dev.vars` (it makes `wrangler types --check` fail on every Pages deploy); use `npm run preview:test --binding` flags for local and Playwright runs, and type any new secret as optional in `src/app.d.ts`.
- The old path-scoped `/admin/*` CSP block in `_headers` belongs to the Sveltia SPA and is removed with it (D-20). The new panel is SvelteKit routes, so its CSP question belongs in `kit.csp`, and the site-page CSP must not be loosened to accommodate the panel.
- **Panel output must be prettier-shaped JSON** (tabs, trailing newline), pinned by a unit test (D-09). This is the Phase 3 UAT blocker that stopped every local commit; `.prettierignore` is deliberately not the fix.
- Generated upload filenames must be guaranteed to resolve inside `src/lib/assets/uploads/`, because **the basename lookup is the path-traversal defence** (T-03-03), and an unknown basename must keep yielding the tint fallback rather than a filesystem read.
- The `recruitmentOpen` boolean currently lives in a TypeScript module (`src/lib/content/site.ts`) and **the panel cannot safely rewrite TypeScript**. Resolve this deliberately (most likely by moving the boolean into a small JSON file the panel already knows how to write) before building the `/admin/nabor` screen.
- Admin copy should join a `tests/*.unit.ts` copy sweep in the shape of `tests/forms-copy.unit.ts`: an explicit export list asserted for no emoji, no em dashes, and Polish-only strings. Note the standing gap recorded in CONTEXT.md: `*.unit.ts` currently runs in no automated gate, so this phase's verification must not lean on that suite alone.
- Every screen in this contract must be checked with JavaScript disabled. If a screen needs JavaScript for anything other than adding a photo, the implementation has diverged from D-17.
- The image island is the phase's accessibility risk. Budget a real keyboard pass plus an axe run **with a preview loaded**, not only on the empty form.
