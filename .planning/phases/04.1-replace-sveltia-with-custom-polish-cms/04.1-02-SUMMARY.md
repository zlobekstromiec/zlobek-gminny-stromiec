# Phase 04.1 Plan 02: Kod jednorazowy i polska tresc panelu Summary

**A six-digit CSPRNG login code that lives in KV only as a salted hash under an address-free key, works exactly once inside fifteen minutes, burns after five wrong attempts, and refuses the login on every failure path, plus the one Polish copy module the whole panel and its login e-mail render from, both pinned by 62 unit cases and four mutation checks.**

## Accomplishments

- **`kod.ts` fails closed and says so.** Every branch that could go either way (absent binding, missing or whitespace-only salt, a thrown KV call, a corrupt stored value) returns a refusal, and the module header states explicitly that this is the deliberate inverse of the fail-open degrade documented at length in `ratelimit.ts`. That module is an abuse control behind Turnstile; this one is the authentication boundary.
- **The code never exists in KV.** The key is a salted SHA-256 of the address truncated to 8 bytes, so `adm:kod:<hex16>` names no address. The value is a salted SHA-256 of the code, an expiry stamp and an attempt count, so it contains neither the code nor the address as a substring. Both asserted, not assumed.
- **Timing is not an oracle.** `sprawdzKod` compares digests, never the codes, over a loop that always walks the longer of the two inputs and folds every difference into one accumulator, so its running time does not depend on where the inputs diverge.
- **The panel's daily budget is genuinely its own.** `kluczDobowy` and `podLimitem` each gained one optional TRAILING parameter with a default, which is what keeps `src/routes/api/kontakt/+server.ts` and `src/routes/api/rekrutacja/+server.ts` byte-identical (the same append rule that added `teraz` in Plan 04-08). `podLimitemKodu` passes `rl:doba:adm`, so a login flood cannot refuse a parent's enrolment enquiry and a busy contact-form day cannot lock staff out of the panel.
- **One copy module, swept, with a counter on it.** `src/lib/content/panel.ts` carries all 34 exports covering every UI-SPEC section including the e-mail. `tests/admin-copy.unit.ts` sweeps an explicit list and then asserts that list is the same length as the module's actual export count, so a forgotten entry turns the suite red instead of quietly escaping the rules.
- **The forms mailer was not touched at all.** `mail-kod.ts` is a sibling: it imports the exported sending identity and nothing else, builds its own payload with one recipient, no hidden copy and no reply-to, and its header records all three reasons why extending the existing builder was rejected.

## Decisions Made

- **`MNOZNIK_TTL_KODU` exists for the same reason `MNOZNIK_TTL` does.** A wrong attempt rewrites the entry, and a KV write overwrites the previous expiration, so a KV lifetime equal to the code lifetime would be restarted by every wrong guess. Validity is therefore decided by the `wygasa` stamp INSIDE the value, and the KV lifetime is twice the code life and only sweeps entries nobody touches again. The rewrite deliberately keeps the original stamp, so a stream of wrong attempts cannot extend a code's life.
- **A vanished entry reads as `wygasl`, not `za-duzo-prob`.** The attempt that reaches the cap returns `za-duzo-prob` and deletes the entry, which is the moment the „Za dużo prób" panel is shown. From KV alone a burned code and an expired one are afterwards indistinguishable, and inventing a tombstone to tell them apart would be state an attacker could probe. „Wyślij kod ponownie" is the correct instruction for both.
- **`czytajWpis` rejects a partial value rather than repairing it.** A missing attempt count that defaulted to zero would reset the burn counter on every write, which is the cap silently disabled.
- **The `Math.random` ban is described, never written.** The plan's own acceptance gate for this module is a literal grep, and a comment naming the banned call would make that gate permanently red. Same rewording the pre-launch gates already forced in 04-02, and the comment says so.
- **The English-chrome detector cannot use a word boundary.** `\b` treats every Polish diacritic as a non-word character, so it splits `ważność` at `ż` and `ś` and reports the `no` between them as the English word. Observed on the first run of the suite, not predicted. Replaced with `(?<![\p{L}\p{N}_])` and `(?![\p{L}\p{N}_])`, and a positive-control case now proves the detector still fires on real English input, so the sweep cannot pass by matching nothing.
- **One copy normalisation.** Where the UI-SPEC table pairs an opening `„` with a straight closing `"`, the module uses the Polish closing `”`. A mixed pair is a rendering artefact of the markdown table, not a typographic decision. Recorded in the module header.
