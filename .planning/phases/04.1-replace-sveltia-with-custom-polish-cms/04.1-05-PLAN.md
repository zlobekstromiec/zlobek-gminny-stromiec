<objective>
Deliver the thinnest possible end-to-end editing capability: the recruitment open and closed switch, saved by the panel as one real commit that changes the public site.

Purpose: this is the first plan where a staff member changes the live website from the panel, and it is deliberately the simplest content in the phase (one boolean) so the write path built in Plan 04 is proven with nothing else in the way. It also closes RESEARCH Open Question 2 and delivers D-16, which CONTEXT.md records as the one thing the żłobek currently cannot do without a developer.

Output: the recruitment value moved into JSON with every consumer untouched, a shared save orchestrator every later editor reuses, and a screen that proves the whole chain from a radio button to a live public page.
</objective>

- **P-14 (RESEARCH Open Question 2, resolved):** the recruitment value moves to `src/lib/content/nabor.json` as `{ "otwarty": false }`, and `src/lib/content/site.ts` imports it and keeps `export const recruitmentOpen = nabor.otwarty;` plus the existing derived `recruitment` object built from it. Repeating it per route would put the conflict handling and the error mapping in six places, and the D-10 refusal is the one branch that must never drift.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated editor to form action | the submitted state is untrusted input even though the person is authenticated |
| form action to git | the only path from a browser into the repository |
| build-time JSON to public page | the value a visitor sees comes from the committed file, never from a runtime store |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-22 | Tampering | an arbitrary value written into nabor.json | medium | mitigate | The validator accepts exactly two values and rejects everything else including an absent field; the reader in site.ts consumes a boolean, so a malformed value cannot reach the public page. Pinned by the validator unit case and by the empty-submission Playwright case. |
| T-04.1-13 | Tampering | a save overwriting a change made since the page loaded | medium | mitigate | The head SHA read on load is compared before any write, and update-ref uses force false. Manual two-tab confirmation is listed in the phase UAT because the race is not reliably reproducible in a test. |
| T-04.1-09 | Elevation of Privilege | an unauthenticated POST reaching this action | high | mitigate | The Plan 01 gate covers actions as well as pages, and `tests/admin-auth.spec.ts` already asserts an unauthenticated POST to `/admin/nabor` is refused. |
| T-04.1-23 | Denial of Service | one editing session producing several Cloudflare builds | medium | mitigate | D-11: one page, one save, one commit, one build. Enforced by the single-submit-button assertion. |
| T-04.1-07 | Information Disclosure | the editor's address reaching the commit | high | mitigate | The scope and description come from the copy module and the handle comes from locals; `komunikatCommita` self-asserts the absence of an at sign, and the real commit message is inspected in the SUMMARY. |
| T-04.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero packages installed. |
</threat_model>
