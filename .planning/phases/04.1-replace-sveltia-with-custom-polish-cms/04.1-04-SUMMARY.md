## Verdict on the Three Orphaned Files

The previous executor was killed after writing `src/lib/server/admin/repo.ts`,
`tests/admin-serializuj.unit.ts` and `tests/admin-commit.unit.ts` and after
observing RED. All three were read and judged on their merits before anything
else happened.

**Verdict: adopt all three, with one correctness fix to `repo.ts`.**

They are good work, and specifically they are good in the ways that are hard to
redo. The commit suite does not test the implementation that existed at the time,
it states a contract: the exact outbound request sequence, the exact call count,
the requirement that a conflict costs zero blobs, a positive control paired with
the PKCS#1 negative assertion, and a check that no error message or stack carries
key material. The serializer suite is genuinely property based, crossing 15 value
kinds with 3 structural positions and folding in the 4 real content files as
controls, with the real formatter as the oracle rather than a description of it.
Rewriting either from scratch would have produced something weaker.

**The one fix:** `bezpiecznyOpis` in `repo.ts` stripped control characters with a
regex written using LITERAL control bytes, so the source file contained a raw NUL
and a raw DEL. That works, but it is a character class that no editor, diff, patch
or copy-paste round trip is guaranteed to preserve, and a silently corrupted class
there would let a line break into a commit subject. Replaced with the equivalent
`\u0000-\u001f\u007f` escapes and a comment saying why. Verified afterwards that
the file contains no raw control bytes other than tabs and newlines.

Two smaller notes, both left as they were because they are correct: the suites
were not prettier-clean as written (three files needed `prettier --write`, which
changed only line wrapping), and `tests/admin-commit.unit.ts` types its failure
injection as `Partial<Record<...>>` fed by a computed key, which TypeScript
accepts. `npm run check` reports 0 errors over 4251 files and the tests directory
is inside the typecheck's include list, so this is checked, not assumed.

## Accomplishments

- **The write path exists and is unit-drivable with no network.** `zapiszAtomowo`
  takes `fetchImpl` by injection exactly as `obsluz()` takes every side effect, so
  the entire outbound sequence is observable as data. 30 cases in
  `tests/admin-commit.unit.ts`, all passing.
- **Pitfall 1, the phase's highest-severity item, is disarmed and checked.**
  `pemDoArrayBuffer` rejects a PKCS#1 header with a named Polish error instead of
  letting WebCrypto throw an opaque `Invalid keyData` at the first save on the
  deployed site. The test proves this with a throwaway RSA key generated
  in-process, using the same bytes under both headers, paired with a positive
  control so the assertion cannot pass merely by rejecting everything.
- **The CryptoKey is cached at module scope**, which on workerd means once per
  isolate, because the measured import-to-sign ratio is about 4:1 and re-importing
  per request would spend most of a save's CPU budget on work that never changes.
  The cache stores the PEM beside the key so a rotated secret cannot keep signing
  with the retired one, and `wyczyscPamiecTokenu` clears both caches.
- **Conflict detection is genuinely free and genuinely early.** The head SHA the
  Git Data API needs anyway is compared before the first blob request, so a
  refusal costs one read and leaves no orphan objects. Mutation-checked.
- **A staff e-mail address cannot reach the history of a public repository.**
  `komunikatCommita` scrubs the handle to a conservative ASCII class, strips at
  signs from the description, and then asserts to itself that the result contains
  none. Two checks for one property, deliberately, because the failure is
  irreversible.
- **The Phase 3 prettier blocker is closed with a real gate, not a proxy.** The
  serializer's output is fed back through this repository's own prettier binary in
  its stdin-filepath mode with a path under `src/lib/content/`, and compared byte
  for byte.

### Auto-fixed

**1. [Rule 1 - Bug] Raw control bytes in the `bezpiecznyOpis` character class**

- **Found during:** review of the orphaned `repo.ts`
- **Issue:** the control-character strip was written with literal NUL and DEL
  bytes embedded in the source file rather than escapes
- **Fix:** replaced with `[\u0000-\u001f\u007f]` plus a comment explaining why the
  escaped form is the only safe one here
- **Files modified:** `src/lib/server/admin/repo.ts`
- **Commit:** `ffc0b2c`

**2. [Rule 2 - Missing critical functionality] Conflict mapping narrowed to the ref update**

- **Found during:** Task 3
- **Issue:** RESEARCH Code Example 2 maps any 409 or 422 to `konflikt` by matching
  the status inside a message string, so a 409 from a blob or a tree would have
  been shown to an editor as "somebody else changed this entry, reload", which is
  a false and confusing statement
- **Fix:** a typed `BladGitHub` carrying the step path and the status; the
  conflict branch requires the path to be the ref update. Both 409 and 422 remain
  mapped there, per P-12
- **Files modified:** `src/lib/server/admin/commit.ts`
- **Commit:** `ffc0b2c`

**3. [Rule 2 - Missing critical functionality] Base64 charset validated before the first request**

- **Found during:** Task 3
- **Issue:** the plan mandates assembling the base64 blob body by concatenation
  for a measured reason. That is safe only if the payload really is base64; a
  payload carrying a quote would break out of the body it is spliced into
- **Fix:** every base64 file is charset-checked before any outbound request, so a
  malformed payload costs nothing and leaves no orphan objects. The commit suite
  already asserted this behaviour
- **Files modified:** `src/lib/server/admin/commit.ts`
- **Commit:** `ffc0b2c`

**4. [Rule 2 - Missing critical functionality] Key cache invalidated on rotation**

- **Found during:** Task 3
- **Issue:** RESEARCH Code Example 1 caches the imported CryptoKey with `??=`, so
  after a key rotation an already-warm isolate would keep signing with the retired
  key until it was recycled, producing an intermittent and very confusing auth
  failure
- **Fix:** the cache stores the PEM that produced the key and re-imports when it
  differs
- **Files modified:** `src/lib/server/admin/github.ts`
- **Commit:** `ffc0b2c`

```bash

cat > sonda.mjs <<'JS'
// Deliberately stale update-ref against the real repository. Must be REFUSED.
import { readFileSync } from 'node:fs';
const PEM = readFileSync(process.env.HOME + '/Documents/panel-redakcyjny-zlobka.pkcs8.pem', 'utf8');
const CLIENT_ID = 'Iv23lipuQ3hnHl4snF6h';
const INSTALL = '154059103';
const REPO = 'zlobekstromiec/zlobek-gminny-stromiec';
const H = { Accept: 'application/vnd.github+json', 'X-GitHub-Api-Version': '2022-11-28', 'User-Agent': 'zlobek-panel-redakcyjny' };
const b64url = (d) => {
  const b = typeof d === 'string' ? new TextEncoder().encode(d) : new Uint8Array(d);
  let s = ''; for (const x of b) s += String.fromCharCode(x);
  return btoa(s).replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
};
const der = Uint8Array.from(atob(PEM.replace(/-----[^-]+-----/g, '').replace(/\s+/g, '')), (c) => c.charCodeAt(0));
const alg = { name: 'RSASSA-PKCS1-v1_5', hash: 'SHA-256' };
const key = await crypto.subtle.importKey('pkcs8', der.buffer, alg, false, ['sign']);
const t = Math.floor(Date.now() / 1000);
const head = `${b64url(JSON.stringify({ alg: 'RS256', typ: 'JWT' }))}.${b64url(JSON.stringify({ iat: t - 60, exp: t + 540, iss: CLIENT_ID }))}`;
const jwt = `${head}.${b64url(await crypto.subtle.sign(alg, key, new TextEncoder().encode(head)))}`;
const tok = await (await fetch(`https://api.github.com/app/installations/${INSTALL}/access_tokens`, { method: 'POST', headers: { ...H, Authorization: `Bearer ${jwt}` } })).json();
```
