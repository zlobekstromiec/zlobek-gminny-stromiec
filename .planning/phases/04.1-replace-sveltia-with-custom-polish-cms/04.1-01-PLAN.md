<objective>
Build the auth gate that makes every admin surface unreachable without a valid, revocable session, and prove it with an enforced Playwright assertion rather than only a unit test.

Purpose: SC1 has two halves. This plan delivers the second half (an unauthenticated visitor can reach neither an admin page nor an admin action) plus the session mechanics the first half will hand a cookie to. It is deliberately first: every later plan adds a screen behind this gate, and a gate added late is a gate that leaks.

Output: a signed, revocable session cookie module, a single `handle()` gate, the prerender opt-out, the six new optional secrets typed and bound for the test harness, and an authenticated-session Playwright fixture every later plan reuses.

<planner_decisions>
Recorded here so the executor implements them rather than re-deciding them.

- **P-01 (cookie identity):** the session cookie is `__Host-panel_sesja`, `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, `Max-Age` 30 days, per the UI-SPEC "Discretion Decisions Recorded" table. This deliberately supersedes the `path: '/admin'` sketch in RESEARCH Pattern 3, because the `__Host-` prefix requires `Path=/` and no `Domain`, and the prefix is the stronger control. Chromium treats `http://localhost` as a secure context, so the prefix works in the Playwright harness; task 3 proves that rather than assuming it.
- **P-02 (renewal cadence):** D-03 says the session renews on use. Renewing on literally every request would emit a `Set-Cookie` on every page view. The rule is: renew when more than 5 days of the 30-day life have elapsed. That keeps a weekly editor permanently signed in while keeping most responses cookie-free.
- **P-03 (revocation):** the allowlist re-check runs inside `handle()` on every request, per RESEARCH Pattern 3. Without it, removing a departed editor takes up to 30 days.
</planner_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet to /admin/** | every request is untrusted until `handle()` has verified a signature and re-checked the allowlist |
| cookie jar to server | the cookie is attacker-controlled input; only the HMAC makes its contents trustworthy |
| Cloudflare Pages secret store to worker | ADMIN_EMAILS and ADMIN_SESSION_SECRET arrive only through the platform env object |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-01 | Spoofing | sesja.ts cookie verification | high | mitigate | HMAC-SHA256 over the payload with a deployment secret; length-independent signature comparison; any verify failure returns null and the gate redirects. Pinned by `tests/admin-sesja.unit.ts` and by the tampered-cookie case in `tests/admin-auth.spec.ts` (AG-3 second enforced check). |
| T-04.1-02 | Elevation of Privilege | hooks.server.ts stale session after an editor leaves | high | mitigate | `naLiscie` re-check inside `handle()` on every request, so a secret update plus a rebuild revokes immediately instead of after 30 days. Enforced by the de-allowlisted-cookie Playwright case. |
| T-04.1-09 | Tampering | admin form actions reachable without a session | high | mitigate | The gate runs before routing and returns 303 for every non-GET method, so an action cannot be invoked directly. Enforced by the unauthenticated-POST Playwright cases. |
| T-04.1-14 | Information Disclosure | admin pages prerendered or indexed | medium | mitigate | `prerender = false` in the admin layout, `Seo` noindex left at its default, no public page links to /admin. Enforced by the build-output assertion and the robots assertion. |
| T-04.1-07 | Information Disclosure | staff address in logs | high | mitigate | `sesja.ts` and `allowlist.ts` contain no logging at all; the gate logs binding names only. Enforced by a grep for any console call in both modules. |
| T-04.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing. `package.json` dependencies are untouched; only the `preview:test` script string changes. Any deviation requires the Package Legitimacy Gate before it is written. |
