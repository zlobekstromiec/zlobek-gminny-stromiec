# Cennik prowadzi stawka z uchwaly, obok niej nota o obowiazujacej obnizce

## Decyzja zlecajacego

Dyrektorka poprosila wprost: „Wysokosc czesnego to 2337 zl". Zlecajacy zdecydowal, zeby nie
isc wbrew jej slowu: strona ma podawac 2337 zl jako cene z uchwaly i **dopisac note, ze
obowiazuje obecnie obnizka**. To jest decyzja klienta i tak zostaje wykonane.

Granica, ktora zostaje utrzymana, bo jest to ta wersja polecenia, ktora jest RowNIEZ prawdziwa:
**strona nigdzie nie powie, ze rodzic placi 2337 zl**, bo rodzic tyle nie placi. 2337 zl jest
podane jako STAWKA Z UCHWALY, a tuz pod nia, rownie widocznie, stoi kwota faktycznie placona
dzis. Zaden rodzic nie odczyta 2337 zl jako sumy na swoim rachunku.

## Problem, ktory to tworzy w kodzie

Dzis naglowkiem ramki jest `CENNIK.kwotaProza`, czyli kwota PLACONA (1 500 zl miesiecznie).
Zeby naglowkiem byla stawka, czytnik musi wystawic druga proze.

Pulapka jest w `kwotaOpis`. To pole SKLEPU o tresci „Opłata za pobyt dziecka do 10 godzin
dziennie, po obniżce obowiązującej w okresie trwałości projektu." Opisuje kwote 1500, nie 2337,
i jest wspoldzielone z `FeeBox.svelte` na /rekrutacja. Przesuniecie naglowka na 2337 zostawiloby
to zdanie pod zla liczba, a edycja go w sklepie zepsulaby /rekrutacja, gdzie dalej opisuje 1500.

**Rozwiazanie: nie ruszamy `kwotaOpis`, tylko przenosimy je tam, gdzie nadal jest prawdziwe.**
Ide za kwota placona, do bloku noty. Stawka dostaje wlasny, kodowy opis. Dzieki temu ani jedno
pole sklepu sie nie zmienia i /rekrutacja zostaje nietknieta.

## Zadania

### 1. Testy czerwone PRZED zmiana

- `tests/cennik-reader.unit.ts`: `OCZEKIWANE_KLUCZE` to RoWNOSC zbioru kluczy, wiec dodanie
  `stawkaProza` do widoku samo z siebie zaswieci na czerwono. To jest bramka, ktora ma zadzialac.
- `tests/cennik.spec.ts`: naglowkowa kwota rowna `CENNIK.stawkaProza`, nie `kwotaProza`; nota
  obnizki istnieje, lezy w tej samej ramce i niesie kwote placona; podpis stawki i podpis kwoty
  placonej sa rozne.
- Bramki kwoty zerowej BEZ ZMIAN i maja dalej przechodzic: nowa tresc jest bezzerowa.

### 2. Czytnik

`src/lib/cennik.ts`: `WidokCennika` dostaje `stawkaProza`, budowane tak samo jak `kwotaProza`,
czyli `${zlote(stawka)} ${OKRES}`. Slowo okresu dalej deklarowane raz (05 D-28).

### 3. Copy

`src/lib/content/cennik.ts` (HARD RULE 1: zadna z tych stalych nie niesie kwoty; kwoty wchodza
wylacznie przez argumenty funkcji, wzorem `przykladZus`):

```
KWOTA_PODPIS   = 'Stawka z uchwały:'
PODPIS_PLACI   = 'Rodzic płaci teraz:'
STAWKA_OPIS    = 'Pełna miesięczna stawka za pobyt dziecka do 10 godzin dziennie, ustalona uchwałą Rady Gminy Stromiec.'
notaObnizki(obnizkaTekst) = 'Obecnie obowiązuje obniżka {obnizkaTekst} miesięcznie w okresie trwałości projektu, więc kwota do zapłaty jest niższa od stawki z uchwały.'
```

### 4. Render i styl

`src/routes/cennik/+page.svelte` wedlug ukladu powyzej. Nota to blok o wlasnym tle
(`--color-surface`) wewnatrz zoltej ramki, zeby czytala sie jako osobna informacja, a nie jako
przypis. Kwota placona ma klase `.kwota` tak jak stawka.

### 5. Adnotacja specyfikacji, ten sam commit

`05-UI-SPEC.md` Kontrakt 4a wypisuje kolejnosc DOM ramki oplat i mowi, ze pierwsza pozycja to
„the payable amount". Po tej zmianie pierwsza pozycja to STAWKA. Adnotacja w miejscu, plus
Kontrakt Copywritingu dla /cennik.

### 6. Pelna brama

`npm run check && npm run lint && npm run test:unit && npm run test`.
