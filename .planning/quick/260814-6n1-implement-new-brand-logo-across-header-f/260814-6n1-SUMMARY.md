# Quick Task 260814-6n1: Real brand logo across header, footer, and favicons Summary

The client's delivered logo now drives every brand surface: the circular emblem in the sticky header at 52px, the full lockup on a white card in the footer brand column, and a regenerated PNG favicon pair, with the placeholder vector icon and the delivered source file removed from the repo.

## What Was Built

**Task 1 (`2b30c54`) — brand assets and favicon set.**
A throwaway sharp script in the session scratchpad (never in the repo, never in git) produced four files from `logo-bg.png` (1079x514 RGBA):

| File | Size | Notes |
|---|---|---|
| `src/lib/assets/brand/logo-full.png` | 873x468 RGBA | whole lockup, alpha-trimmed |

**Task 2 (`64d8023`) — component wiring.**
`Header.svelte` drops the `IconBear` import and renders `logo-mark.png?enhanced` through `enhanced:img` inside a `.brand-mark` wrapper (`flex: none; display: flex;` plus a `:global(img)` rule at `height: 52px; width: auto`). The accent-circle background, the icon colour tokens, and the `0 3px 0` hard shadow are gone. Sticky positioning, the 4px accent bottom border, the scroll shadow, the 44px minimum link height, and every nav rule are untouched, and the two-line wordmark markup is byte-identical.

`Footer.svelte` renders `logo-full.png?enhanced` in a `.brand-lockup` white card (surface background, `--radius-sm`, 10px 12px padding, max-width 280px) immediately above `.footer-wordmark`.

Both images carry `alt=""`, confirmed in the prerendered output, so the header link's accessible name is still the wordmark text and no duplicate name is introduced.

**Task 3 (`f09af5d`) — cleanup and spec.**
`static/favicon.svg` deleted and de-referenced from `src/app.html` and `static/site.webmanifest` (which keeps its 2-space indentation, since `/static/` is in `.prettierignore`). The manifest now carries exactly two PNG icons. `logo-bg.png` removed from the repo root. UI-SPEC gained a four-point `## Amendment v1.3 (2026-08-14): real brand assets` section.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Scratchpad script could not resolve `sharp`**
- **Found during:** Task 1
- **Issue:** The plan specified `const sharp = (await import('sharp')).default` in a script living outside the repo. Node module resolution walks up from the *script's* directory, so from the scratchpad it never reaches the repo's `node_modules` and threw `ERR_MODULE_NOT_FOUND`. The repo's sharp also exposes no `lib/index.js` (only `lib/index.d.ts`); the real ESM entry is `dist/index.mjs`.
- **Fix:** The script now `process.chdir()`s to the repo and imports sharp by absolute path (`node_modules/sharp/dist/index.mjs`). The plan's bare `import('sharp')` form does work from the repo root, which is why the Task 1 `node -e` verify gate ran unchanged.
- **Files modified:** scratchpad only, nothing in the repo
- **Commit:** n/a (uncommitted throwaway script, per the plan)

**2. [Rule 1 - Bug] `sharp .trim()` was a silent no-op, so both crops were untrimmed**
- **Found during:** Task 1
- **Issue:** The plan's key_facts stated the source has a transparent background and that `.trim()` with threshold 0 would use the top-left pixel as the background reference. In fact the top-left pixel is `(255,255,255, alpha=1)` and the image carries faint alpha noise (values 1 to 4) across nominally empty areas. With threshold 0 nothing matches exactly, so `.trim()` returned the input unchanged: `logo-full.png` came out 1079x514 and `logo-mark.png` 550x514 (ratio 1.07, which would have passed the square assertion while actually being an untrimmed slab with dead space).
- **Fix:** The generator computes the alpha bounding box directly, ignoring alpha at or below 8. A per-column alpha scan showed the emblem spans x 125-530, columns 531-593 are completely empty, and the wordmark starts at x 594 — so the emblem boundary is derived from the image rather than guessed. Results: full lockup 873x468 (ratio 1.865), mark 406x468 (ratio 0.868).
- **Files modified:** `src/lib/assets/brand/logo-full.png`, `src/lib/assets/brand/logo-mark.png`, and the two downstream favicons
- **Commit:** `2b30c54`

**3. [Rule 3 - Blocking] `logo-bg.png` was untracked, so `git rm` failed**
- **Found during:** Task 3
- **Issue:** The plan called for `git rm logo-bg.png`, but the delivered file had never been committed (it showed as `??` in `git status`).
- **Fix:** Removed with plain `rm`. The net effect the plan asked for is identical, and the commit's only deletion is `static/favicon.svg`.
- **Files modified:** `logo-bg.png` (removed)
- **Commit:** `f09af5d`
